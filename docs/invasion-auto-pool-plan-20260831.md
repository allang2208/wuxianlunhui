# 位面入侵自动入池方案（待实施）

> 此后已按用户授权实施；实际范围、接入字段和未验证边界见 [实施说明](invasion-auto-pool-implementation-20260831.md)。下文保留为原设计记录。

日期：2026-08-31。本文仅为设计方案与现有配置的初拟归档，不代表功能已实现或怪物已通过入侵实测。此次只新增本文档，不修改游戏代码、数据、已有怪物行为或存档，不运行测试、构建、素材检查或游戏。

## 1. 目标与现状

目标是“新增怪物在自身登记处声明一次，符合条件后自动加入正确候选池”，同时保持一个首领、少量精锐、大量普通怪、整场有限种类的编队。分类覆盖全部条目，但不要求把所有条目都变成主动攻城单位。

当前 `data/enemy-config.json` 有53条配置，包含3个特殊设施/伴生对象。现有 `data/invasion-campaign.json` 是8套固定编队、22个不同怪物类型；`src/world/invasion-formation.js` 随机抽系列后直接使用三个固定ID，尚无动态候选池。

已有 `family/families` 和 `src/config/enemy-family.js` 服务图鉴、伤害等既有业务；`rank` 提供普通/精英/领主/Boss阶级。它们应该复用，但不足以决定同族编队：动物、自然和僵尸的范围过宽，资源管理器使用的纹理族又是另一种含义。

先修正分类基础中的两处问题：

- 深脉之母的配置描述是矿压融合体，不是钻虫母体。建议归入“矿晶融合体”主题族，不能凭名称与钻虫组成默认生物族。
- 紫蚀古树、集合体的配置描述均为固定型首领。可归类并用于守点，但在缺少明确的攻城适配前，不列入主动行军攻城候选。

以上是方案中的修正建议，本轮没有改动现有8套编队。

## 2. 分类采用三个独立维度

| 维度 | 用途 | 示例与约束 |
|---|---|---|
| 身份与具体系列 | 决定可以与谁形成军团 | 狼族、蛇族、矿工亡灵；保留现有动物/自然/僵尸大标签，不把大标签直接当编队 |
| 战斗用途 | 决定可以参加哪类遭遇 | 主动入侵、固定守点、专属事件、仅召唤/伴生；同时登记移动、攻城目标、前后台保存能力 |
| 性能与机制 | 决定同场可选组合 | 群体/精锐/首领资源用途档、全部形态、弹体、召唤依赖、持续地面区域、控制与召唤数量 |

阶级默认来自现有 `rank`：normal→普通，elite→精锐，lord/boss→首领候选；minor默认不进入军团主编队。实际角色还要通过用途条件，因此“rank为normal”不意味着墓碑可以行军。

同一怪物可以具有多个身份标签，但应有一个默认主系列；跨系列领军关系单独登记。分类和行为必须分开，不能为配齐军团擅自修改怪物的全局rank、技能、尺寸或行动方式。

## 3. 推荐算法：规则归类＋受约束抽样

### 3.1 正式分类优先级

1. 怪物明确声明的入侵系列，优先级最高，算法不得覆盖。
2. 继承一个明确登记的内容原型/谱系，如“霜狼继承狼族谱系”。只允许显式内容继承，不能从JavaScript父类推断物种，因为代码继承可能只是复用技能。
3. 结构化标签命中唯一系列规则，可以自动归入该系列；仍须通过入侵准入规则。泛标签“自然/僵尸”和单一地图来源都不能独立命中。
4. 信息不足或规则冲突，生成待确认建议，不进入正式随机池。不猜一个最接近的系列强行上场。

本阶段不需要训练模型或联网调用。首次登记/配置加载时扫描并建立 `系列→角色→候选ID` 索引；新军团只读取索引，不逐帧扫描全怪物表。

### 3.2 缺标签时的辅助分类

可使用一个很小的加权规则分类器，生成建议和解释。初拟分值为：

`建议分 = 5×具体谱系词命中 + 3×描述关系吻合 + 2×生态来源吻合 + 1×资源命名吻合`

每项取0或1，示意阈值为最高分至少8、且领先第二名至少3；这些分数是设计启发式，不是统计概率，也未经样本校准。同源名字、目录与描述不能被当成多份独立证据刷高分。描述里的“以红狼为数值基准”“数值接近棕熊”必须排除，不是血缘关系。

达阈值只代表可优先确认的建议；未给出明确用途、资源与行为登记时，不自动批准攻城。规则明确、登记完整的未来怪物不走人工逐次审核，直接通过正式规则归池。

| 方法 | 本项目建议 |
|---|---|
| 明确标签/规则分类 | 正式运行使用，能解释归属、冲突和排除原因 |
| 加权匹配 | 仅帮助首次清理旧数据、发现漏标；不把建议当批准 |
| 文本向量/大模型分类 | 暂不接入；可在未来大量导入时离线给建议，不能决定正式抽取或资源准入 |
| 按数值相似度聚类 | 不用于物种归类；血量、速度相近无法证明是同一系列 |

### 3.3 分类台账的状态

每条记录显示：主系列、阶级、归类依据、可用模式、准入状态、排除原因及可选依赖。建议状态包括“正式候选”“待补元数据”“缺少角色”“仅固定守点”“专属事件”“仅依赖”“待资源/行为接入”。

这样所有怪物都有去向，不能入侵的也能明确看到原因，而不是从配置中消失。

## 5. 自动入池的硬性条件

分类以后，还要顺序检查：

1. **用途允许**：明确允许 `plane_invasion`，目标生态与进度满足；专属时空特工默认排除。
2. **特殊标记**：`noPool` 不作为直接成员；现有 `poolWhitelistOnly` 保持地牢原语义，需要显式声明允许入侵才能加入，不清除原标记。
3. **构造登记**：实体工厂可用，支持入侵创建；新怪物不应再被要求分别添加到地牢和防守两套名单。增设统一敌人登记入口，保存基础构造器及各模式适配器；现有地牢专属装饰不自动带入攻城。
4. **战斗能力**：能在基地地图选择敌方单位/建筑、支持相关行动与出生条件；固定怪、纯遭遇脚本怪或缺少前后台记录能力的怪物进入对应待接入状态。
5. **资源登记**：动作、形态、专属弹体及必需召唤物有完整登记；预算数据有来源版本，缺失时不把成本当0。
6. **机制预算**：召唤、持续区域、多目标攻击及多阶段转换有明确边界；未知机制不因分类相同就直接批准。
7. **角色完整**：能组成1首领、若干精锐和普通兵，并在强度与性能预算内满足最低人数。

缺精锐：仅系列明确允许时，复用普通怪作为局内强化精锐。缺普通兵或首领：默认暂不成军。不得把Boss自动降为精锐，也不得把普通怪无提示地包装成已有首领。

新怪物改名、ID中的King/Lord不决定阶级；阶级以rank为主，用途档位以预计同场数量为主。

## 6. 自动编队过程

```mermaid
flowchart LR
  A[读取登记与配置] --> B[分类索引]
  B --> C[用途 进度 构造 资源 机制准入]
  C --> D[选择一个可成军系列]
  D --> E[抽1种首领 1种精锐 1种普通怪]
  E --> F[计算数量与依赖预算]
  F --> G[冻结本次军团并存档]
  G --> H[提前一天行军 侦察 拦截 攻城]
```

先抽系列，再抽角色，避免成员较多的系列天然拥有更高的总出场概率。生态与进度是硬条件，偏好生态和近期重复惩罚是权重；不同生态间的入侵来源通过明确路线/系列规则允许，不能仅因目标位面相邻就视为所有物种都适用。

在系列内先确定一个合格首领，再选择其兼容的精锐和普通兵。主编队最多3种直接怪物，整场所有波次一致。系列候选池可以很大，但本次军团不会预加载或使用全部候选。

跨系列关系只允许显式的一步关系，如“美杜莎可以统领蛇族”；不能传递推导成“美杜莎认识巫婆，所以巫婆也能统领蛇族”。召唤关系和直接领军关系分别登记，不能互相暗示。

用稳定ID排序后进行有种子的加权抽样，保存种子、目录/规则版本、已选成员与角色、数量、倍率、战损和召唤余额。读档不重抽；新增怪物只影响尚未集结的未来军团。已经出发的阵容不能因资源暂未加载而换兵。

## 7. 强度算法与性能限制

### 7.1 强度采用预算，不把所有怪物视为等价

保留现有周期增长方向，但先选择符合进度的首领，再按单位成本确定精锐与普通兵数量。高强度新怪加入后不会仅因它也叫normal就一次生成48只。

单位成本使用独立的“入侵威胁”估算：有效生命、物理/魔法输出、射程与机动、控制/持续区域、召唤和阶段恢复。复用现有基础属性公式；现有 `strategicRosterPower` 的HP/物理攻击摘要只能作为起点，不能准确估算巫婆、熊德鲁伊、红狼的完整技能与变身回血成本。

第一版可采用基础HP/DPS成本＋人工登记的机制档位和覆盖值；复杂技能未登记则暂不自动放行。系数需要后续获得授权后，用实际体验校准，本文不给未经验证的“精确战力”。图鉴综合等级仍保留原语义，不直接修改为入侵战力。

数量仍受现有直接兵力55、分批12的上限约束，这些上限是天花板而非必填数量。预算不足时在集结前减少普通怪、选择同族低成本候选，或放弃该系列选择另一支合法军团；不增加图集种类、不临时削弱敌人技能，也不改变已经出发的兵力。

### 7.2 成本按真实纹理依赖，不按物种名

敌军成本计算所有动作、变身、投射物、召唤物和必要伴生物的纹理键并集，基础驻留估算使用实际整图宽×高×4。相同纹理键只计算一次，同一PNG注册为多个不同键不能按文件路径去重。

沿用项目既有预算：crowd/specialist/boss整套目标32/64/128MiB，超准入线64/128/256MiB按项目例外流程处理；场景受管理纹理稳态目标512MiB、过渡目标640MiB，还包括友军和建筑，不能全部分配给入侵。预算值是工程目标，不代表实际整机显存或已测帧率。

主编队3种不是总资源保证。建议通用入侵把“主编队＋必须同时存在的召唤/伴生敌人”控制在最多4种，变身形态虽然不一定算新怪物ID，但其纹理必须全部计入。超出的怪物先进入专属编队适配，不静默关闭技能。

只预取选定波次及必要依赖，不预取整个系列索引；保留上一波尸体、变身和切场重叠预算。资源瞬时压力交给原调度和驻留机制，不以随机换兵解决，也不删除已存在单位来腾额度。

### 7.3 召唤改为军团共享额度

现有有限召唤只接入了甲虫首领路径，不能视为所有召唤型怪物已经兼容。自动接入巫师、蝇手、巫婆、蟾祖等之前，应将补充额度提升为军团共享账本，而非每个召唤者各拿4个额度。

建议先维持全军额外补充4只的默认值，并约束生成速率、同时存活量、依赖种类与跨代召唤；需要更大额度的首领独立配置并重新评估。机械上通过正常召唤条件抑制超额启动，不在动画执行一半后丢弃结果。召唤物、召唤设施及其子代全部扣同一预算并保留战损与余额，避免换波、撤退、读档再生。

不同召唤技能需要各自接入正常的生命周期；本轮不承诺仅添加一个字段便自动兼容所有脚本。

## 8. 新怪物以后怎样接入

已有系列的新怪物，至少在自己的登记处给出：

```json
{
  "rank": "elite",
  "invasion": {
    "series": "wolf_pack",
    "mode": "assault",
    "enabled": true,
    "minDay": 15,
    "weight": 1
  }
}
```

此处仅展示新增的入侵声明，实际还需要原有实体与资源登记，并引用机制/预算元数据；不能把这段示例当作完整可运行怪物配置。角色可从rank推导，不再重复填三个角色名单；生态与通用机制规则可继承系列默认值。

- 新增“霜狼精锐”：复用狼族规则，登记与准入完成后自动进入精锐候选；不修改入侵名单和抽取代码。
- 同一怪物强化数值：仍属原系列，但重新计算入侵成本与解锁条件，不能自动保持原数量产生难度突升。
- 新增全新系列：登记一次系列规则；角色不齐则保留候选状态，后续补齐后自然具备成军条件。
- 新增有特殊技能的怪物：归类可以自动，技能生命周期和预算适配仍需实现，不能把“自动入池”说成“新怪物零接线”。
- 新增纯美术候选/未验收资源：不因文件出现而加入战斗。

## 9. 建议实施顺序与边界

1. **全量台账与元数据**：基于53条完成正式归档，标明候选、缺角色、固定守点、事件和依赖；在怪物自身保存归属，系列表只保存规则。数据/公开镜像按现有项目流程同步。
2. **统一登记与准入索引**：整理入侵所需的实体/模式入口，提供纯数据目录解析与解释性排除结果；不重写地牢配波或修改现有family伤害语义。建议新增 `src/config/enemy-invasion-catalog.js`，必要时新增基础敌人登记模块，避免从地牢巨型模块导入来获得工厂。
3. **接入编队**：修改 `src/world/invasion-formation.js` 与 `data/invasion-campaign.json` 的固定ID逻辑；继续复用现有一天行军、侦察、拦截、战损和基地交接，不改变这些流程的时间契约。
4. **补齐特殊适配与交付**：统一召唤账本和资源依赖预算，先启用资料完整的系列；为复杂首领列出未满足项。输出完整台账、自动纳入/排除报告和人工验收清单，不把未适配怪物伪装成已可用。

现有活动军团/旧waves继续使用已保存记录，不因分类迁移变更阵容。不做全局图鉴重分类、地牢改池、怪物技能改造或额外美术制作；必要的入侵模式适配单独列明。

## 10. 后续验收标准（本轮未执行）

- 53条全部可追溯到系列/专用类别或明确待确认原因，无静默漏项。
- 新增一个资料完整的同族精锐，不编辑入侵名单即可成为未来军团候选。
- 新怪改名、目录改名和数值参考文字不会把它误归另一个系列。
- noPool、专属特工、固定Boss、缺工厂/资源/机制登记的条目不会混入主动入侵。
- 一个系列有10种候选也只选择本次允许的有限种类；加载不会覆盖全部候选池。
- 每次恰有一个首领，普通/精锐不跨未声明的系列，复杂Boss不会自动降级占位。
- 召唤设施、子代、变身、尸体过渡均计入相应预算；多召唤者不会各自重领军团额度。
- 同种子、同目录版本、同状态生成同一军团；存读档、拦截、撤退和配置更新不会重抽已出发军团。
- 更强新怪加入后仍满足进度与威胁预算；不以候选数量扩大改变系列总概率。

以上为待实施方案。自动分类可以减少重复维护，但正确归属来自正式元数据与明确规则，实际强度和性能仍需要用户后续测试，或另行授权专项验证。
