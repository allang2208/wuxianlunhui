# RTS 指挥模式操作与命令契约

> 2026-08-30 入库边界：本文件中的现有兵种指令、队列、索敌及UI已纳入本次提交。城墙有限驻守/安全离梯的新接口与尚未入库的游击兵适配仍留在共享开发工作区，不能据此视为已发布；待各自基础实现入库后再合并。

## 操作

| 操作 | 行为 |
|---|---|
| F1 | 切换指挥模式；离开后玩家恢复手动操作，玩家未完成的队列取消 |
| 左键 / 拖框 | 单选 / 框选；框内有友军时优先选择友军 |
| Shift + 左键 | 将单位加入选择；已选单位再次点击则移除 |
| Shift + 拖框 | 追加框内单位，不清空已有选择 |
| Ctrl + 左键 / 拖框 | 从已有选择中移除单位 |
| 双击单位 | 选择屏幕内同类友军 |
| Ctrl + 数字 / Shift + 数字 | 创建编组 / 将当前选择追加到编组 |
| 数字 / 快速双击数字 | 选择编组 / 将镜头移到编组 |
| 右键地面 / 敌人 | 移动 / 指定攻击 |
| 小地图左键 / 拖动 | 移动镜头 |
| 小地图右键 | 前往小地图对应的地面位置；不会命中其下面的主画面单位 |
| A / P，再左键地图 | 移动攻击 / 两点巡逻；主画面与小地图均支持 |
| S | 停止当前命令并清空队列；军队恢复自动接敌，可追击 |
| H | 坚守并清空队列；军队只攻击当前位置可打到的敌人，不追击或冲锋 |
| Shift + 右键 / Shift + 目标确认 | 为各单位追加移动、指定攻击、移动攻击或巡逻；空闲单位立即执行 |
| 长按中键 | 打开轮盘，移到指令上松开；轮盘保留墙顶、楼梯和高度信息，支持 Shift 追加 |
| Esc | 优先取消待选命令、集结取点或轮盘，再处理面板/菜单；浏览器与 Electron 共用入口 |

P 在指挥模式中归巡逻，普通角色模式仍归队伍栏目。文本框、下拉框、可编辑文本保留输入，不触发角色操作或 RTS 快捷键。科技树、世界切换等独占栏目和暂停态不接收指挥快捷键。

`data/game-config.json` 与既有 `public/data/game-config.json` 的 `rtsCommand.hotkeys` 保存 A/P/S/H 键位，值为浏览器 `KeyboardEvent.code`。自定义时应使用互不重复的键位，避免占用 F1、Esc、数字编组和 Space 压平；本次未增加键位设置面板。

## 单位能力与城墙

### 左侧指令栏（2026-08-30）

- 上方“兵线部署 · 新生产士兵”只管理出兵后的跟随/出口待命/自订集结，保留原科技门禁与建筑独立集结优先规则；下方“选中单位”才给当前选择下令。
- 常驻按钮：移动、指定攻击、移动攻击、巡逻、停止、坚守、跟随玩家。无可执行单位时禁用，悬停显示原因；混编时角标显示可执行人数/选中人数。采集仅在选中正式队友等支持采集的单位时出现。
- 移动、移动攻击、巡逻、采集点击按钮后左键地图取点；前三者沿用原表面寻路，采集只是指定资源搜索区域。指定攻击只接收主画面的可见敌人，小地图点击不能隔着地图选中敌人。移动/攻击沿用玩家独立控制器、原队列与目标反馈，不新增AI执行分支。
- 只有移动、指定攻击、移动攻击、巡逻支持Shift追加；跟随/采集/探险替换原命令。跟随玩家、停止、坚守点击即执行；目标选择可用右键、Esc或栏内“取消”退出。
- 探险家显示开始探险，并在有人探险时追加停止探险；忍者显示烟遁隐身，并在有人隐身/施法时追加解除隐身。混选不同状态时可分别开始/停止，不再由一个切换按钮互相遮住入口。冷却、探险时间和可执行人数随状态更新。
- 按钮改为网格流式布局，高度随内容增长并在剩余屏幕空间内滚动，修复停止/坚守沿用绝对定位造成重叠的问题。A/P/S/H仅在指挥态显示，普通队友选择态不暗示这些键已接管。
- 快捷键位于对应图标下方、指令名称上方，沿用右侧栏目银灰色20px加粗等宽字体；同组按钮保留键位行以对齐，没有绑定的指令不显示虚构键位，禁用指令的键位同步变暗。
- 图标由内置image_gen生成一张4×3冷钢图集，左栏、兵线部署和中键轮盘共用。映射/文案在`src/ui/rts-command-presentation.js`，样式在`ui/panel-theme-backpack.css`，素材/来源/提示词在`assets/ui/rts-command/`；图像没有烘焙文字或快捷键。

### 执行边界

- 玩家继续使用独立 `PlayerRtsController`，支持移动、指定攻击、停止/待命以及移动/攻击队列；不支持移动攻击、巡逻、跟随或采集。单选玩家时相关按钮禁用，混编时显示可执行人数和部分拒绝原因。
- 正式队友继续交给 `PartySystem` 和原 AI；玩家及正式队友的 H 保留原地待命、不自动施法/攻击的既有行为。军队的原地自动攻击复用各兵种射程、近射盲区、LOS、高度判定。
- 仓鼠军队待机/坚守、停止后的接敌及移动攻击/巡逻读取本兵种 `ai.engageRange`；900px 只作缺省值，不再统一截断狙击手等长射程单位。斥候、射手、火枪及牧师基础 AI 的默认索敌同样读取该配置。坚守会从范围内选择当前位置能攻击的敌人，目标失效后继续选敌，不攻击友军或资源点，也不会为射程外目标离开岗位。
- 防暴队（及继承其攻击方式的兵种）的可攻击判定与实际开火共用真实地面距离和 LOS，保留原300px射程，不能按压缩后的画面距离误锁不可射击目标。投石组仍保留近射盲区及抛物线遮挡检查。
- 新移动/攻击命令必须先通过该单位的能力与目标检查，再取消原动作或高层巡逻；拒绝新命令保留旧任务及队列。
- 移动层禁止坚守攻击生成追击位移，骑兵不会因此发动冲锋；保留既有击退、恐惧与高架导航顺序。后续有限驻守集成还须保持预约、不打断安全离梯，不能把坚守做成跳过这些规则的坐标锁；该驻守集成不在本次提交内。
- 小地图只表示地面。需要指定墙顶/塔楼/楼梯时，在主画面使用右键、按钮或轮盘；三者共用表面解析。

## 队列

- 每单位最多追加 32 条，配置项为 `rtsCommand.commandQueueLimit`；保存目标位置/表面/目标实体，不保存旧路线，也不为未执行的单位预占终点。
- 同一次群体地面命令共享实际接受的终点预约，兼容空闲单位立即执行与忙碌单位稍后执行。下一单位开始时回收死亡、移除或已离开且改令的预约，避免受阻投影挤到重叠落点；不增加每帧队形调整。
- 由原执行器自然完成移动、指定攻击或移动攻击后推进。完成记录同时关联旧命令和完成后的状态，外部命令接管后旧队列不能恢复控制。尚未入库的游击兵适配应同样发布完成记录并保留已经起手的移动射击，随该兵种另行合并。
- 两点巡逻是持续任务，没有自然终点；其后的队列会等待。使用不带 Shift 的新命令或 S/H 结束巡逻并清空后续队列。
- 执行时重新规划路线；目标死亡、不可见或不可达时跳过该条并显示原因，后续条目继续处理。移动攻击/巡逻在接敌结束或折返时重新规划失败，也会记录任务失败并续行后续队列，不误判为外部改令。已执行中的墙面路线仍保留原有等待/重试规则。
- 队列只在当前运行场景有效，不写存档。死亡、移除、换场景会清理；F1 退出只取消玩家队列，仍在本场景中的部队继续执行。
