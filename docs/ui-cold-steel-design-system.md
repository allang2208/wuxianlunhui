# 冷钢档案 UI 设计系统与标准工作流

版本：1.0
生效日期：2026-08-21
适用范围：主菜单、游戏 HUD、右侧栏目、建筑详情、模态窗口及后续新增的所有玩家可见 UI。

本文是项目 UI 的权威执行规范。新增或修改 UI 前必须先阅读本文；若旧实现与本文冲突，新工作优先向本文收敛，但不得借单个需求扩大为全局重构。

## 1. 设计目标

“冷钢档案”延续背包界面的灰、白、黑基调，但比背包更克制、更偏战术档案：

- 黑色与炭灰负责外壳和层级，不使用大面积纯黑死板铺底。
- 白色负责主信息，冷灰负责辅助信息，银灰负责边框与交互强调。
- 金币、能源、危险、成功、稀有度等游戏语义色只用于对应信息，不参与普通装饰。
- 信息密度可以高，但必须依靠标题、分区、间距和字体档位建立清晰层级。
- 同类面板必须共享尺寸、动画、挂载层和关闭规则。

## 2. 单一真源

| 规则 | 真源 |

| 面板生命周期 | `src/ui/panels/base-panel.js` |
| 右侧栏目挂载与层级 | `src/ui/right-sidebar-panel-layer.js` |

## 3. 色彩规范

### 3.1 基础色

新面板必须优先使用以下变量，不直接硬编码近似灰色：

| 用途 | 变量 |
|---|---|
| 最深背景 | `--bp-ui-black`、`--bp-ui-black-soft` |
| 面板炭灰 | `--bp-ui-charcoal`、`--bp-ui-graphite` |
| 控件与卡片灰 | `--bp-ui-gray`、`--bp-ui-control`、`--bp-ui-surface` |
| 主文字 | `--bp-ui-white`、`--bp-ui-text` |
| 次要文字 | `--bp-ui-text-muted` |
| 弱提示文字 | `--bp-ui-text-dim` |
| 普通边线 | `--bp-ui-line` |
| 强边线 | `--bp-ui-line-strong` |
| 选中强调 | `--bp-ui-accent-bright`、`--bp-ui-line-accent` |
| 面板外壳 | `--bp-ui-shell` |

### 3.2 全局滚动条

滚动条由 `ui/panel-theme-backpack.css` 统一定义，不在业务面板单独建新变量：

- CSS 变量：
  - `--bp-scrollbar-size: 8px`
  - `--bp-scrollbar-radius: 4px`
- 全局应用规则：
  - Firefox：`scrollbar-width: thin`，`scrollbar-color: var(--bp-ui-gray) var(--bp-ui-black-soft)`
  - WebKit：统一宽高 `var(--bp-scrollbar-size)`；轨道 `var(--bp-ui-black-soft)`；滑块 `--bp-ui-gray` + `1px solid var(--bp-ui-black-soft)` + `var(--bp-scrollbar-radius)`
  - hover 使用 `--bp-ui-accent`，active 使用 `--bp-ui-accent-bright`
  - `::-webkit-scrollbar-corner` 使用 `--bp-ui-black-soft`
- 因兼容旧样式高特异性覆盖，规则保留 `!important`。
- 禁止业务层面重置滚动方向/行为（overflow 由面板本身契约决定），禁止局部覆盖滚动条为项目外观。

### 3.3 游戏语义色

- 金币、能源、生命、危险、成功、稀有度可以保留各自颜色。
- 语义色只出现在数值、图标、状态条和关键反馈上。
- 普通标题、卡片边框和按钮不得使用金币黄、生命绿或危险红装饰。
- 同一状态在不同面板必须保持同色；不能为了“更好看”改变语义。

## 4. 字体与信息层级

默认字体使用 `--bp-font-ui`，纯数字、计时、坐标和紧凑数值使用 `--bp-font-number`。

| 档位 | 变量 / 类 | 使用场景 |
|---|---|---|
| 展示标题 | `--bp-type-display` / `.bp-type-display` | 主菜单标题、重大页面名称；普通栏目禁用 |
| 面板标题 | `--bp-type-title` / `.bp-type-title` | 一级面板标题、建筑详情标题 |
| 分区标题 | `--bp-type-subtitle` / `.bp-type-subtitle` | 模块组、属性组、二级区块标题 |
| 正文 | `--bp-type-body` / `.bp-type-body` | 描述、主要内容、普通按钮 |
| 辅助信息 | `--bp-type-meta` / `.bp-type-meta` | 数值说明、状态、副标题、快捷键 |
| 微型说明 | `--bp-type-caption` / `.bp-type-caption` | 时间戳、悬停提示、极次要说明 |

执行规则：

- 一个面板最多同时出现四个字体档位，避免层级噪声。
- 正文不得低于 `body`；只有明确的辅助信息才使用 `meta` 或 `caption`。
- 标题使用紧行高和标题字距；长正文使用 `--bp-leading-body`。
- 不在 HTML `style` 中重新写 `font-size`；优先使用语义类或主题选择器。
- 中文内容不使用全大写模拟标题；英文缩写可保留。

## 5. 面板类型

### 5.1 右侧主栏目和建筑详情栏目

- 标准尺寸：`45vw × 100%`，固定在屏幕右侧。
- 统一从 `translateX(100%)` 滑入到 `translateX(0)`。
- 动画：`0.25s cubic-bezier(0.4, 0, 0.2, 1)`。
- 建筑详情是建筑主栏目的同级独立栏目，不嵌套为父子 DOM 页面。
- 同一位置一次只把当前操作栏目置于最前；关闭详情后应自然露出原栏目。

### 5.2 居中模态窗口

- 用于必须先处理才能返回游戏的决策，不得用来承载普通详情。
- 必须有遮罩、清晰标题和唯一关闭路径。
- 尺寸由内容和目标分辨率决定，不强制套用 `45vw` 右栏尺寸。

### 5.3 HUD 与小型状态栏

- HUD 不使用整块高亮面板抢占战斗视野。
- 外壳、边框、字体仍使用冷钢变量；资源和危险信息保留语义色。
- 同一侧的面板宽度、间距和对齐线必须统一。
- HUD 只展示即时决策需要的信息，详细说明放入对应栏目。

### 5.4 上方通知与升级效果（2026-08-30）

- 字体共用`--bp-font-ui`。普通通知20px，场景标题/重要警告24px；升级保留28px主标题、18px说明与48px图标，闪光/音效随本条显示一起开始。
- 色彩由主题的`--bp-notice-*`统一：info银白、success柔和绿、warning琥珀、danger柔和红；金色只用于升级。不得按通知文本猜测类型。
- `SceneManager.showTopNotification`使用`tone`与`emphasis:'headline'`声明语义。已有调用的已知color归入对应语义色，fontSize>=24归入重要档；未识别的自定义颜色仍作为显式语义例外保留，不恢复旧48px默认。
- 通知按内容换行、限制宽度，不截掉危险详情；升级和普通通知共用`TopNotificationQueue`，按调用先后FIFO显示，同一时刻只能有一条；前条完整结束并移除后才展示后条。错误不插队、不打断，不因同文案合并或丢弃通知。
- SceneManager、人物/技能升级、背包满、改造返还和裂隙完成均通过共享队列；新上方通知禁止自行append到body或另开播放计时器。升级入口每次调用直接登记到公共队列，禁止先在升级私有队列积压再转交，避免改变跨来源顺序。
- 永久属性及冷却刷新在升级提交时执行一次，不等待通知显示，也不因取消提示丢失。仅文字、闪光、音效排队；数据在入队时快照。默认普通3000ms、升级2800ms（文字动画2500ms），调用方显式时长继续生效；升级最短500ms覆盖闪光周期，文字动画不超过本条播放时长。
- 该队列仅负责顶部瞬态通知；底部常驻路线HUD、模态、武器切换状态和世界飘字保留各自生命周期，不纳入排队。大量连续触发时后续通知会延后，不能以插队或丢弃破坏顺序。
- TimerManager暂停时剩余时长与CSS动画一起冻结，暂停期间新增提示只入队；恢复继续，退出游戏/clearAll清空所有提示与附属特效。仅清理升级类时不删除其它提示，后续按原FIFO推进。渲染异常必须清理该条部分DOM并释放播放槽。
- 队列实施回退范围（2026-08-30）：新增`src/ui/top-notification-queue.js`；修改level-up-queue、timer-manager、scene-manager、backpack-dialog-manager、craft-system、rift-system、game-menu与主题CSS。只撤销本次队列接线/生命周期订阅和升级回调时机调整，保留前轮字体颜色及并行改动；不得整文件回退。升级清理不再影响已发放属性。

## 6. 结构和通用组件

标准新面板使用以下结构：

```text
panel root
├─ .bp-panel-header
│  ├─ title / meta
│  └─ .bp-panel-close
└─ .bp-panel-body
   ├─ .bp-panel-section
   │  ├─ .bp-panel-section-title
   │  └─ content
   └─ .bp-panel-actions
      └─ .bp-button
```

规则：

- 面板根类必须是业务专属类，例如 `.research-panel`，不能只依赖通用类定位。
- 标准右栏根节点同时使用业务根类和 `.bp-right-column`；内部优先复用 `.bp-panel-*` 和 `.bp-button`。
- 关闭控件必须使用原生 `<button type="button">`，并提供 `aria-label`。
- 可点击卡片优先使用 `<button>`；必须使用其他元素时补齐键盘和 ARIA 语义。
- 不通过内联样式拼装整套视觉；动态宽度、进度和游戏语义色可以使用内联变量。

## 7. 生命周期、挂载层和关闭规则

### 7.1 默认生命周期

抽屉式面板优先继承 `BasePanel`：

- `buildContent(el)` 只负责首次构建 DOM 和绑定事件。
- `onOpen()` 刷新数据，不重复创建 DOM。
- `open()/close()/toggle()` 不自行重写。
- 显隐只切换 `.active`，动画由 CSS 负责。

### 7.2 右侧栏目挂载

右侧栏目统一使用：

```js
mountElement: (el) => mountRightSidebarPanel(el, 'panel', { bringToFront: true })
```

禁止分别挂到 `#uiLayer`、`#gameContainer` 或 `body` 后用更大的 `z-index` 补救。

### 7.3 关闭规则

- 普通面板：标题栏关闭按钮；是否允许遮罩关闭由其交互性质决定。
- 建筑详情：`panelGroup: 'buildingDetail'`、`closeOnEscape: true`、`closeOnOutsidePointer: true`。
- Esc 优先关闭最内层模态或详情，再关闭主栏目，不能同时触发角色输入。
- 外部点击关闭时必须阻止点击穿透到攻击、移动或场景选择。
- 打开事件的首个点击保护由 `BasePanel` 处理，不在业务面板重复实现。

## 8. 交互状态

按钮和卡片至少考虑以下状态：

- 默认：冷灰控件底色和普通边线。
- 悬停：文字变亮、边框增强，不做大幅缩放。
- 选中：银灰强调边、左侧强调线或轻微内发光。
- 禁用：降低对比度并禁用指针事件，同时保留原因提示。
- 危险操作：只有出售、删除、放弃等破坏性动作使用危险色。
- 键盘焦点：必须有可见 `:focus-visible`，不能只设计鼠标悬停。

默认鼠标箭头统一读取主题变量`--bp-cursor-default`，复用48×48冷钢箭头与尖端热点`(3,2)`；右侧栏目、面板空白区、模态背景和非交互信息区通过根层样式继承。禁止用`* { cursor: ... !important }`覆盖后代：按钮的点击手型、文本输入光标、`grab/grabbing`拖拽状态、移动/缩放和禁用反馈必须保留。世界准星与指令游标只在真实游戏表面接管，进入UI后交还控件样式。

点击、可拖拽、拖拽中三种手型统一为银灰甲片、炭黑接缝的冷钢手套，分别使用`var(--bp-cursor-pointer, pointer)`、`var(--bp-cursor-grab, grab)`、`var(--bp-cursor-grabbing, grabbing)`。按统一大小要求，三张透明PNG均为48×48，源图Alpha内容框等比缩放至44px可见长边并居中；当前三态可见高度相同，保留各自宽高比，不再按主甲片宽度定标。热点随相同裁框/缩放变换：点击食指尖`(20,2)`、张手掌心`(27,33)`、握手掌心`(25,29)`，不将源图留白或旧热点带入新版。切换不添加漂浮或缩放动画，仅替换图片与热点，保持选择器优先级、禁用态和原有拖动状态机；原生HTML拖放期间浏览器/系统的允许或禁止放置反馈不强行覆盖。

手型变量由主题入口导入`ui/hand-cursors.generated.css`，源图及提示词归档于`tools/ai-gen/hand-cursors-cold-steel-20260830/`；运行其中`export.ps1`同步导出正式PNG与内嵌PNG变量。采用内嵌URL是为了兼容不同目录样式表与内联消费者，避免[CSS变量的相对URL解析规则](https://www.w3.org/TR/css-variables-1/#defining-variables)导致路径漂移，不增加运行时样式扫描器。

**游戏内物品拖动例外（2026-08-30）**：为避免原生HTML拖放接管后回退Windows指针，背包、装备、仓库、队员背包、改造/附魔槽及快捷栏物品使用统一受控鼠标拖动，复用原有DragEvent/DataTransfer放置处理。只有实际超过起拖阈值后才启用临时`item-drag-active`状态，以`--bp-cursor-grabbing`强制显示现有冷钢握手并屏蔽世界指针/输入，物品小预览放在手掌右下方，不改热点或真实鼠标坐标。松手、Esc、失焦或源失效必须清理状态；取消不能触发丢弃/归还/解绑。技能、文本、外部文件以及非物品原生拖放不接管，正常状态禁止全局覆盖后代cursor。

动画以短、稳、可预测为准；普通控件使用约 `0.16s`，栏目使用 `0.25s`。禁止弹跳、旋转或与战术界面不符的夸张缓动。

## 9. 标准工作流

### A. 新增面板

1. **备份**：修改前建立带日期的回退记录，列出新增文件、修改文件和删除方法。
2. **分类**：确认是右侧栏目、建筑详情、模态窗口还是 HUD，先确定尺寸和关闭规则。
3. **选参考**：同类面板优先参考背包或已经迁移的同类面板，不跨类型照搬。
4. **复制模板**：从 `docs/templates/cold-steel-panel-template.js` 建立业务面板。
5. **接生命周期**：使用 `BasePanel`、`UIState` 和正确挂载层。
6. **接主题**：标准右栏使用 `.bp-right-column`；内部使用主题变量、字体档位和通用组件类，业务根类只写专属布局。
7. **实现内容**：先完成标题、分区和主要操作，再加入辅助信息；避免先写大量内联样式。
8. **检查交互**：关闭按钮、Esc、外部点击、点击穿透、键盘焦点和打开顺序。
9. **静态核对**：检查 diff、选择器范围、旧调用和硬编码；不扩展到无关面板。
10. **交付**：按项目约定不主动启动游戏或运行测试，明确列出需用户重点验证的界面状态；只有用户明确授权时才进行运行时验证。

### B. 修改现有面板

1. 备份本轮目标文件或建立可执行回退说明。
2. 确认需求是视觉、布局、生命周期还是业务逻辑，避免混改。
3. 视觉调整优先在 `panel-theme-backpack.css` 覆盖，不破坏既有 DOM 和事件。
4. 生命周期不一致时收敛到 `BasePanel` 和右侧挂载层。
5. 将硬编码的灰、白、黑和字体大小替换为主题变量；保留有意义的游戏语义色。
6. 同类面板同步尺寸、动画和关闭规则，但不顺带改造需求之外的其他面板。
7. 完成后按新增面板的第 8–10 步交付。

## 10. 交付检查表

### 视觉

- [ ] 使用冷钢主题变量，没有另建近似灰黑色板。
- [ ] 标题、副标题、正文、辅助文字使用正确字体档位。
- [ ] 游戏语义色只表达对应状态。
- [ ] 分区、间距、边线和对齐关系清楚。
- [ ] 1080p 与 2K 目标下没有依赖固定坐标的明显风险。

### 结构

- [ ] 使用业务根类和通用组件类。
- [ ] 右侧栏目挂载到 `rightSidebarPanelLayer`。
- [ ] 详情栏目不是主栏目的子页面。
- [ ] 没有重复实现 BasePanel 已提供的生命周期。

### 交互

- [ ] 打开、关闭和重复打开状态正确。
- [ ] 关闭按钮、Esc、外部点击符合面板类型。
- [ ] 不发生点击穿透或角色输入串扰。
- [ ] 默认、悬停、选中、禁用和焦点状态完整。

### 范围与交付

- [ ] 修改前已有回退记录。
- [ ] 没有处理无关面板或其他会话的改动。
- [ ] 静态 diff 中没有遗留旧挂载、旧选择器或无用导入。
- [ ] 已明确说明未运行的测试以及用户需要验证的状态。

## 11. 例外规则

- 需要独特叙事表现的过场、结局或剧情 UI 可以偏离冷钢外壳，但文字层级、输入和可访问性规则仍适用。
- 开发工具面板不要求完整美术表现，但不得遮挡玩家 UI 或复用玩家面板状态键。
- 如果新需求必须改变本规范，应先更新本文和主题真源，再实现业务面板，避免代码与规范长期分叉。

## 12. 维护方式

- 新规则只记录稳定结论，不写调整过程流水。
