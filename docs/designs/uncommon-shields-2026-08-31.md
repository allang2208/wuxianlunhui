## 改造规则

每款盾牌固定3个实体部位，每个部位3选1；每盾9项、两盾共18项配件，但单面盾最多同时安装3件。九个方向不是九个可叠加槽，而是分散到三组互斥选择中，避免物防、主动格挡、弹反、机动与被动格挡同时堆满。采用现有改造券机制：首次安装每槽1张，同槽更换4张，三槽首次装满共3张。全部为普通配件，没有特殊改造槽、随机词条或新增货币。

部位名称用于改造面板，图标展示实际钢板/盾脐/握柄/木芯/铁边/承带。正面图不可见的握柄、前臂带应标注“背面”，连接线不能落在不相关的正面装饰上。槽位 `x/y/lineTarget` 要在改造展示图中经候选布局、预览和人工调整后保存，设计阶段不写猜测坐标。

## 数值口径与上限

- 配件加的是“本盾物防”，不直接乘玩家全部物防。盾牌物防 = `floor(max(0, base + perEnhance × E + shieldDefenseFlat))`；原有持盾技能对总物防的倍率随后照旧应用。
- 格挡承伤 = `max(0.05, min(1, baseDamageRatio − shieldBlockReductionBonus − 持盾技能减伤加成))`。例如+5个百分点把卫戍盾58%减伤变为63%，不是58%×1.05。
- 防御移速倍率 = `clamp(0.35, 0.50 + shieldDefenseMoveSpeedDelta, 0.75)`；只改变防御状态步行，不允许防御中冲刺，也不乘普通移速词条两次。
- 体力、时窗和眩晕均为本盾基础值加对应配件增量；眩晕再加已有持盾技能效果。只读取当前武器组的配对盾牌，不叠加备用盾。
- 以100点**已扣护甲**的伤害示意，未改造时技能0/10/20级分别承受：小圆盾50/30/10，拳盾50/30/10，卫戍盾42/22/5。此示例只解释盾牌独立减伤，不代表完整玩家伤害结算的最终取整。
- 主动格挡减伤在触及5%承伤下限后不再继续降低；面板必须显示封顶，不能继续宣称100%减伤，技能的其他既有效果仍正常成长。
- 持有100体力、忽略回体与弹反时，未改造的小圆盾/拳盾/卫戍盾分别可以完整支付5/6/4次普通格挡。破防当击仍减伤、余体力归零、眩晕1500ms的现行规则不变。
- “格挡成功后减伤”只由**成功的非弹反主动格挡**在本次伤害结算完成后赋予1层；本次命中不能立刻吃到该层。层数不叠加、不刷新，下一次合格直击消耗；触发或过期后才进入冷却，冷却中再次格挡不赋层。
- 被动近战格挡只接受 `hitContext.isMelee === true`；被动投射物格挡必须接受显式 `hitContext.isProjectile === true`，不能用 `isMelee === false` 冒充，否则会把环境、持续伤害和无来源魔法范围伤害错误归入“投射物”。
- 两类被动格挡仅在当前配对盾牌已装备且玩家**未处于主动防御**时判定；不耗体力、不触发弹反、不赋予“格挡后减伤”，排除DOT、环境伤害、自伤和无敌伤害。
- 同一次命中若盾牌被动格挡、主手次级格挡或护甲自动格挡同时触发，只结算减伤最高的一个自动格挡来源，不进行乘法叠加；只让最终采用的来源进入冷却。主动盾牌格挡优先，并直接跳过全部被动格挡。
- 伤害顺序固定为：护甲与暴击结果 → 主动盾牌格挡或单个自动格挡 → 格挡后余势减伤 → 其他最终全局修正。随机判定每个有效命中事件只进行一次，面板预览与实战必须读取同一聚合结果。
- 两款仍沿用普通格挡全方向、弹反总角度240°和已有重举规则。改造不新增无敌帧、盾击、反伤、额外碰撞尺寸或格挡角度。

## 接入时必须补齐的盾牌专用效果

小圆盾 `weapon17` 仍保持无改造条目的兼容基准；`weapon56`—`weapon59` 已由 `getShieldDefenseValues` 消费盾牌专用九键。现有 `staminaCostDelta` 仍只指普通攻击耗体力，`defensePercent` 仍是主手字段，后续盾牌不得拿它们冒充盾牌改造。

| 拟新增效果键 | 值类型与含义 | 主要消费端 |
|---|---|---|
| `shieldDefenseFlat` | number，本盾物防固定增量 | `getShieldDefenseValues`、玩家物防与提示 |
| `shieldBlockReductionBonus` | number，主动格挡减伤百分点的小数增量 | 盾牌普通格挡与改造预览 |
| `shieldStaminaCostDelta` | number，每次普通主动格挡的体力增量 | 盾牌体力支付与提示 |
| `shieldDefenseMoveSpeedDelta` | number，防御状态基础移速倍率增量 | 玩家防御移动分支 |
| `shieldParryWindowDelta` | number，弹反判定时间增量，ms | 进入防御时窗与提示 |
| `shieldParryStunDelta` | number，近战弹反后眩晕增量，ms | 近战弹反结果；反制免疫规则仍优先 |
| `shieldAfterBlockGuard` | object，`{ reductionPercent, durationMs, cooldownMs, charges: 1 }` | 主动格挡成功后的单层余势状态与下一次直击 |
| `shieldPassiveMeleeBlock` | object，`{ chance, reductionPercent, cooldownMs }` | 非防御状态的近战直击自动格挡 |
| `shieldPassiveProjectileBlock` | object，`{ chance, reductionPercent, cooldownMs }` | 非防御状态、显式投射物直击的自动格挡 |

所有效果先登记 `src/config/craft-effect-registry.js`。标量与对象均在 `getShieldDefenseValues` 统一合成，再让盾系统、玩家盾物防汇总、移动分支、伤害链、强化/装备提示和改造预览共用结果。三个对象键不能按普通 number 求和；同一槽只有一个对象选项生效。不要只添加JSON文案而漏掉实际消费，也不能复用普通攻击 `staminaCostDelta` 或主手 `defensePercent` 冒充盾牌字段。

装备静态定义沿用 `EquipDataManager`，模板配置按 `data/`、`public/data/` 双份同步。两款使用 `forged_duelist_buckler` / `weapon56`、`oak_garrison_shield` / `weapon57`；改造配置已登记。
