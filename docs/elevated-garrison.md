# 城墙与塔楼驻守位置

城墙、塔顶继续允许友军在移动中互穿，停留时按单位地面半径分配互不重叠的位置。驻守是运行时位置预约，不新增兵种命令、刚性行军编队、全局寻路障碍或硬碰撞。

## 规则

- 点击墙顶的移动命令先等待分配，再沿原高架路线与楼梯FIFO前往各自终点。原始点击点不被替换，分配位置和派生路线另存；未分配不能算到达。
- 优先原目标附近同高度、同连通墙面的合法位置，最多搜索384个地面单位距离。容量由真实墙顶联合承托区域、楼梯净空和现有预约决定，不写死每墙/每塔人数。网格分配是保守布局，不追求几何最大装填数。
- 部署间距在未压缩的等距地面u/v中计算，为双方地面半径之和加8；普通半径20士兵的中心间距为48。最终世界坐标到达容差2，保留误差余量。楼梯连接面额外留16净空；楼梯踏步不提供驻守位。
- 待命、自动攻击间隙和跟随停步共用分配。已起手攻击/施法和已发弹体仍由原兵种系统推进，不被分配器取消；硬控、击退与技能位移继续优先。
- 跟随单位在已分配的位置等待未移动的玩家，AI仍能索敌；玩家移动超过48或离开该层后恢复原跟随。避免反复追逐共享跟随偏移点。战斗停位候选不增加与原敌人的平面距离，实际射程、LOS和攻击资格仍由原AI决定。
- 附近满员时保留原命令等待。已经在墙上且没有合法驻守位的单位尝试沿现有楼梯退到梯外地面；没有安全出口则等待，不瞬移或关闭墙体碰撞。已在梯中的单位先完成原出口，再处理分配。满员记录采用搜索开始时的占用版本；整轮占用未变才停止重复搜索，途中释放的空位会在退避后重新检查。
- 自动停位的单位安全落地后，等待空位不阻断原AI索敌、治疗和撤退；新行动释放旧停位，未移动玩家的旧跟随点只在移动层被拦住，避免无空位时反复上下楼。显式上墙移动命令仍保留目标等待，墙上无位和梯中通行仍遵守原驻守与离梯规则。
- 玩家手动模式只作为实际占用被观察，不自动归位。F1 RTS模式下的移动、待命和攻击站位使用同一分配器，仍通过玩家原有移动/武器系统发布意图；跟随目标按真实命令来源识别，玩家不会被当作跟随自己的士兵。
- 新命令、离位、死亡、失去承托和场景卸载释放预约。拓扑变化清候选缓存并重新分配；非命令派生的停位以当前完好墙面重新定位。状态不存档，加载后按实体与当前结构重建。

## 开销与范围

`data/defense-structures.json`及已有`public/data`副本中的`wallWalk.garrison`控制参数。每帧最多检查64个候选、为新增分配规划4条路线，并设2ms软时间预算；单次已有几何/路线函数不能中途抢占，不能将2ms当作实测硬上限。未完成搜索保留游标并轮转队列。

预约和实际停留体使用局部空间桶；几何候选缓存最多4096项，按墙体拓扑版本失效。单位观察复用既有高架表面遍历，预约按250ms清理，脱离观察超过3秒回收。已获得位置不逐帧重新分配。没有改地面A*预算，也没有引入汇编/Wasm。

选中单位详情显示分配、前往驻守、驻守、满员离墙/等待或不可达。现有性能计数入口新增`garrison.candidates/plans/queued/reserved/usedMs`，便于用户后续采样。

本轮覆盖前台墙顶实体站位；不改大型单位准入、友军高架互穿、墙体/防坠碰撞、楼梯FIFO、伤害公式、出兵编制或后台离线战斗的兵力/DPS统计。离线结算尚不根据实机驻守位置限制输出，不能将本轮视为后台城防平衡重做。

## 涉及文件

- `src/ai/elevated-garrison.js`：位置预约、空间桶、候选缓存、预算和等待状态。
- `src/world/defense-system.js`：复用真实承托/连通/楼梯几何、表面观察和安全离墙路线。
- `src/ai/rts-command-utils.js`：原命令与驻守派生路线分离、精确到位、等待不误报到达。
- `src/systems/movement-system.js`：空闲站位、跟随停留、逐帧末段减速及性能计数。
- `src/ai/elevated-navigation-controller.js`：场景与失去承托的预约清理。
- `src/entities/player/rts-controller.js`：玩家RTS意图接入，手控退出分配。
- `src/ui/rts-command.js`：选中单位驻守状态文字。
- 双份`defense-structures.json`、`skill/08-pathfinding-movement.md`、`CHANGELOG.md`：配置与交付记录。

## 用户验收

未运行测试、构建、lint、浏览器、游戏或性能验证，按项目约定由用户测试。未同步固定EXE。

1. 多选普通士兵点击同一墙顶与塔顶，确认停留位置分散，转角/塔墙连接合法，移动仍可互穿。
2. 填满附近区域，确认多余单位保留命令等待；已在墙上的无位单位沿楼梯退出。在分配搜索尚未结束时让驻军离位，确认途中释放的空位也能被重试发现。
3. 在窄梯与宽梯中途下待命/反向命令，确认先离梯，反向FIFO与原碰撞仍有效。
4. 自动射击、近战、施法与跟随结束后确认站位；玩家不移动时不反复追旧跟随点，移动或下墙后正常跟随。退到地面等待时，新敌人、治疗需求和撤退仍由原AI响应，没有新行动时不反复上墙。
5. 驻守中再次下令、被击退/控制、死亡、拆墙/拆塔和换场，确认不残留幽灵预约，不瞬移、不重复结算坍塌伤害。
6. 玩家手动穿过驻军，再用F1移动/待命/攻击，确认没有手动吸附，武器、换弹与控制状态保持原流程；拥挤墙面只剩较远空位时，玩家待命调整不应因自身走出96距离就取消预约。
7. 大批量命令下检查队列延迟与上述性能计数；实际帧耗时及布局密度仍需实机验收。
