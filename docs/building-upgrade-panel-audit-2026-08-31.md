# 建筑升级按钮排查与修复（2026-08-31）

## 结论与边界

单次升级没有被业务层删除。旧 `TechnologyGate` 会把未解锁的单次按钮设成 `visibility:hidden`，但共用升级卡后来追加的“持续升级”按钮仍可见，造成只剩持续升级的观感。此前房屋已单独修正，仓库等级扩建与研究所塔楼扩建仍遗漏；部分经济功能模块也存在同源显示问题。

本次按 `SKILL.md` 第07卷的建筑/科技契约及第10卷的共用升级卡、冷钢UI规则进行源码排查和修复。只调整按钮可见性、锁定说明与等级卡宽度，不改费用、科技解锁条件、读条、升级效果、持续升级调度、外观资源、逻辑占地、道路或存档。

## 一、手动付费扩建并换外观

配置来源为 `data/population-economy.json` 中的三组 `levels`，执行入口仍为 `PopulationEconomySystem`。

| 建筑 | 等级 | 排查结果与处理 |
| --- | --- | --- |
| 房屋 | Lv.1～7 | 上轮已恢复；保留“升级 / 持续升级”及科技锁定说明。 |
| 仓库 | Lv.1～5 | 本轮恢复单次“升级”；未解锁时显示所需科技，按钮禁用但不隐藏。沿用 `startWarehouseLevelUpgrade()`。 |
| 研究所 | Lv.1～3 | 本轮同步恢复单次“升级”；未解锁时显示所需科技。沿用 `startResearchUpgrade()`。 |

三类等级卡均占满栏目内容宽度，右侧保留单次与持续两项操作。读条中禁用单次按钮；满级保持双按钮位置并禁用继续升级。仓库和研究所增加科技锁状态变化的增量刷新，面板开着时不应停留在旧锁态。

## 二、科技完成后自动换形

以下10类建筑的外观由 `data/producer-buildings.json` 中的 `buildingTiers` 或 `recruitmentTiers` 决定，并不走上表的本栋付费扩建。科技系统 `_refreshConsumers()` 调用生产建筑的 `refreshBuildingTier()` / `refreshRecruitmentTier()`；建造时也读取当前科技档位。这些建筑没有额外“建筑本体升级”按钮属于现有机制，不补造重复收费入口。

| 建筑 | 配置档数 | 外观升级方式 |
| --- | --- | --- |
| 指挥所 | 3 | 指挥所 → 司令部 → 国防部，随建筑等级科技切换。 |
| 城墙塔 | 5 | 沙砌 → 砖砌 → 黑砖 → 混凝土 → 符文，随建筑等级科技切换。 |
| 仓鼠铁匠铺 | 3 | 铁匠铺 → 中世纪兵工厂 → 现代机械工厂。 |
| 市政大厅 | 3 | 古典议事厅 → 自治市政厅 → 现代市政中心。 |
| 仓鼠草屋 | 3 | 仓鼠草屋 → 斥候营地 → 特战基地。 |
| 仓鼠军营 | 3 | 按编制科技切换建筑外观，最高为现代步兵军营。 |
| 教堂 | 3 | 教堂 → 主教议会 → 圣迹大教堂。 |
| 靶场 | 3 | 按靶场编制科技切换。 |
| 骑兵学院 | 3 | 按骑兵学院编制科技切换。 |
| 工程师营地 | 3 | 工程师营地 → 工程工坊 → 载具工厂。 |

募兵建筑的“外观换代”和“兵种槽位换代”是两个条件：外观按科技解锁，兵种整级替换还要求该级单位已实现；不因恢复按钮改变占位兵种或现役单位。

补查墙体、女墙、楼梯与四格城门详情：它们读取全局墙材质科技档位，详情提供修理/回收、门控等操作，没有独立的逐栋等级扩建按钮。普通等级城门与科技墙材质也不能混为一条付费升级链。

## 三、功能模块与共用显示修复

- 部分银行、矿工营地、研究设备、电站等经济模块在卡片内单独绑定科技门禁，出现“卡片在、单次按钮隐藏、持续按钮在”的同源问题。共用经济升级操作组新增显式的 `data-technology-gate-locked-mode="disable"`，组内原生按钮被科技锁定时保留显示并禁用。
- 该例外仅作用于明确标记的按钮操作组；没有改全局科技门禁默认行为。整张未解锁的项目卡、建造项及招募项仍按原规则隐藏，不能绕过科技。
- 单次按钮的业务禁用状态继续保留；解锁变化仍由现有面板刷新和 `buildingUpgradeControlsChanged()` 更新，不强行启用仍在读条的按钮。
- 普通出兵建筑/兵营的通用模块保留原有“升级 / 持续升级”操作组；它们是功能升级，不等于建筑外观换代。
- 防御塔使用独立的芯片/改造模块卡，源码中的 `+1（费用）` 单次按钮仍在，不属于本次缺失，不修改其接口或装备行为。

## 回头复查补修

- 发现一个源码可推导的时序遗漏：矿工营地首次打开时，未解锁按钮以 `disabled` 创建；如果科技在第一次控件轮询前完成，`TechnologyGate` 会恢复创建时的禁用状态，而首次轮询因没有前态只记录“已解锁”，不触发重绘。科技系统主动刷新的是生产建筑面板，不包括独立矿工营地面板，因此此时按钮可能持续禁用，直到另一次面板重绘。
- 已在矿工营地卡片渲染、科技绑定完成后强制记录一次控件状态，后续每秒轮询可识别上述解锁变化并重绘；保留真实读条的禁用状态，不通过强制启用按钮绕过业务限制。普通调用仍按原频率轮询，没有新增定时器或科技监听。
- 本次回看还核对了仓库独立面板分支、仓库/研究所的单次回调与满级占位、操作组的门禁作用范围。除上述已补修问题外，未在本轮相关差异中发现新的确定性问题；不等于运行时验收通过。
- 仍未运行测试或运行时验证。用户验收可补看“打开矿工营地后立即完成相关科技，单次按钮在下一次控件刷新后恢复”的场景。
