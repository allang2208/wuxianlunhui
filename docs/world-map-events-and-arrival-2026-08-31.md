## 动态记录

世界面板新增“动态”页签，角标显示未读数。保留最近40条，按最近发生顺序展示；可查看详情、定位事发地格、逐条或全部标为已读。查看和定位不下达行军命令，不自动抢走地图视角。

记录覆盖：抵达目标格、路线阻断、基地入营取消、追击目标消失、解围目标结束、遭遇战、战场加载失败、返回地图失败、战斗结果、入营加载/失败/成功、围城开始/结束及界面操作被拒绝。重复的调度轮询不反复写入同一条停止事件；战场返回多次失败保留同一个失败事件，成功后更新其说明。

入营的载入、失败或完成更新同一条接收记录。其他战事以战略调度节拍观察，不为每条事件创建实体场景。首次恢复以当前战事为基线，不把旧档已有围城重新报为新战事；“战事结束”不宣称守城胜利，实际归属仍需查看基地。

事件和已读状态进入原 `worlds.strategy` 保存路径，保留战略存档v3，新增可选 `events/nextEventId`；旧档无事件时为空列表。不解除战斗、加载和忙碌时禁止存读档的规则。

事件历史不替代顶部通知。瞬时提示仍走 `SceneManager.showTopNotification` 的共享FIFO，未新增顶部播放队列、模态弹窗或音效。

## 入营接收清单

流程仍是：到达有效信标格 → 原场景加载 → 加载成功后迁移账本 → 收起兵棋并在基地待命。动画和历史记录不延迟或触发结算。

成功通知包含实际接收摘要；按O打开地图时，若有未读接收记录且没有指定要查看的位面，默认打开“动态”并展示该清单。

| 清单字段 | 含义 |
|---|---|
| 本次士兵 | 交接前本次军团幸存士兵记录数量 |
| 已登记 | 实际进入目标基地兵线账本的本次士兵数 |
| 已落地 | 本次入营物化调用中实际完成的本批士兵数 |
| 等待落地 | 本次交接后仍留在目标基地队列的本批士兵数 |
| 伤员 | 已登记士兵中血量比例不足1的数量，包括等待落地者 |
| 归队队友 | 沿既有队友驻留入口处理后仍存活、活动且不再归属于战略军团的队友数 |
| 记录待核对 | 原清单数量未能归入已落地或等待落地的差额，若出现则单独警告，不冒充成功人数 |

这些是**接收时的历史快照**，不是基地当前兵力。之后的物化重试、阵亡或调动不改写历史；也不能通过查看记录重复生成士兵。

兵线原有压缩批次可能把返营士兵与旧驻军合并。此次只记录新追加的批次区间，通过原物化回调和实际保留区间计数，排除旧驻军、其他增援和已物化前缀。没有更改批次合并、物化预算、安全落点、人口来源或重试规则。

加载失败仍保留原军团与携军账本，动态详情提供“重新下达入营”。点击时重新检查当前军团ID、所在格、是否仍在途中、战斗/加载状态、目标基地世代及战事。旧记录不能把已经离开的军团传回，重建后的新基地必须重新选择。主神空间重试沿原撤回资格；已完成记录没有重试入口。

## 兵棋状态和绘制

- 保留正式军旗图集、55°相机与脚点。移动时绕脚点小幅轻摆，幅度0.012弧度、周期1600ms；真实位置仍来自原世界时钟和路段，不写入逻辑占格。
- 接战/围城使用交叉剑和红色地面圈；受阻/战败使用静态禁止标识；普通抵达显示1600ms地面反馈，只有实际入营阶段才使用基地入口徽记。
- 将兵旗、路线、当前路段和状态标记画到独立透明Canvas；行军中的可见动态层最多按50ms调度一次重绘，地貌/城市层仍在地图数据或视角变化时重绘。
- 暂停世界时钟时显示动画不推进；页面隐藏、减少动态效果或没有活动状态时停止动画计时。关闭地图释放计时器、RAF、监听、图片引用与透明层。
- 原左键、右键、拖动、缩放与光标热点不变。状态徽记属于对应兵旗的点击范围，装饰层不拦截鼠标。窄屏四个页签排成两行，沿用原输入与焦点限制。
- 新增一张与地图同分辨率的透明画布，按原400万像素上限最多增加约16MB基础RGBA缓冲；不等同于实际GPU内存测量。动画调度20次/秒是实现目标，不是实测帧率。

## 用户重点验收

1. 行军抵达、路径受阻、目标消失后查看动态，每次状态变化只有对应记录；保存/读取后历史与已读状态保留。
2. 同时存在多城围攻时，各城市记录和定位独立；结束提醒不把失守误报为胜利。
3. 带伤兵返营，核对本次人数、已落地、待落地和伤员；基地已有待落地士兵时不能算进本次清单。落点不足者应继续沿原队列恢复。
4. 入营失败后重试；同时确认军团移动离开、基地重建、基地被围攻或军团已经归队时，旧记录不能重复入营。
5. 行军中改令或停止、拖拽缩放、点击兵旗徽记，确认显示位置与逻辑格不互相影响，鼠标不穿透到游戏。
6. 重复开关地图、最小化、暂停及减少动态效果，确认没有残影、持续动画或错误计时；在实际分辨率下确认新层性能和页签可读性。
