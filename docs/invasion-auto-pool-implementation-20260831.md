# 位面入侵自动入池实施说明

本轮已实现代码与配置，后续在 2026-09-05 的共享工作区整理中补齐遗漏的怪物登记、入侵分类和召唤账本接线。未运行测试、构建、游戏、浏览器探针或素材预算验证；按约定由用户测试。未同步 EXE。设计依据为 `invasion-auto-pool-plan-20260831.md`，本文记录实际落地边界。

## 使用与分类

大地图“敌方军团”区域新增“入侵类别目录”。当前可查看65条现有配置在26个系列/专用类别中的归属、阶级、最早天数、分类依据、不能成军的原因及已经读取到的资源预算。目录不预加载图鉴图片，也不显示未侦察军团的位置、阵容或抵达时间。

分类真源放在每个怪物自己的 `data/enemy-config.json` 的 `invasion` 中，并同步到公开镜像。`data/invasion-campaign.json` 只保存26类系列规则和编队参数，已移除固定的普通/精锐/首领ID名单。原 `family/families`、地牢 `poolWhitelistOnly`/`noPool` 及现有配波语义不变。

角色齐全或明确允许同种强化精锐的候选系列：狼族、蛇族、熊族、腐沼甲虫、矿工亡灵、矿晶融合体、尸变亡灵、腐蝇蛆群。它们仍需在实际集结时通过进度、构造器、整图纹理和威胁预算，不代表八组已经全部通过素材或运行时验收。

其余成员已归档并显示原因：缺少普通兵/精锐/首领、固定守点、专属事件或仅伴生设施。紫蚀古树和集合体不再进入新的主动入侵；深脉之母归矿晶融合体，钻虫独立归档等待同系列首领。已有存档军团不按新分类换兵。

## 自动接入规则

优先级为：明确系列 → 显式 `invasion.inherits` 继承 → 具体谱系标签唯一匹配。继承失效、循环、未知系列或标签冲突均不自动放行。标签只使用系列规则中的具体词，不以“自然/动物/僵尸”等大标签决定军团。

缺少标签时返回最多3项建议及评分依据，只作提示，不批准入池。当前建议评分采用具体标签5分、名称/非数值描述合计最多4分，剔除“数值参考/基准/接近”等比较语句；未采用方案中尚缺可靠来源的生态/目录加分，也不把分数当成概率。未接入模型、向量库或网络分类服务。

新怪物在完成正常的配置、动画与实体模块开发后，导出其类，并在自身配置登记一次：

```json
{
  "entityClass": "FrostWolfEnemy",
  "rank": "elite",
  "invasion": {
    "series": "wolf_pack",
    "mode": "assault",
    "enabled": true,
    "assaultReady": true,
    "mechanics": "control",
    "threatScale": 1.2,
    "minDay": 15,
    "weight": 1
  }
}
```

这是接入字段示例，不是新增怪物内容。重新读取配置后，符合条件者参与未来军团抽取，不需要再编辑入侵名单。`assaultReady` 是内容接入者对攻城目标/移动/记录能力的明确声明，不等于运行时测试已通过。新技能、固定单位改移动单位、全新召唤脚本仍需相应适配；不能只填一个字段就宣称新怪物开发完成。

基础工厂由 `entityClass` 在 `enemy-types.js` 的导出中解析。防守和战略拦截共用注册入口；地牢保留原有特殊工厂，未单列的新类型走统一工厂兜底。集合体沿原专属Boss入口，使用 `dungeonAutoFactory:false` 保持它原先不在通用地牢工厂表中的边界。需要注入子单位工厂时用 `entityBindings`（如巫师的 `_createZombieDog`），召唤目标登记在 `invasion.summons`，必要的图像依赖登记在 `visualDependencies`。原工头地牢矿洞装饰不会因此带入入侵。

## 编队、强度与资源

- 先按符合目标位面的系列抽取，再从该系列分别选择一种首领、一种精锐和一种普通怪。系列成员越多，不会因此自动增大整个系列的总权重；重复上次系列的权重减半。
- 角色默认由rank推导，领主/Boss均占唯一首领槽。已完成攻城适配的精英可在自身声明中显式写`invasion.role:"leader"`，只改变位面入侵编队职责，不改变地牢/图鉴rank；如果该系列没有另一只精锐，必须同时允许普通怪承担强化精锐。普通阶级不得越级声明领队，不降级Boss、不跨系列补兵。
- 成军前按基础生命、物理/魔法输出摘要、射程/速度、机制档位和显式倍率计算入侵威胁；逐步减少普通兵或精锐直到满足预算，达不到至少8普通＋2精锐＋1首领就换候选。此估算未校准，不是精确战斗模拟。
- 直接兵力仍不超过55，每批不超过12。主编队不超过3种，含必需召唤/伴生类型合计不超过4种；全军额外召唤默认4只。数量上限不是每次必须填满的数量。
- 入侵自身的纹理依赖并集默认不超过256MiB；普通/精锐/首领还分别检查64/128/256MiB的用途准入线。所有动作、变身及已声明依赖按实际整图尺寸和纹理键计费，不能用PNG压缩大小或有效帧面积替代。预算规则不自动批准超标例外。
- 游戏集结时只为正在尝试的候选读取已登记PNG头，串行读取、缓存尺寸、不解码上传候选图片；服务器忽略Range时读取头部后取消流。尺寸读取超时或协议/登记失败会记录原因，不按0成本放行。未被尝试的条目显示“资源预算在集结选型时读取”。
- 该256MiB限制只覆盖入侵敌人管理范围，不代表场景总显存、CPU寻路或帧率已达到目标。原资源管理器继续管理友军、建筑、尸体与切场重叠。固定测试协议和Vite的冷读取表现待用户验收；不支持尺寸读取的资源协议会阻止相关候选集结，不静默绕过限制。

## 召唤、阶段和存档

同一军团、跨全部波次共享一个 `summonLedger`，记录额度、累计消耗、允许的子类型和唯一编号。已接入甲虫路径及通用召唤助手；巫师、蝇手、巫婆按明确类型接入。纯召唤的巫师/甲虫在无额度时不启动召唤动作；蝇手的攻击仍可结算，但额外补兵受额度限制。其他非入侵模式不启用这套账本。

召唤物继承入侵/防守标记并进入清场、战损和存档记录；复活/撤退/切场不重领额度。伴生煮锅的已尝试生成状态保存，恢复巫婆时不重复补锅。尚未开放入侵的蟾祖等专属脚本没有借本轮扩大开放范围。

红狼/熊德鲁伊的变身完成或进行中状态、甲虫展开阶段、支护梁巨尸的断梁/耐久状态随入侵记录保存。恢复先设置影响体型的阶段，再找落点，最后恢复实际血量和攻击；不重放变身治疗。临时目标、攻击伤害盒不跨场景保存。其他怪物的新阶段机制仍需要专门接入。

入侵存档升为版本6：持久化选型种子、待集结方案、上次系列、规则版本和共享召唤账本。资源读取回调只提交待集结方案，真正派军仍在正常游戏更新中进行；旧读档/重置后的异步回调不能发兵。已选阵容的待集结方案和已出发军团均不重抽；尚未选成的方案可随游戏天数增加开放候选。

既有一天行军、侦察预警、途中拦截、基地世代校验和战损交接继续沿原入口。后台仍按原摘要近似结算，不逐个模拟技能或召唤。

## 用户重点验收

1. 打开类别目录，确认条目、缺角色/固定/专属事件原因，以及未侦察军团仍不可见。
2. 首次集结的资源冷读取、失败重试与正常发兵；出现不集结时可从 `WorldInvasionSystem.getInvasionCatalog().lastMusterIssue` 查看具体原因。
3. 新登记的同族精锐不改入侵名单即可进入候选；无工厂、未完成适配或未知系列不会混入。
4. 集结期间存读档、等待异步结束、暂停后恢复，不重复发兵；已出发军团不因新怪入库换阵容。
5. 拦截撤退、解围撤退、前后台切换后，伤势、变身、断梁、召唤消耗和幸存子单位仍正确。
6. 不同家族的实际难度、首领技能对基地目标的效果，以及额外4只召唤/纹理上限是否达到预期。

本轮仅查看实际改动和实现所必需的局部调用契约，未做正式代码审计或运行时验证；真实资源准入结果、界面布局、跨场战斗行为和性能仍待用户测试。
