# 玩家副手持盾：先伸后举、三段攻击与冲刺同步

## 本次修改

右键防御改成**手臂先向面朝方向外伸，再抬盾**。攻击1/2/3、冲刺攻击、冲刺突击及各自收势改为读取正在显示的身体源帧，以该帧副手掌心作为盾牌握点，不再固定挂在身体某个比例位置。

本轮只改显示。原有攻击动作、主手武器轨迹、伤害、弹反窗口、格挡耗体力、输入锁、连段顺序、攻击与收势时长均未调整；两款优质盾的美术候选也没有在本轮注册进游戏。

## 防御动作

| 阶段 | 持续时间 | 上臂相对源图角度 | 前臂相对源图角度 |
|---|---:|---:|---:|
| 起点 | 0ms | 0° | 0° |
| 先外伸 | 前80ms | 0° → −16° | 0° → −24° |
| 再抬盾 | 后120ms | −16° → −20° | −24° → −105° |
| 松开收回 | 180ms | 沿上述路径反向 | 先下落，再回收 |

原上臂+25°使右向源图先向身体内侧旋转。本次改用向外的负角，保持肩关节位置和上下臂骨长不变。每阶段采用平滑起落，盾面在抬起阶段才由原休息倾角转入防御倾角；左右通过身体朝向统一镜像。快速松开/重按直接反向推进同一个进度，不创建重复Tween。

2026-08-31按“前伸太多”的实机反馈微调：外伸角由−22°/−30°收为−16°/−24°；举稳角由−32°/−98°改为−20°/−105°，上臂收近、前臂增加屈肘。按当前关节配置计算，右向idle举稳掌位约从源图(430,140)收至(412,139)，主要收回水平距离，抬盾高度基本不变；这是配置几何说明，不是本轮运行时测量。左右镜像及手枪副臂共用调整，举盾/收盾时长、肩点、臂长、盾握点、攻击挂点和战斗数值均不变。

盾牌位置仍由显示前臂的实际掌心变换给出，没有另加一个盾牌专用世界偏移。手枪副臂仍接在躯干真实肩点，主握枪臂、枪握点和瞄准旋转保持原样。暂停或石化不推进举盾进度。

200ms仅是显示过渡；格挡和弹反仍由原战斗系统即时决定，不等待视觉抬盾完成。

## 攻击源帧标定

直接读取现有PNG，按各自动画配置的帧格查看上半身与两手，以现有主手握柄轨迹辅助排除持剑手。三段攻击及所有收势为512×512，两种冲刺攻击为512×516。没有生成替代动作、覆盖PNG、修改帧数或拉直已经认可的手臂摆动。

| 动作 | 现有源文件 | 本轮挂点 |
|---|---|---:|
| 攻击1 | `assets/player/attack_sword.png` | 12帧 |
| 攻击2 | `assets/player/attack_sword_2.png` | 12帧 |
| 攻击3 | `assets/player/attack_sword_3.png` | 16帧 |
| 收势 | `assets/player/recover_sheet.png` | 13帧 |
| 冲刺攻击 | `assets/player/dash_attack.png` | 17帧（追加） |
| 冲刺攻击收势 | `assets/player/dash_recover.png` | 14帧（追加） |
| 冲刺突击 | `assets/player/dash_attack_thrust.png` | 15帧（追加） |
| 冲刺突击收势 | `assets/player/dash_recover_thrust.png` | 14帧（追加） |

数据位于 `src/config/player-shield-poses.js`，原53帧保持不变，追加冲刺及收势60帧，合计113帧。每个源帧记录掌X、掌Y、盾面倾角和前后层。可见掌心为人工图内标定；被肋骨、主臂或髋部遮住的掌心只能按同一副臂的肘腕末端推定，**不宣称这些遮挡帧已自动检测或实机精确验收**。

同步规则：

- 读取 `playerSprite.texture.key` 和 `playerSprite.frame.name`，不使用连段编号猜当前动作，也不以墙钟或武器Tween百分比另跑一条轨迹。
- 一帧对应一个挂点；不在两个离散身体姿势间插值掌位。攻击3原有100ms帧、命中停顿和变速均直接沿当前身体帧生效。
- 末帧定格及石化时即使 `anims.isPlaying=false`，仍跟住实际显示的纹理帧；切回idle后不会误读残留的 `currentAnim`。
- 挂点使用身体当前的origin、displayWidth/Height、flipX、rotation及位置，包含攻击的1.0956显示倍率、源图内前移和地面高度偏移。
- 身后回摆/遮挡帧使用身体深度−0.01；其余帧沿现有盾牌前层偏移，继续服从建筑与墙垛仲裁。墙后透视副本也读取同一个前后层标记，不会重新把身后盾画到胸前。
- 普通攻击收势读取自己的13个源帧；两种冲刺收势分别读取各自14帧。动作切换沿用原人物素材，不另外用盾牌平滑轨迹掩盖身体姿势切换。
- 未配置的其他动作继续使用已有回退；本轮没有扩大到普通步行、奔跑或其余特殊攻击的全面逐帧标定。

## 冲刺追加范围

- 通用冲刺17帧：副手从身前屈肘逐渐摆到身后，0基第8～16帧使用身体后层；第9帧掌心被髋部遮住，只能从腕末端推定。没有使用历史脚本里已废弃的 `DASH_HAND_PX_LEGACY`，也没有改已验收的主剑30点轨迹。
- 通用冲刺停顿：现有动画仲裁会把身体切到 `player_dash_recover` 第0帧，盾牌同步读取收势第0帧，不固守攻击第16帧。收势前10帧随副手经过髋后，随后回到idle副手侧；两只手靠近时不追踪更大的主手掌。
- 骑士长剑突击15帧：原片为双手接近重叠的前伸动作，沿内侧副掌与腕部标定，没有复制最前端剑柄坐标。重叠时不能从单张图独立分割两掌，这部分保留人工推定；本次没有重画双手姿势。专属收势14帧跟随分开后的外侧副手回落。
- 帧格尺寸由挂点表显式记录。攻击使用516高、收势使用512高，继续通过现有rig尺寸守卫与origin/缩放换算，不会因帧高不匹配退回固定挂点。
- 只追加显示数据与尺寸参数。冲刺方向、位移/停步、定格与收势时长、突击三段判定、技能快照、输入锁、伤害/体力/经验和主手贝塞尔收势均未调整。

## 交付范围与人工验收

已读取源图、局部调用链及本次修改；**未运行测试或运行时验证，按约定由用户测试**。没有启动/重启开发服务器、调用游戏播放、浏览器探针、构建或同步EXE。源图标定不等于游戏内验收通过。

请重点确认：

1. 左右朝向的待机右键：先送手，再抬盾；松开先落盾再收手；快速松按不跳回起点。
2. 连续攻击1→2→3：副手在胸前、向前伸、向后甩时盾脐都随该手，尤其攻击2第8～11帧与攻击3第9～11帧的身后层。
3. 第1/2段末帧停留、命中停顿、收势回idle；不应出现手停住而盾独自滑动。收势首帧与攻击末帧的姿态差异保留原素材，需要实机观察衔接观感。
4. 单持手枪右键及边走边举盾、卸盾/换组/死亡/闪避/施法、石化恢复、墙前墙后和城墙顶遮挡。普通走跑的旧回退仍是已知限制。
5. 通用冲刺左右朝向：身前屈肘→髋后回摆→定格→收势。特别查看攻击第8～9帧、收势第8～10帧的遮挡与两手交叠，确保盾跟副手而非髋关节；攻击末帧与收势首帧的原素材姿态差仍需观察。
6. 骑士长剑冲刺突击：起手、前伸/末帧停留、专用收势与回idle；双手重叠时的握持观感需实机确认。暂停/石化或命中停顿时盾不应自行继续移动。
