## 确定缺陷

### A01 · P2 · 弹反结果跨攻击残留，后续命中效果被错误跳过

**影响：共享伤害管线及读取 `_lastParried` 的近期怪物。** 例如狼人王飞扑、矿洞领主的控制/击退、深脉之母落点冲击，以及依赖确认命中回调的效果。

- `src/entities/components/shield-system.js:20` 的 `exitDefense()` 只清除防御开关；`onDamageTaken():32` 才把 `_lastParried` 重置为false，成功弹反再设true。
- `src/entities/player/subsystems.js:153` 仅在正在持盾防御时调用 `onDamageTaken()`。成功弹反后松盾，下一次受击不经过重置入口。
- `src/combat/damage-pipeline.js:82` 在新的 `takeDamage()` 返回后仍读旧标记，并据此跳过确认命中及后续效果。个体代码也直接读此标记，例如 `src/entities/enemy-types/deep-vein-mother.js:313`。

**触发条件：** 玩家弹反一次 → 松盾 → 再被攻击。后续伤害可以正常扣血，但部分附加效果被当成已弹反而跳过，直到再次走盾牌受击入口。并非注释所说的“每帧重置”。

**修复方向：** 将弹反结果限定到本次伤害调用，优先明确返回本次结算结果；至少在每次受击入口重置，避免依赖持久字段代表当前命中。不能只在单个怪物处绕开弹反检查。

### A02 · P2 · 三种怪物在死亡动画结束前被移出逻辑更新

**影响：支护梁巨尸、断索狱监、黑肺提灯长。**

| 怪物 | 死亡动画 | 尸体停留 / 淡出 | 现有逻辑删除时限 |
| --- | ---: | ---: | ---: |
| 支护梁巨尸 | 5083ms | 1000 / 300ms | 默认3000ms |
| 断索狱监 | 3417ms | 1400 / 300ms | 默认3000ms |
| 黑肺提灯长 | 3417ms | 1600 / 300ms | 默认3000ms |

- `support-beam-brute.js:283`、`broken-cable-gaoler.js:423`、`black-lung-lamp-keeper.js:388` 设置了死亡计时器，却未设置 `_deathRemoveDelay`。
- `src/entities/damageable-entity.js:461` 为其补上默认3秒；`src/game.js:1615` 按 `Date.now()` 到期直接删除实体，没有等待 `_preserveCorpse` 的三段计时结束。
- 删除实体后，其 `_updateDeathSequence()` 不再运行。Phaser自主死亡动画是否继续由渲染对象状态决定，但自管帧、停尸和淡出清理已经失去驱动；可出现动画中断、末帧/尸体残留，不能简单理解为“正常淡出”。Sprite所在分组通常到离开战斗的 `GameScene.clearCombatView():10214` 才统一清理。

**修复方向：** 以游戏内死亡时间轴结束作为删除条件，沿用封井岩魇/深脉之母的保留到完成机制，明确释放Sprite与特效。不要仅把3秒改成另一个全局常量。

**关联风险：** 其他采用“总时长+余量”的有限 `_deathRemoveDelay` 尸体仍混用了真实时间与游戏dt；暂停/后台后也可能先到删除时限。统一生命周期修复时应一并处理，不能把这部分算作已通过。

### A03 · P2 · 石化中死亡仍被渲染层拦在生前贴图

**影响：19种中的17种；封井岩魇、深脉之母已有主动清理，除外。**

- `src/phaser/scenes/GameScene.js:13374` 只要实体仍有 `petrified` 就直接退出动画同步，没有排除死亡实体。因此不会执行后面的死亡纹理切换/手动帧写入。
- `src/entities/damageable-entity.js:360` 的通用死亡入口不清除石化状态；这些怪物死亡后只推进自己的死亡计时，不再正常更新状态持续时间。
- `GameScene._syncPetrifyEffects():8344` / `8400` 会移除死亡者的灰色效果记录，但不会移除实体上的状态，故不能解除上面的拦截。`repairSpriteFrame()` 也只修复损坏帧，不会替正常生前纹理主动切死亡图。
- 相比之下，`sealed-shaft-rock-wraith.js:523`、`deep-vein-mother.js:379` 在死亡时显式清理石化/冻结状态。

**触发条件：** 石化持续期间被伤害杀死。逻辑已死亡，画面却可继续停在生前姿态或恢复生前旧动画，随后被尸体清理带走。

**修复方向：** 死亡切换优先于活体石化定格，清除死亡不应继承的控制视觉/状态；保留活体石化期间不乱跳帧的既有契约。

### A04 · P2 · 狼人王与封井岩魇的特殊位移绕过束缚

- `src/systems/movement-system.js:240` 明确规定束缚禁止移动，但只能阻止该系统负责的常规移动。
- 狼人王 `_canStartPounce():3919`、`_updatePounce():3959` 未检查bind，`enemy-types.js:3999` 直接解析墙体后写入自身坐标。
- 封井岩魇 `_isActionControlled():499` 不含bind；`sealed-shaft-rock-wraith.js:257` 的旋冲运动也直接写坐标，未检查bind。
- 独角仙王已在起手和冲锋期间分别处理bind（`enemy-types.js:4559`、`4430`），因此同一状态在这些单位上行为不一致。

**触发条件：** 束缚期间启动飞扑/旋冲，或技能运动中被束缚。常规追击停止，特殊技能却仍能移动。

**修复方向：** 在这两种位移自己的入口/运动阶段处理bind，禁止起步或进入原地收势；不要把bind全局改成眩晕，从而错误禁用所有原地攻击。

### A05 · P2 · 岩芯钻虫把寻找安全落点失败当成成功

- `src/entities/enemy-types/core-drill-worm.js:274` 调用 `WallSystem.findSafeSpawn()`，只检查返回坐标是不是有限数值。
- `src/world/wall-system.js:2363` 最多尝试若干位置，失败后仍返回原始 `{x,y}`，不保证位置可通行。
- `core-drill-worm.js:300` 出土时无条件写入该坐标，未进行最终 `canMoveTo()` 判断，也未复查隐藏期间发生的障碍变化。

**触发条件：** 预判落点及所有候选位置被墙体/地形阻挡，或预警后落点变为不可通行。钻虫会被放到非法位置，可能卡墙或与障碍重叠。

**修复方向：** 必须验证最终落点；无可用落点时回到确认安全的原位置或取消出土攻击。保留“钻地能绕过障碍”的机制，只要求落点合法。

### A06 · P2 · 黑肺提灯长镐击切换存在约27px的一帧脚点跳动

- `black-lung-lamp-keeper.js:425` 的 `_getPhaserOptions()` 才按当前动作写 `footOffsetY`；开始/结束动作只先改 `_animState`，没有同步脚点。
- `src/phaser/scenes/GameScene.js:3378` 先读取旧脚点定位Sprite，随后 `3391` 才调用 `_syncEnemyAnimation()`，计算新脚点并切换贴图。本帧位置未再按新脚点重算。
- 当前配置：待机/行走为544px高、footY=503；镐击为640px高、footY=599；主体都按 `260/460` 缩放。对应脚点偏移约130.57px与157.70px，差约27.13px。

**触发条件：** 进入或退出镐击的首个渲染帧；逻辑/碰撞体没移动，贴图定位却采用旧动作脚点。

**修复方向：** 动作状态改变时立即同步视觉尺寸与脚点，或让渲染先取新动作选项再统一定位。无需逐帧重新缩放主体、重生素材或改变碰撞大小。

### A07 · P2 · 独角仙王控制中断漏清红色预警替身

- `src/entities/enemy-types.js:4250` 覆盖 `_onCombatActionInterruptedByControl()`，没有调用父类清理；在 `4276` 仅清零预警计时和回调。
- `src/entities/enemy.js:620` 的父类入口会调用 `_clearAttackTelegraph()`，后者才真正销毁 `_telegraphGlow`。
- 计时被直接清零后，`_updateAttackTelegraph():541` 直接返回，无法再补做销毁。`_cancelActionsForStun()` 和idle复位也没有补上这个释放步骤。

**触发条件：** 红色预警可见时遭眩晕、冻结或石化。已取消攻击的红色旧姿态可留在原地，直到后续预警正常结束或精灵被销毁。

**修复方向：** 子类完成特殊状态快照后仍履行父类的公共清理职责；石化定格只保留主体，不保留已取消攻击的红色替身。

### A08 · P2 · 独角仙王召唤落点不检查活体占据

- `src/entities/enemy-types.js:4858` 只取两侧固定位置，再用 `findSafeSpawn()` / `canMoveTo()` 检查墙体。
- 随后直接创建并插入幼虫，没有检查玩家、友军、已有怪物/召唤物占据的足底范围。
- 同文件 `RotTideToadAncestor._findToadSummonPoint():5419` 已有候选实体、透视尺度下的占据判断和多候选落点，可作为现成契约参考。

**触发条件：** 玩家或单位位于固定召唤点；连续召唤或墙体搜索又把多只幼虫引导到同一位置。结果是重叠出生、挤出或贴身突袭，而非清楚的召唤站位。

**修复方向：** 召唤前检查活体占据并改找其他合法落点，找不到时减少本次生成数量；每只成功插入后应立即参与后续占据判断。

### A09 · P2 · 蟾祖缺少幼虫视觉依赖，冷资源状态下先生成后补图

- `data/enemy-config.json:7368` 的蟾祖配置会召唤 `smallRotbogRhinocerosBeetle`，但没有 `visualDependencies`；独角仙王已有这条依赖（同文件 `7231`）。
- `src/phaser/assets/runtime-asset-manager.js:682` 明确只展开 `visualDependencies`，不会把任意 `summonType` 当成资源依赖。
- `src/entities/enemy-types.js:5389` 的蟾祖释放逻辑直接创建幼虫，没有像独角仙王那样先确认整套资源就绪。
- `GameScene.getOrCreateEnemySprite():13325` 在目标纹理未就绪时回退 `enemy_circle`，随后异步请求。

**触发条件：** 单独预览/加载蟾祖，或进入当前未驻留幼虫资源的战斗。第一批幼虫可以先以占位图参与逻辑，后续才换成正式贴图；同时出现幼虫的普通波次可能掩盖此问题。

**修复方向：** 补齐显式依赖闭包，让蟾祖加载/驻留覆盖幼虫全部动作；释放前仍处理加载失败，不把异步资源回调当成补发召唤入口。

### A10 · P2 · 深脉之母喷矿对结构目标的遮挡规则前后不一致

- `deep-vein-mother.js:141` 通过 `_wallBlocked()` / `hasAttackLineOfSight()` 选择目标，支持只豁免目标自身墙段/矩形。
- `src/combat/melee-reach.js:5` 实现了 `_coverSeg`、`_gateSeg`、`_wallRect` 的目标自身豁免，同时保留中间其他墙体遮挡。
- 但 `deep-vein-mother.js:282` 在炮弹落地前直接调用没有ignore参数的 `WallSystem.blocked()`；只要这条线进入目标自身墙体/矩形，就直接丢弃整次爆炸，连后面的合法目标LOS判断都进不去。

**触发条件：** 喷矿对准自身就是遮挡物的可攻击结构，尤其落点位于目标 `_wallRect` 内时。可以正常起手、飞到落点，却被目标自身当墙消掉。

**修复方向：** 在保持起手锁定落点的前提下，保留需要的目标/表面上下文，统一“仅豁免被攻击结构自身”的遮挡规则；不能简单删除遮挡检查，否则会恢复隔墙空降伤害。

## 风险与尚不能下结论的部分

### R01 · 纹理预算与设备兼容

以下数字来自实际PNG宽高的 `width × height × 4`，计入尾格空白；是本体配置纹理的RGBA基础解码量，不是PNG磁盘大小，也不是实测VRAM。不包含渲染目标、驱动开销、临时副本或召唤依赖；重复实例通常共享这些纹理，不能按怪物只数直接倍乘。

| 怪物 | 本体整套约MiB | 最大动作表举例 |
| --- | ---: | --- |
| 岩芯钻虫 | 655.0 | 研磨8192×5120，160MiB |
| 狼人王 | 645.9 | 飞扑8064×5760，177.2MiB |
| 腐潮蟾祖 | 604.2 | 扑压7168×4032，110.3MiB |
| 支护梁巨尸 | 570.0 | 持梁攻击8192×5120，160MiB |
| 断索狱监 | 432.6 | 囚笼6144×5120，120MiB |
| 沼泽吸血大蚊 | 168.8 | 攻击6400×3840，93.8MiB |

`data/performance-config.json:20` 受管理纹理软预算为640MiB。`RuntimeAssetManager._evictUnusedAssets():1439` 明确保留活体/预览/地牢正在使用的资源族，因此单套超过预算时，清理闲置资源也无法使其满足预算。同场多种怪物、建筑、友军和尸体交叠只会增加压力。新第16卷的目标/准入线更低，但不应擅自重采样已批准素材来强行达标。

这些大于4096px的纹理还需要目标设备最大纹理尺寸的依据；本轮未读取GPU能力，不能说用户设备一定加载失败。建议后续单独做保留源视频与主体比例的资产预算优化，先裁除透明浪费/重排，再选择画质档；分页本身不会减少总显存。

### R02 · 独角仙王召唤中资源失效后没有有限退出

`enemy-types.js:4821` 在资源未就绪时每帧把召唤计时退回释放点；`_ensureBroodVisuals():4765` 可以不断重试，却没有累计等待上限。正常依赖预热/驻留已大幅降低发生概率，但若召唤已经开始后发生资源损坏、上下文恢复或持续加载失败，单位可一直处于施法锁定，直到外部控制/死亡中断。建议失败达到有限时长后取消本次召唤并正常恢复AI，不异步补发。未模拟故障，不将其描述成日常必现。

### R03 · 动画画面、音频和手感仍有验收缺口

- RGBA格式和帧格合法不证明蚊子黑底已完全清理，也不证明每帧主体大小一致。此次没有逐帧查看102段动作，没有播放GIF/视频，没有做黑底/浅底合成对照；透明边缘、循环接缝、长武器边缘淡出、镜像、粒子挂点需另行视觉验收。
- 当前19种配置中，狼人王有成套动作声音接线，其余未配置同类专属声音。无专属声音不等于完全静音，仍有共享受击/死亡声；也不自动判定为Bug。狼人王移动循环1333ms与32帧/24fps约一致，但没有试听，不能保证背景声、音量和新攻击节奏下的音画接触点。
