# RTS 士兵导航优化方案

> 发布状态：本文记录共享开发区的完整导航方案/实现；2026-08-30仅独立近战遮挡与紧凑方阵已纳入发布提交。完整导航因未入库的驻守/墙体移动接口依赖暂缓，详见[rts-publication-2026-08-30.md](rts-publication-2026-08-30.md)。

状态：核心代码已实现，等待用户实机验收。2026-08-30。第1–9节保留原方案与验收矩阵；第10节记录实际实现与取舍，不是运行时验收结果。

## 1. 目标与范围

解决三个主要问题：没有有效路径仍顶墙；隔墙近目标漏掉远处绕行；楼梯按直线距离选择而非实际可达路程。保持整队响应与帧时间稳定。

首轮覆盖士兵/侍从的显式移动、移动攻击/巡逻中的移动段，以及到楼梯入口的地面接近段。复用 PathManager、PathFinder、PathWorkScheduler、HierarchicalRoutePlanner 与现有高架系统。玩家独立控制器、手动移动和原同步调用接口保持兼容；不借机改变敌军索敌、攻击、伤害、技能位移或后台战争结算。

路线质量目标：局部 A* 在当前导航网格和成本定义内择优；大地图/跨层采用完整可达、代价较低且稳定的路线。40px离散网格、门户压缩和动态队列不支持承诺连续空间中的绝对最短路线。优先保证能绕过去，其次优化路程与等待时间。

## 2. 当前证据

- MovementSystem.update 无有效路径时落入普通朝目标移动；PathManager 虽记录 pending/reachable，移动执行没有完整消费这些状态。
- 800px 直线距离决定是否调用分层中继。局部 A* 使用有限搜索框；迭代耗尽会把 best-effort 路径作为普通数组返回。
- RegionIndex 的出口回退只选最靠近目标的连通区边界，墙边也满足边界定义，不能作为开放地图绕墙出口的证明。
- 现有分层导航以整个640px扇区为节点，每对扇区只取一个入口，未表达扇区内部被墙分割的多个连通区域；同扇区起终点直接退出分层规划。
- DefenseSystem.routeSurfaceMoveForUnit 对楼梯按欧氏距离和队列惩罚评分，没有预先比较到梯底的完整地面路线。
- 当前配置为：细寻路2.4ms、分层0.6ms、调度排空3ms；每帧最多2次重算尝试、5次验证尝试。驻守另有2ms软预算。以上是配置值，不是实测硬上限。

## 3. 第一阶段：统一路径结果与安全执行

在 PathManager 的指挥导航入口引入明确结果，不直接把所有 findPath 调用点从数组改成对象。保留旧同步调用的兼容入口；新的结果由指挥导航适配层消费。

| 结果 | 含义 | 单位行为 |
|---|---|---|
| pending | 排队、建图或跨帧搜索未完成 | 无合法前缀时停止主动推进；允许继续同一命令下仍合法的路线前缀 |
| complete | 已有连接真实终点的完整路线 | 跟随路径并按原到达容差完成 |
| partial | 尚未连接终点的搜索片段 | 不当作成功、不写入完整路径缓存；继续升级搜索 |
| search_limited | 达到整次搜索的资源上限，尚不能判定连通性 | 显示未能规划，停止盲走；有限退避或相关变化后重试 |
| unreachable | 已在当前导航图内证实不存在合法连接 | 结束该条移动并给出原因，按现有队列规则处理下一条 |
| cancelled | 改令、死亡、换场或请求被替代 | 丢弃结果，不回写旧目标 |

每次请求绑定命令代次、目标/表面身份、半径与通行权限、相关拓扑版本。改令清理旧派生路径和调度任务；异步完成只允许回写仍匹配的请求。语义目标与路线航点继续分开保存。

安全直走仍保留，但必须先通过完整当前位置→目标段的地面半径、墙体和建筑阻挡检查；不能只测终点合法或前方几像素无障碍。直线检查按请求/拓扑缓存，实际逐帧碰撞继续生效。它只是开阔地的快速路径，不替代低成本路线优化。

没有有效路径时制止主动加速并走原有制动/碰撞链，不能靠关闭碰撞或瞬移处理。击退、恐惧、既有技能位移和安全离梯保持原优先级。寻路等待不能触发随机脱困、判定到达或当成FIFO无进展。

安全前缀必须属于当前命令，并经过实际连线检查；“离目标最近的墙边”和未连接全局路线的 best-effort 不属于安全推进方案。预算不足不得进入不可达负缓存。

## 4. 第二阶段：局部 A* 失败后进入可靠的全局绕行

请求流程：完整直线检查 → 现有局部 A* → 局部搜索框耗尽/受限后升级分层规划 → 按门户路线计算细路径。

升级条件不再仅由直线距离决定。隔墙两点即使相距很近，只要局部无法连接，就允许寻找墙端、缺口、可通行门和外围通道。没有证明出口可达时，指挥移动不采用 RegionIndex 的最近边界回退；其他旧用途保持兼容。

### 分层导航的必要补强

1. 保留640px扇区与40px细格，按需读取本任务需要的扇区；每个扇区基础为16×16格，不在下令时同步重建全图。
2. 在扇区内标记真正连通的区域，节点身份变为“扇区＋连通分区”。起终点在同一扇区但不连通时，也能从扇区外绕回。
3. 从细网格的有效跨边连接构建门户，合并连续开口，保留多个分离通道；不再仅凭80px稀疏采样选择一个边界点。对角连接遵守同一禁止切角与线段阻挡规则。
4. 门户必须关联两侧连通分区；“能跨边界”不等于“该扇区内任意两个门户互通”。门户之间的实际局部路径和代价按需求取、缓存复用。
5. 从邻近扇区开始分批扩展，搜索可逐步覆盖场景内必要区域。每帧预算用尽只暂停；总搜索额度达到上限则返回 search_limited，不能伪装成全图不可达。
6. 找到完整的分层连接后，细化即将行走的几段。单位只能执行已经验证的前缀；后段失效时在安全位置暂停并修复，不退回直线硬冲。

缓存按半径桶、门通行权限/版本、连通分区和拓扑版本分开。正路径缓存保持现有有界LRU；只有实际证明断开的结果才能进入负缓存。拆墙、开门、建楼梯时让相关扇区及引用其版本的路线失效，避免远处变化清掉全队所有路线。

暂不全局缩小到20px网格。无法被40px网格表达的细窄通道要单独记录为精度限制，再按真实反馈决定是否只在门户附近局部细化；不通过减小单位半径伪造可达。

## 5. 第三阶段：楼梯按完整路线成本选择

楼梯候选先通过原有能力、有效承托、目标墙链与入口限制检查。地面单位上墙时比较：到梯底的真实地面路线、楼梯通行、墙顶到目标站位的路径，以及现有队列惩罚。

建议统一成本单位为估算时间：各段带地形权重的路径成本÷对应移动速度＋队列等待惩罚。首版队列惩罚可沿用已有参数并换算单位，不新增逐帧交通模拟。只有完整可达候选才能被选定；直线距离仅作便宜的排序下界。

候选求解复用同一起始连通分区的一次多目标增量搜索，逐步获得各梯底代价；每帧仍受同一寻路预算约束，不为每名士兵×每座楼梯同时跑完整A*。先处理最有希望的候选，但不能只固定检查最近几座后就宣布无路。

跨墙链目标比较“下楼入口→地面连接→上楼入口→目标”的组合成本，不能分别贪心选最近下楼梯和最近上楼梯。墙顶BFS仍可提供连通证据，排序成本需读实际墙顶路径长度。

整队可共享静态入口路线成本；根据本批已分配人数增加轻量队列代价，避免所有人同时选同一座梯。正式FIFO许可继续在入口按原规则取得，远处计划不提前占住物理通道。

入口选择完成后保持稳定，只有原路线失效、确认持续堵塞，或新路线有明显优势才切换。可用现有20%偏好差作为初始门槛，待用户实测调参；实际已入梯者先走完安全出口，禁止中途掉头重选。

驻守位仍由 ElevatedGarrison 分配，满员等待不算不可达。单位没走到梯底时的真实地面规划失败，可暂时排除该单位当前条件下的入口；排队、预算等待或别的单位堵住入口不能永久封禁楼梯。

## 6. 性能与大编队

| 项目 | 初始方案 |
|---|---|
| 新规划/建图总预算 | 沿用约3ms软截止时间；细寻路2.4ms、分层0.6ms是其中的分配，不是再叠加一个3ms预算 |
| 单帧任务数 | 保留最多2次重算尝试、5次验证尝试；按耗时先到者停止 |
| 驻守 | 保留现有独立2ms软预算；其中新增寻路必须走共享导航预算，不能在驻守循环里绕开限制 |
| 续算公平性 | 保留现有最多连续8个切片让出的策略；新增指挥任务优先但带等待老化，避免普通战斗AI长期饥饿 |
| 查询快路径 | 下令立即反馈；合法直线和有效缓存命中直接使用，其余按帧计算，不冻结输入 |
| 整队复用 | 同连通分区、半径/权限、目标区域的单位共享分层路线和门户成本；起点接入和最终方阵槽位仍逐单位计算 |
| 失败重试 | 区分预算、动态堵塞与静态断开；使用现有450/900ms节流作为初始值，并由相关拓扑变化唤醒 |
| 队列容量 | 到达现有256任务上限时保留可重试的待调度状态；被暂缓/淘汰不等于不可达，不丢命令 |
| 缓存 | 有界LRU与引用扇区版本；动态拥挤不强制每帧重算静态连通图 |

3ms是新增规划与建图的软预算目标，不包括所有单位移动积分、碰撞、高架表面维护与渲染；现有函数的不可抢占片段必须拆成可续算的小批次，不能把这些数字当作帧时间保证。禁用重复计费和多个子系统各自再跑一份额外全量搜索。

不引入每帧刚性队形、队长牵引或“全队共用一条精确路径”。保持原终点方阵、途中自然散开、不同移速、窄口通行以及墙顶互穿/有限驻守的契约。首版不引入Worker、Wasm或GPU寻路，避免把几何同步问题扩大成另一套系统。

## 7. 游戏反馈与失败语义

- 下令立即出现目标标记；需要跨帧时选中单位显示规划中，不把等待包装成移动中。
- 寻路成功后分批起步，避免要求整队全部算完才能动；安全直线单位可立即响应。
- 暂时拥堵显示等待通行，已有合法路径不因友军短暂阻挡全量重算。
- 静态不可达和搜索受限分开提示。同批只汇总一次人数/原因，不给每名士兵刷屏。
- 初步检查已证明无效的新命令仍拒绝并保留旧任务；已接受但后来证明不可达的命令发布正式失败记录，由原Shift队列续行，不能隐式恢复已取消的旧巡逻。
- 路线恢复判断看实际路径航点和单位位移；合法绕路允许暂时远离目标。排队和计算等待不计普通卡死，实际沿路无进展才进入局部修复/入口重选。

前三阶段作为一轮完整修复交付：仅完成A会把顶墙变成原地等待，不能声称绕墙问题已经修好。共享API先保留兼容适配，避免影响地图生成、玩家同步寻路和无关敌军AI。性能参数调整必须有采样依据，不靠扩大预算掩盖规划错误。

## 9. 验收矩阵与风险

以下为后续验收计划，当前未执行；按项目约定由用户测试，除非另行明确授权模型测试。

1. 长墙镜像目标：墙端在原局部搜索框外，士兵绕过墙端，不在墙面反复试探。
2. U形墙：必须先远离目标再走出口，进度看门狗不取消正确绕路。
3. 同一640px扇区被墙切开：允许从邻区绕回，不因同扇区跳过全局规划。
4. 对侧唯一楼梯、多楼梯及远但更快入口：选择真实可达路线，单梯FIFO与双梯分流稳定。
5. 墙链跨越、墙顶满员、梯中改令/拆墙：保持现有安全离梯、驻守等待与损毁处理。
6. 完全封闭目标与搜索受限目标：分别给出正确原因，不强行直走、不把部分路径当完成。
7. 单兵、24人、100人混编同时下令：观察首批起步、全队规划等待P50/P95、单帧导航耗时P95/峰值、队列饥饿和缓存命中；100人为压力档，不是已保证容量。
8. 连续改令、Shift队列、开关门、建拆墙：只接受最新目标对应结果；失败可续行；局部拓扑变化不使所有无关路线失效。

已知取舍：冷缓存复杂绕路可能短暂停步；粗层近似会牺牲少量路径最优性；40px网格可能拒绝实际存在的极窄通道；缓存与多目标搜索会增加有界内存。全部需要实机数据确认，不提前宣称固定延迟、固定帧率或绝对最短。

## 10. 本轮实现与交付边界

- **无路不盲走**：士兵/侍从指令地面段使用独立的`CommandRoutePlanner`结果；只有连接真实终点的`complete`路径才能交给移动层。`pending`原地等待，`search_limited`与`unreachable`分别报告；旧数组API的best-effort/RegionIndex墙边出口不进入该分支。原恐惧、击退、生产离场与安全离梯优先级保留。
- **近距离也能远绕**：实现采用640px分块缓存、40px真实格边、共享反向A*成本场。搜索从近处向外展开，允许越过原800px范围后绕回同一块，不把一整个块当连通节点。此次没有改造旧`HierarchicalRoutePlanner`为压缩门户图，也没有先调用旧局部A*再补第二次完整搜索；这避免接收旧部分路径和重复建图。旧敌军中继与玩家同步接口保持兼容。
- **完整成本选梯**：按地面可达成本＋楼梯/墙顶折线路程（含高度）＋原队列惩罚排序。下梯与上梯按完整组合比较，候选逐座产出、每个下梯点共用多源入口场；不固定只看最近几座。成本沿用等效像素，同一单位的统一速度缩放不改变排序，未引入逐段精确通行时间模拟。若部分替代路线受限，允许执行已确认可达的最佳已知路线，并保留`navigationLimitedAlternatives`标记。
- **批量与预算**：新增搜索与候选组装计入原Finder的2.4ms软预算，每次搜索/候选切片最多0.6ms；选梯轮询预留0.8ms给原地面/战斗队列。队列仍最多2次重算、5次验证、3ms排空，加入指令优先和等待老化。默认缓存上限12个成本场、单场32768节点、总65536节点、512块；没有提高原配置预算。不可抢占的单个碰撞查询/候选构造仍可能越过软截止，数值不是性能保证。
- **复用和安全**：相近起点共用目标成本场；编队在已验证公共终点到个人槽位直通且不超过160px时共用公共路线，最终位置仍独立。选梯时已求得的地面路径随航点传给PathManager，接入首段再次校验，避免重复搜索。局部几何失效清相关块/场，行进路径用有限变更记录判断是否受影响；半径桶、脚底圆心偏移、命令对象和目标变化会丢弃旧请求。缓存仅压缩共线已验证格边，不跨拐角猜测直线。
- **交通与反馈**：计划接近人数只加轻量成本，不获取物理FIFO许可；已有入口选择保持稳定，实际入梯者先完成安全出口。驻守满员继续等待，已接受命令的导航失败绑定原始移动/巡逻/移动攻击任务，Shift队列可跳过失败项。单选/多选显示规划中、搜索受限、不可达；失败提示按600ms窗口汇总，切场清理观察记录。
