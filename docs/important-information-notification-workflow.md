# 重要信息提示栏项目接入标准工作流

> **权威入口**：凡是要把新的系统结果、后台工程、探险/军团回报、奖励信件、特殊天气或其他“玩家稍后仍需查看/处理”的信息接入顶部通知与右下“重要信息”入口，必须先按本文执行。
>
> 本文只规定“顶部瞬态提示 → 右下重要信息坞 → 业务详情页”的非阻断信息流。普通飘字、战斗伤害数字、必须立即选择的模态事件、常驻任务追踪和纯调试日志不属于本流程。

## 1. 开工前必读与边界

开始修改前依次阅读：

1. `SKILL.md` 的 UI 索引和 `skill/10-ui-party.md` 的冷钢 UI、顶部通知及重要信息坞合同；
2. 本文；
3. 涉及新图标或改图时，再读 `tools/ai-gen/WORKFLOW.md`；
4. 涉及奖励、溢出物品或信件时，同时核对 `src/systems/player-reward-delivery.js`、`src/systems/mail-store.js`；
5. 涉及存档时，找到该业务状态的真实 `serialize/restore/reset` 路径，不能只改 UI。

先判断信息应该去哪里：

| 信息性质 | 正确承载面 | 说明 |
|---|---|---|
| 数秒后即可遗忘的即时反馈 | 顶部共享 FIFO | 例如一次失败原因、普通天气结束、普通操作反馈 |
| 玩家稍后仍需查看、定位或领取 | 顶部 FIFO + 右下重要信息坞 | 本文的标准接入对象 |
| 必须立刻选择，否则流程无法继续 | 模态结算/决策面板 | 不得伪装成右下提示 |
| 高频、重复、同类后台结果 | 先合并成报告，再进入重要信息坞 | 禁止逐条刷屏 |
| 战斗内伤害、掉落、状态变化 | 世界飘字/战斗 HUD | 不进入重要信息未读 |

重要信息坞的目标是“可回看、可定位、不打断”。它的出现不得自动暂停游戏、抢占战斗输入、改变业务结果，或成为奖励发放的唯一执行入口；玩家主动点击后，真实详情页是否暂停仍沿用该面板原有合同。

## 2. 现有架构与不可破坏的主流程

当前主链路如下：

```text
业务系统完成并提交真实状态
        ↓
业务所有者登记持久未读/运行期预警
        ↓
SceneManager.showTopNotification / TopNotificationQueue.show
        ↓（仅自然播放完成）
EventBus 发出 *:report-ready 或业务 announce 事件
        ↓
ResearchReportDock 释放右下卡片或仅累计角标
        ↓（玩家主动点击）
打开真实详情页/定位真实记录
        ↓（打开成功或显式确认后）
业务所有者标记已读，重要信息坞同步移除
```

必须遵守以下顺序：

- **业务先提交，表现后播放**。研究完成、奖励入账、工程报告写入、天气生效等都必须在顶部提示入队前完成。
- `onComplete` 只能负责“允许右下卡片显现”，不得在回调中发奖励、完成科技、修改建筑、结算伤亡或创建真实业务记录。
- 顶部队列被清空、渲染失败或切场中断时，可以没有右下展开动画，但已经提交的业务状态不能回滚或丢失。
- `ResearchReportDock` 是业务状态的只读适配层，不是第二套信箱、科技树、天气存档或战略日志。
- 未读、已读、附件、领取和过期状态必须由各自业务所有者维护；UI 只能调用其公开接口。

## 3. 开发前先填写“接入清单”

在任务说明、manifest 或代码改动说明中先填完以下字段。字段未确定时不要开始堆 UI：

```text
通知类别：
玩家为什么需要稍后再看：
业务来源模块：
权威状态所有者：
触发时机（必须是业务提交后）：
稳定 ID / 去重键：
是否存档；旧存档默认值：
顶部摘要文案与 tone：
右下标题 / 摘要 / 操作文案：
详情页与定位参数：
何时标记已读：
何时自动清除或过期：
是否合并；合并键、窗口与字段守恒规则：
战斗/地牢/加载期间如何处理：
图标复用路径；缺图回退路径：
是否涉及物品、奖励信箱或地牢临时战利品：
```

稳定 ID 必须能跨 UI 重绘并在需要时跨存读档识别同一条记录。禁止使用数组下标、当前 DOM 顺序、随机文案或图标路径作为业务 ID。

## 4. 业务状态归属

优先复用现有所有者，不要为了接入提示栏再造通用 `notifications[]` 存档：

| 类型 | 权威状态 | 重要信息坞只做什么 | 点击目标 |
|---|---|---|---|
| 科技完成 | `TechnologySystem.unreadReportIds` | 按科技 ID 映射节点与解锁摘要 | `TechnologyTreePanel.openAt(id)` |
| 正式奖励信件 | `MailStore.state.mails` | 映射未读且仍有附件的正式信件 | `MailboxPanel.openAt(id, npc)` |
| 高影响天气 | 对应天气系统的活动事件；坞内仅保留运行期映射 | 展示正在生效的预警，结束/重置/读档覆盖时清理 | 显式确认，不切位面 |
| 工程/探险/军团结算 | `WorldStrategySystem.state.events` / `StrategicJournal` | 映射重要且未读的战略事件 | `WorldSwitchPanel.openAtEvent(id)` |

新类型若确实不属于这些所有者，应先在原业务域建立清晰的记录、读取、序列化、恢复、重置和已读接口，再让重要信息坞消费它。不得把业务数据长期塞进 `_releasedKeys`、DOM `dataset` 或临时回调闭包。

持久信息至少要补齐：

- 初始空状态和旧存档缺字段时的安全默认值；
- `serialize`、`restore`、`reset/new game`；
- 无效 ID、已删除配置、超过历史容量后的清理；
- 恢复后重建未读入口的事件或显式同步入口；
- 标记单条已读和需要时的全部已读；
- 打开失败时不误删未读。

运行期信息（目前的特殊天气）必须有稳定活动 ID，并在自然结束、系统重置、读档覆盖或事件被替换时发出对应清理事件，禁止留下过期角标。

## 5. 顶部通知接入

所有顶部瞬态提示统一走：

- `SceneManager.showTopNotification(text, options)`；或
- 底层 `TopNotificationQueue.show(text, options)`。

不得自行向 `body` 挂另一条 toast、另建播放队列或用模态层模拟顶部通知。现有队列是单槽 FIFO，按触发顺序播放；暂停时由 `TimerManager` 冻结，`clear` 不会调用完成回调。

新调用优先传语义参数：

```js
SceneManager.showTopNotification(summary, {
    tone: 'success', // info | success | warning | danger
    onComplete: () => EventBus.emit('domain:report-ready', { id: report.id }),
});
```

要求：

- 顶部只写一行可扫读摘要，不粘贴完整报告；
- `tone` 按结果语义选择，不用文案关键词猜色；
- 只有自然播完才释放右下展开动画；
- 若业务记录可能在排队期间被合并、读掉或过期，回调执行时必须再次按稳定 ID/修订号核验；
- 同一业务不能同时调用两个顶部入口；
- 顶部提示的显示与否不得影响真实结算。

## 6. 重要信息坞适配

统一入口是 `src/ui/research-report-dock.js`。接入一个新类别通常要完成以下最小闭环：

1. 定义不冲突的 key 命名空间，例如 `domain:${id}`；
2. 在 `init()` 订阅业务的 ready/read/restore/clear 事件；
3. 初始化时从权威状态恢复未读 key；
4. 在 `_entryForKey()` 将业务模型只读映射为：
   `type / id / icon / eyebrow / title / summary / action`；
5. 在 `_openEntry()` 打开真实目标；只有打开成功或显式确认后才调用业务已读接口；
6. 读档、重置、业务侧已读或过期时同步删除对应 key；
7. 只有新增视觉语义确有必要时才增加 `data-kind`，样式写入 `ui/panel-theme-backpack.css`；
8. 图标加载必须有明确回退，不能因一张图缺失让整条信息不可操作。

不要为每种业务复制一套卡片 DOM。卡片结构、角标上限、ARIA、移动端位置、危险时段抑制与收起动画继续由统一坞维护。

### 6.1 点击与已读边界

- 点击成功打开科技节点后，才调用 `TechnologySystem.markReportRead(id)`；
- 信箱不满足地点/NPC 条件时，显示顶部说明并保留信件未读及附件；
- 战略报告由 `WorldSwitchPanel.openAtEvent(id)` 定位，详情面板成功打开后由战略日志标记已读；
- 天气点击属于“确认预警”，只移除该运行期入口，不结束天气、不暂停、不切换位面；
- 新类别若没有可靠详情页，不应写“查看报告”；应提供真实可执行的确认动作，或先补详情页。

## 7. 战斗、地牢与加载期间不得打断

右下来函不得自动暂停游戏或自动打开面板。当前统一坞会在以下危险时段只累计未读角标，不展开卡片：

- 场景加载或地图模式；
- 地牢战斗/Boss 阶段；
- 玩家正在攻击、闪避、冲刺或特殊攻击；
- 开放世界近身交战；
- 玩家不可用或游戏未处于可交互状态。

新类别必须复用这套统一判断，不得在业务模块复制一份“是否在战斗”的近似逻辑。顶部 FIFO 仍按公共规则播放；若该信息本身要求立刻中断玩家，它就不属于重要信息坞，应设计成独立的强制决策流程。

## 8. 合并、去重与高频事件

后台工程、连续升级、批量招募、探险归来等高频完成项应先形成报告，再发一条提示。

现有战略报告以“同类别 + 同位面 + 未读 + 10 秒窗口”为合并示例：

- 工程报告守恒合并建筑升级条目、持续升级阶段、传送门记录和招募人数；
- 探险报告守恒累加归来次数、物品数、金币和转信箱附件数；
- 已读报告不再回写，下一次完成创建新报告；
- 不同位面不合并；工程、探险、军团战报和奖励信件不互相合并；
- 合并后更新 `createdAt`、摘要和 `revision`，旧的排队回调不能释放已经失效的版本。

新系统可选择不同窗口，但必须在接入清单中写清：合并键、时间窗口、字段如何累加、哪些字段取最新、何时另起一条。禁止仅拼接文案而丢掉数量、伤亡、附件、来源或定位 ID。

去重必须依靠业务 ID/收据：

- 奖励使用稳定 `sourceId` 和 `MailStore.state.receipts`；
- 科技使用科技 ID；
- 战略事件使用事件 ID；
- 天气使用本次活动事件 ID。

## 9. 奖励与小鼠大王信箱的强制隔离

重要信息报告与小鼠大王奖励信箱是两套职责：

- 报告说明“发生了什么”，不能保存或复制奖励附件；
- `PlayerRewardDelivery` 负责背包 → 仓库 → 正式信箱的事务、收据去重和领取；
- 只有正式 `MailStore` 信件已成功提交后，才能发 `mailbox:report-ready`；
- 右下信件入口只引用信件 ID，不复制 `attachments`，也不重算“待领取”；
- 领取、部分领取和已读仍由信箱流程处理，报告不能替代领取按钮。

地牢期间默认 `deferDuringRun: true`：装不下的掉落进入本次地牢临时战利品，死亡/放弃按原规则损失，不能提前显示为“已寄信”。只有已经明确属于后台探险、战略结算等独立系统奖励，才可在调用处显式使用 `deferDuringRun: false`，使溢出物品独立进入正式信箱；这不能作为新奖励类型的默认偷懒选项。

任何奖励都必须先完成事务提交，再播顶部提示；不得在顶部 `onComplete`、卡片点击或动画结束时发奖。

## 10. 图标复用与缺图生成

### 10.1 先查再做

新通知编码前先搜索以下位置和业务配置：

```text
assets/ui/technology-icons/
assets/ui/event-icons/
assets/ui/icons/
data/technology-tree.json 与 public/data/technology-tree.json 的 iconPath
src/world/weather-event-icons.js
```

复用顺序：

1. 业务模型已有 `iconPath`：通知栏、详情页、时间进度栏共同消费同一字段；
2. 已有语义完全一致的科技树/事件图标：直接复用，不复制文件；
3. 只有语义不匹配或确实缺图时才生成；
4. 新图尚未定稿时提供明确的通用回退图标，不留断图。

当前已用映射：

| 类别 | 图标 |
|---|---|
| 科技简报 | `assets/ui/icons/technology_tree.png` |
| 奖励信件 | `assets/ui/icons/quest.png` |
| 工程报告 | `assets/ui/technology-icons/engineering_drafting.png` |
| 探险回报 | `assets/ui/technology-icons/expedition_logistics.png` |
| 军团战报/归营 | `assets/ui/technology-icons/tactical_command.png` |
| 天气通用回退 | `assets/ui/technology-icons/weather_forecasting.png` |
| 六类特殊天气 | `src/world/weather-event-icons.js` 的唯一映射 |

DOM `<img>` 直接读取静态资源路径，不需要为了右下通知额外登记 Phaser `BootScene` 预载；若同一图还要在 Phaser 画布内使用，再按对应场景的资产注册合同接入。

### 10.2 缺图时的生成工作流

缺图后严格转入 `tools/ai-gen/WORKFLOW.md`，不要在业务任务中临时发明另一套生图流程：

1. 选择同系列已定稿图标作模板，确认框体、主体安全区、冷钢材质、视角和透明轮廓；
2. 同系列图标采用 FLUX.2 Dev 模板锁定 img2img；需要固定结构时使用 Dev Depth。禁止自动改用历史 Klein 路线；
3. 先生成候选并保存在任务目录，不直接覆盖正式运行图；
4. 候选须提供可直接查看的总览/预览，确认后才晋级正式资源；
5. 图标不得包含文字、数字、角色肖像式杂讯或与相邻类别混淆的主体；
6. 检查透明 Alpha、四角、黑边/白边、棋盘格烘焙、主体居中和小尺寸辨识度；
7. 保存最终提示词、参考图、模型/seed/denoise/步数、源图、运行图和选择结论，保证可重建；
8. 正式接入只保留一个真源映射，通知坞和其他 UI 不各写一份路径。

尺寸遵循所属图标系列，不按通知栏 44px 显示尺寸直接生小图：

- 科技树六边形徽章按该系列 1024×1024 RGBA 正式规格；
- 特殊天气事件图先保留 1024 源图，再派生 256×256 RGBA 运行图；
- 在 44px、48px、64px 三档查看主体是否仍能一眼识别；
- 框外透明，主体不贴边，不能靠发光或细小文字维持语义。

## 11. 文案、视觉与可访问性

每条右下信息必须包含：来源眉题、短标题、一行摘要、真实动作。建议上限：标题尽量不超过 20 个汉字，摘要由适配层压缩到约 112 字符以内；完整数据留在详情页。

视觉规则：

- 统一使用现有卡片 DOM 和 `ui/panel-theme-backpack.css`；
- 动态颜色通过 `data-kind` 和主题变量表达，禁止业务文件写内联色板；
- 图标固定 `object-fit: contain`，不能为不同图标改变卡片结构；
- 新动效必须是轻量进入/收起，不遮挡操作，并补 `prefers-reduced-motion`；
- 入口必须是原生按钮，保留 `:focus-visible`、`aria-label` 和统一 `aria-live="polite"`；
- 数量角标沿用 `99+` 上限，不用更多位数字撑坏布局；
- 窄屏继续使用统一坞的响应式位置，不在新类别里硬编码另一套坐标。

## 12. 推荐实施顺序

按以下顺序开发，避免“卡片做完才发现没有可靠状态”：

1. 找到业务完成的权威提交点和真实详情页；
2. 填写接入清单，确定 ID、所有者、存档、已读和过期规则；
3. 在业务域完成记录/去重/合并/序列化，确认表现失败不影响结果；
4. 在提交后调用顶部共享 FIFO；
5. 通过自然完成回调发出 ready/announce 事件；
6. 在 `ResearchReportDock` 增加最小只读适配、点击和同步清理；
7. 先盘点图标，缺图才走标准生图和候选批准流程；
8. 在主题 CSS 增加必要且最少的视觉语义与减弱动态支持；
9. 核对存档恢复、重置、打开失败、危险时段和顶部队列清理边界；
10. 更新 `skill/10-ui-party.md` 的稳定合同与 `CHANGELOG.md`，未来计划写 `TODO.md`，不要把进度流水塞进本工作流。

## 13. 交付前检查表

### 13.1 静态接线

- [ ] 业务状态在顶部提示入队前已经提交；
- [ ] `onComplete` 只释放表现，不执行业务；
- [ ] 顶部提示只走共享 FIFO；
- [ ] 新 key 命名空间不与 technology/mail/weather/strategy 冲突；
- [ ] 未读和已读由业务所有者维护，坞没有复制存档；
- [ ] 打开成功后才标已读，打开失败仍可再次点击；
- [ ] 读档、重置、过期和业务侧已读都能同步清理；
- [ ] 高频事件已定义合并和字段守恒规则；
- [ ] 奖励有稳定 `sourceId`/收据，报告与附件隔离；
- [ ] 已搜索现有图标；缺图才生成，并有回退路径；
- [ ] 图标路径只有一个真源，通知栏与其他 UI 不重复映射；
- [ ] 样式集中在主题 CSS，键盘焦点、ARIA、窄屏和减弱动态未退化；
- [ ] `data/` 与 `public/data/` 若涉及配置，保持实际镜像合同一致。

### 13.2 运行时重点场景

只有当前任务明确授权测试时才由开发者运行；否则将本清单交给用户验收：

- [ ] 普通探索时：顶部自然结束后右下来函展开；
- [ ] 战斗、Boss、闪避/攻击、地图模式和加载中：只累计未读，不暂停、不抢输入；
- [ ] 顶部队列连续多条：保持 FIFO，完成回调不串条；
- [ ] 顶部提示被清理：业务结果保留，不错误展开卡片；
- [ ] 同位面短时多次完成：按合同合并，数量与项目不丢；
- [ ] 不同位面、不同类别或已读后的新事件：分别成条；
- [ ] 点击成功：定位正确记录并在正确时机已读；
- [ ] 点击条件不足：保留未读并给出可行动说明；
- [ ] 存档、读档、新游戏/重置：未读恢复或运行期预警清理正确；
- [ ] 天气结束/被替换：过期入口消失；
- [ ] 背包和仓库已满：正式奖励进入信箱，报告本身不持有附件；
- [ ] 地牢进行中：临时战利品和显式独立系统奖励按各自合同分流；
- [ ] 图标在 44/48/64px、窄屏和加载失败回退时可辨识。

## 14. 禁止事项速查

- 禁止用提示动画代替业务提交；
- 禁止在 `onComplete` 或点击卡片时发奖/完成工程；
- 禁止新增第二条顶部 toast 队列或第二个重要信息坞；
- 禁止在战斗中自动打开报告、暂停游戏或抢占输入；
- 禁止把所有通知塞进一个脱离业务域的通用持久数组；
- 禁止打开失败仍标记已读；
- 禁止把地牢临时战利品伪装成正式小鼠大王信件；
- 禁止在报告里复制附件、领取状态或奖励数量真源；
- 禁止已有图标仍重复生成、复制文件或为两个 UI 维护两套映射；
- 禁止候选图未确认就覆盖正式资源；
- 禁止在业务 JS 中复制冷钢色板、坐标和卡片结构；
- 禁止把完整报告塞进顶部提示或右下摘要。
