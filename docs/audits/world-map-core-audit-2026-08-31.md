## 发现与处理

### F01 · P1 · 战场返回失败后恢复残缺现场（已修复代码）

触发路径：`finishBattle()`已读取结果并打包幸存者，随后`_switch(strategy_map)`进入`StrategicEncounter.load()`。地图加载先执行`_clearSiege()`和撤退标记清理，并把战场菱形配置切为地图配置；`StrategicSiege.destroy()`会将旧城防对象销毁/置为不活动。后续资源加载等阶段仍可能失败。

原`SceneManager._rollback()`对非永久战略场景仅恢复旧实体引用；原`finishBattle()`的catch又物化士兵、恢复玩家并打开战斗HUD。该路径没有重建被毁城防及撤退标记，旧战场引用不再能支持完整继续战斗；后续再次读取城防结果还可能把卸载后的状态当成战损。

修复位于`world-strategy-system.js#finishBattle/retryBattleReturn`与`strategic-encounter.js#showReturnFailure`：

1. 确认时只读取一次敌军/城防/设施结果和战利品，幸存士兵只打包一次。
2. 私有`_pendingBattleReturn`保留本次结果，兵力仍以原`strategicTroops`为唯一账本；没有另复制一份可物化军团。
3. 转场失败后保留`_busy`，因此`Game.update`不继续战略战场操作，存读档沿用原忙碌门禁；显示独立返回重试按钮。
4. 重试只执行转场；`inFlight`阻止并发调用。成功后才按原入口写战损、归属和战利品，随后清理待返回对象。战败仍走原撤回主神空间入口。
5. 重试提示沿用既有战场HUD和`bp-button`，错误内容使用`textContent`，不新增主题或全局事件监听。

这是当前运行内的失败恢复，不是战斗断点存档；关闭进程不会持久化待返回对象。共享世界时钟继续按既有规则推进，战略调度和战场更新停在忙碌边界。

### F02 · P2 · 撤退选格只排除军团，遗漏敌城和战事（已修复代码）

原`finishBattle()`选择第一个没有战略敌军的邻格，但敌方城镇驻军记录位于`state.sites`，普通周期围城记录位于`WorldInvasionSystem`。这些格子可能没有`state.enemies`记录，因此会被当成撤退空地。落入敌城后，保护期结束又会被`_contact()`带回战斗；全部邻格被占时则停留原敌格却显示已撤出。

新增`retreatCell()`统一检查敌军、活动敌城和当前战事。HUD和确认入口读取同一方法；无安全邻格时禁用撤退并说明原因，未到10秒或未到西侧集结区仍沿用原门禁。确认后保存所选相邻格，成功回图时使用它；不跨格瞬移、不删除敌军，不改驻军强度。战败不受主动撤退门禁阻挡。

4. 战败回图后撤回主神空间、正常返营，以及反复开关地图和旧行军档恢复。此次未扩展完整返营失败恢复或存档审计。
