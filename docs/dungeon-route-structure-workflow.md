# 地牢路线与背景同源流程

> 当前默认已采用[独立探索台v10](dungeon-exploration-console-v9.md)。本规范保留用于未来确需空间贴路的特殊地图；普通地牢背景只承担环境展示，不要求逐图标注路网。

## 当前问题与本轮边界

当前矿洞运行时不识图。背景是先由ImageGen生成环境图，再在`mine-route-landmarks.js`登记平台折线和楼梯端点。逻辑房间图、背景图、人工通道坐标分别产生；选图的拓扑权重只能挑近似合适的图，不能保证全部连接天然吻合。

本轮撤销平台旁轨偏移，连线直接沿已有平台中心线、楼梯端点连线绘制，节点后画并遮住线头。继续保留共享段合束、出口颜色及悬停追线。不修改房间生成、奖励、迷雾、点击门禁、背景或HUD。

这只修正算法主动把线移出路面的行为，不代表十张图的人工坐标都已校准。现有楼梯仅有两端，不能完整描述转折平台；现有平台也没有路面宽度、多边形或遮挡数据。识图只能辅助草拟这些数据，不能把推断直接视为通行事实。

## 标准制作流程（后续实施规范，尚非现有完整功能）

1. **先定可支持的结构。** 先整理房间图需要的分叉、汇合、上下层和节点容量，选能承载它的道路结构。视图容量不足就分区；模板不合适就更换模板，不靠画一条穿墙直线补连接。
2. **先画结构底稿，再做环境美术。** 用相同坐标系定义平台、楼梯、节点台面和路口，固定镜头与画幅。结构图或简单3D场景同时输出背景依据与路线数据；材质和装饰围绕已定结构制作，不允许改变道路出口。
3. **图片与数据成对交付。** 每张图对应独立版本的数据：原图尺寸、投影/裁切规则、可用道路、楼梯完整折线、禁行区、节点槽位和可见区域。不能用一份近似坐标套全部图片。
4. **沿路布点、沿图寻路。** 节点绑定道路上的位置；不同楼层只通过登记的楼梯相连。各逻辑边映射为道路段序列，几何相交不等于连接。过境线经过其它徽记下方也不改变玩法上的邻接或可达。
5. **最后处理信息层级。** 同路段只画一束，颜色用于独立出口和聚焦路径。节点密集先分区，不能把路移到悬空区域或不断缩小徽记。装饰避开道路与节点台面。
6. **验收后再扩展。** 先完成一张含平台、楼梯、汇合和4～6条分支的样板。核对完整道路和楼梯是否贴合、墙/断桥是否阻断、上下层交叉是否被误当路口，以及往返路线、显隐切换和各窗口尺寸。样板确认后再制作同规格变体，不一次重画十张。

## 数据最低要求

| 数据 | 必须表达的内容 |
| --- | --- |
| 图像与坐标 | 背景路径、结构版本、原图尺寸；背景与线路共用投影 |
| 路口 | 唯一ID、原图坐标、楼层；不同楼层同屏交叉仍是不同点 |
| 道路段 | 起终路口、完整中心折线、路面范围/宽度、道路或楼梯类型 |
| 楼梯 | 上下层归属、踏步段和转折平台；不能只按图像距离连接楼层 |
| 节点槽位 | 绑定道路段、沿线位置、徽记/标签所需空间 |
| 禁行与遮挡 | 墙、水面、断桥、装饰性梯井和遮挡结构；识别不清处待校准 |
| 逻辑边映射 | 真实房间边对应的道路段序列；不得在渲染时新增玩法边 |

## 旧图迁移与限制

旧图可以保留：逐张描定路面中心折线，补全楼梯转折、楼层和禁行区，再收敛到上述格式。辨认不清或不能容纳所需分叉的图片应补作结构或换模板，不强行解释成可通行道路。视觉和连通性足够清楚的图不必重做。

当前缺失路径时仍保留原有直连降级以免把真实可走边隐藏；它不是贴路成功。后续严格模式需要同时设计清楚的示意图降级提示，不能直接删掉回退后让选路入口消失。本轮尚未接入道路面约束、完整楼梯折线、结构制图工具或新的背景生成流程。

本轮仅阅读现有代码/合同和一张原始背景，未运行测试或运行时验证，按约定由用户测试。上述验收项是后续标准，不是已通过记录。
