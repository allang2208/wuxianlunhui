# 建筑详情面板第 1—4 项修复

仅处理本次代码审计提出的四项问题。窄窗口布局、升级收益说明和键盘浮窗改善不在本轮范围；不修改招募计时、资源支付、升级队列、持续升级互斥或存档规则。

| 项目 | 修复方案 | 实现状态 |
| --- | --- | --- |
| 1. 矿工营地每 500ms 重建控件 | 每 500ms 原位更新岗位、人口、矿工携带量、资源、属性和耐久；人数按钮操作后只刷新数值；升级开始/完成、科技或续升状态变化仍按需重建卡片 | 已实现，待用户实机验收 |
| 2. 详情生命值、余额和兵力滞后 | 共用耐久显示计算与原位更新函数；通用建筑详情每 500ms 同步当前/最大耐久、百分比、颜色、已有资源余额以及单/双通道特色编制数量 | 已实现，待用户实机验收 |
| 3. 双通道单次招募完成后按钮仍高亮 | 每次进度刷新读取各通道真实模式，同步单次/持续/暂停按钮的选中态 | 已实现，待用户实机验收 |
| 4. 能源不足仍显示下次生成 0s | 首次渲染和后续刷新都使用原招募状态函数生成倒计时/等待原因；缺能源时进度和倒计时使用资源不足警示色 | 已实现，待用户实机验收 |

## 用户验收步骤

1. 矿工营地保持打开，聚焦岗位或可用升级按钮并等待超过 500ms；没有升级/科技/续升状态变化时焦点应保留。连续调整岗位，人口、按钮禁用态、携带能源和仓库能源正常更新。
2. 矿工升级开始、完成或持续进入下一档后，等级、费用、按钮状态和进度应同步；关闭并重新打开仍正常，不遗留刷新定时器。
3. 保持经济/出兵详情打开，让建筑受伤或被维修，并使金币、能源或粮食变化；耐久数值、条长和现有余额显示应在下一次数值刷新时更新，周期约 500ms。
4. 探险家营地、丛林神庙分别执行一次单次招募；完成后该通道显示“已暂停”并高亮“暂停”，数量加一。持续招募和另一通道不受影响；单位死亡后数量也应更新。
5. 选择消耗能源的普通兵种，粮食/人口等其它条件满足而能源不足时，“招募状态”和“下次生成”都应显示能源不足，进度使用警示色；补足能源后沿原重试入口恢复招募，支付和生成次数不变。

进度表示已完成的等待时间，缺资源时可能保持 100%；这不表示已经生成单位。此时等待原因与警示色负责说明阻塞状态，原生产计时不被重置。

只查看了本轮真实差异及必要局部调用链。未运行测试或运行时验证，按约定由用户测试；未运行构建、未启动游戏、未同步固定 EXE。
