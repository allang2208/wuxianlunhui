# 世界位面生命周期短期路线图（2026-08-20）

目标：先把“地牢解锁 → 传送门构造 → 位面运行 → 入侵 → 毁灭 → 重建”的生命周期闭环做稳，
再扩充新世界、地牢和怪物。每个阶段独立交付，不跨阶段顺手重构。

## 阶段 1：构造后立即初始化基础位面快照（已完成）

- 传送门构造或重建成功后，立即建立对应 `sceneId` 的基础快照。
- 基础快照至少包含时间锚点、传送门耐久、空建设状态和后台结算所需字段。
- 已构造但尚未首次进入的世界可以正常成为入侵目标，不再依赖不存在的快照。
- 玩家首次进入时按现有世界规则生成地形与资源；离场后捕获为完整快照。
- 读档若发现“传送门已建成但快照缺失”，自动补齐基础快照；已有完整快照不得覆盖。

验收：首次构造、重建、新游戏初始世界和旧档恢复四条入口都满足“已建传送门必有快照”。
实现位置：`world122-snapshot.js`、`world-progression-system.js`、`scene-manager.js`、
`world-invasion-system.js`。

## 阶段 2：正式位面状态机与世代号（已完成）

- 将布尔组合收敛为 `LOCKED / AVAILABLE / ACTIVE / DESTROYED / REBUILDING`。
- 每次重建递增 `worldEpoch`；旧世代快照、延迟任务和后台回调不得写回新世界。
- 保留旧存档字段迁移口径。

验收：任何时刻只有一个合法状态，旧世代数据无法复活。
实现结果：内部状态统一为 `LOCKED / AVAILABLE / ACTIVE / DESTROYED / REBUILDING`；保留旧布尔
字段供现有调用方兼容。首次构造使用 `worldEpoch=1`，以后每次重建递增；快照、前后台入侵和
传送门实体都携带世代号，显式旧世代数据被丢弃。v1 布尔存档自动迁移到状态机与初始世代。

## 阶段 3：毁灭事务与存档原子性（已完成）

- 统一停止后台结算、清快照、清旧坐标、撤入口、撤离玩家和保存进度的执行顺序。
- 处理毁灭与保存、切场景、观察模式同时发生的竞态。
- 失败回滚不能恢复已经毁灭的位面。

验收：前台和后台毁门结果一致，存读档不能恢复已清除建筑。
实现结果：毁灭入口先按 `sceneId + worldEpoch` 建立幂等事务并把位面标记为 `DESTROYED`，随后
删除快照和旧坐标、撤销主城入口，再处理玩家/观察者撤离。快照捕获与主存档序列化统一校验传送门
是否仍有效，因此毁门和离场/保存同帧发生也不能重新写回旧建筑。强制回城不建立通用 rollback；
失败时彻底拆除位面系统、实体、墙体、特效和循环音，并最多重试三次，到达主城后关闭事务。

## 阶段 4：配置化重置规则（已完成）

- 为每个世界配置基础模板、生成规则版本、种子策略、资源规则和重建保护期。
- 明确哪些是全局进度，哪些随位面毁灭清除。

验收：新增世界只需配置重置策略，不在生命周期代码中写世界特例。
实现结果：`world-system.json` 新增公共 `resetPolicyDefaults` 与每世界 `baseSeed`，统一声明基础
模板、生成规则版本、`per_world_epoch` 种子策略、资源规则、毁灭清除项、全局保留项及后续保护期
参数。传送门状态和快照封存 `generationVersion/generationSeed`；同一世代的地表点缀、障碍和资源点
稳定复现，重建递增世代后生成新布局。旧存档自动推导缺失生成字段且不覆盖已有完整建设快照。
当前基础模板为 `portal_only_v1`，资源规则为 `energy_clusters_v1`；`rebuildProtectionDays` 只完成
配置协议，实际入侵保护行为留在阶段5。

## 阶段 5：重建保护与入侵体验（已完成）

- 新建/重建后的世界按配置获得保护期，保护期内不进入随机入侵池。
- 增加传送门耐久分段预警、跨世界支援和毁灭前撤离提示。

验收：重建后不会立即再次被选中，玩家能获得清晰预警并主动响应。

实现结果：公共重置策略启用 1 个游戏日的新建/重建保护期，绝对截止时间随传送门状态存档；真实
入侵候选池统一排除保护中的位面，若所有位面均受保护则保留已积累进度，首个保护期结束后再选点。
普通帧入侵只消费环境时钟本帧实际增量，因而太阳时钟暂停、游戏暂停和地牢冻结时，倒计时与保护期
不会分叉。
传送门在 50%/25%/10% 耐久分别触发配置化预警，HUD 同步显示实时耐久并在异世界入侵时提供
“前往支援”；该入口明确转移玩家本体，不使用观察模式。10% 阶段提示立即支援或撤离，毁门时位面内
玩家收到紧急撤离提示并继续执行阶段3的原子毁灭事务。

## 阶段 6：调试工具与数值扩展（已完成）

- 开发面板展示位面状态、世代号、快照、入侵候选池，并支持受控推进时间与模拟毁门。
- 生命周期稳定后再调整入侵波次、怪物池和更多地牢—世界解锁关系。

验收：开发期可以快速复现完整生命周期，数值扩展不修改核心状态链。

实现结果：交互开发工具新增“位面”页签，集中显示每个位面的生命周期状态、`worldEpoch`、传送门
耐久、保护剩余时间、生成版本/种子、快照摘要和当前真实入侵候选池。页签可通过统一环境时钟受控
推进 1/5 天，也可对选定位面调用正式毁门入口，因而能快速复现保护期、入侵、毁灭和重建链路。
入侵怪物仍由现有 `monsters` 配置表和工厂扩展，波次数值、新怪物及更多地牢—世界关系作为下一轮
独立内容阶段处理，不修改本轮已经稳定的生命周期状态链。
