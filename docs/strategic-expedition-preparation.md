# 指挥建筑出征准备

2026-08-30。本轮按用户新重心实施大战略闭环的出征入口与编组界面，不开发第一章教学。当前为本地代码接入，未运行测试或运行时验证；完整玩法的 Git 发布边界仍见 `world-strategy-publication.md`。

## 玩家操作

1. 点击当前建设位面的指挥所、司令部或国防部，仍先打开原建筑详情，保留建筑图片、耐久、防御及原有操作。
2. 详情功能区新增“位面出征”卡，点击“出征”进入独立准备界面。点击入口和选择单位不打包、不扣钥匙、不改变兵力。
3. 顶部展示编组出征、接敌战斗、占领/摧毁、撤军回归四步关系；当前只处于编组阶段，不是可跳过战斗的导航按钮。
4. 左侧名册可按全部/士兵/队友筛选，并按名称、兵种查找。点击卡片切换随军/留守；“编入当前列表”仅选择当前筛选结果，士兵达到原24名上限即停止添加，不删除已有兵力；“清空编组”同时取消士兵与队友选择。玩家固定随军，保留既有单独亲征能力。
5. 右侧显示真实建筑等级缩略图、当前位面和信标格、玩家领队及所选兵种/队友摘要。顶部和底部显示已选人数与留守数量，全部可选士兵随军时提示防守风险；不据此强制留守或改变军事人口。
6. 确认后调用既有 `WorldStrategySystem.depart()` 打包，原场景加载器接管转场，进入大地图再选行军目标。后续接敌、攻占/摧毁、战利品和返营继续由已有战略系统处理。本界面不直接跳到目标敌城。
7. 取消或 Esc 关闭准备；原建筑仍在本体当前位面且满足入口条件时回到该详情。确认失败则返回准备页并显示原因，保留仍有效选择；若兵力已因原回滚流程重新物化而更换身份，会明确提示重新选择，不自动替选。

## 交互和状态边界

- 使用原 `BasePanel`、`strategicExpedition` 状态键和右侧挂载层 `modal`，保留浏览器/Electron Esc、RTS/快捷键与世界指针隔离。打开/关闭清除按住输入；焦点限制在模态控件中，取消后定位原出征入口。
- 名册每秒读取一次现有候选接口，仅在打开期间运行，关闭清理计时器及卡片引用；存活、离场和外派资格仍由现有系统决定。卡片按单位身份原位更新，不周期性销毁整张列表。刷新和切换筛选均保留有效选择。
- 当前位面的士兵名册合并现场实体、友军列表及当前产兵建筑名册，以统一`getUnitKind`和可保存的军事兵种表识别，不再要求额外兵营/兵线标记；按稳定单位ID去重。已有低阶兵、新兵种和已抵达的跨位面增援都按实际在场身份列出，来源位面不冒充当前驻留位面。交互开发工具通过“测试友军”实际生成的士兵也可编入，`_collisionEditorTest`仅表示生成来源，不能作为出征排除条件；只有固定冻结的`_collisionPreview`预览体不列入。死亡、已外派、其他位面记录和经济矿工继续排除，队友仍单独列出。24名上限只限制选择，不裁掉当前位面的完整士兵列表。
- 确认前重取候选；若这一刻发现已选单位失效，先停在准备页要求重看编组，不静默减少出征兵力。确认后仍由原系统复核建筑、场景和单位，UI不自行复制或移除实体。
- 只展示真实HP和原容量，不新增战力算法、补给扣费、多军团、额外单位、教学保护、存档字段或普通地牢入口。
- 世界自然时间不暂停。准备页仍可能遇到建筑受损、单位离场或玩家死亡；不可出征原因原位显示。已打开准备页不构成安全区。
