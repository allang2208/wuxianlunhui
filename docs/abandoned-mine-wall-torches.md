# 矿洞挂墙火把（2026-08-30）

后续按用户要求增加三类稀疏随机墙面挂饰：挂绳圈、矿镐挂架和旧工区木牌，来源、图片及分布规则见`tools/ai-gen/_mine_wall_decor_20260830/README.md`。挂饰复用本模块的候选和清理，但不改变原火把选位、灯光或数量；独立侧面挂点修正了宽挂饰被邻墙遮盖的问题。

按用户“墙面增加火把与光源，看看能否复用僵尸地牢”的请求实施。只接入矿洞样式，不重新开启旧地牢障碍物系统，不改现有墙门PNG、地板小物、战斗事件、场地生成、随机布局参数或碰撞。

## 复用来源

- 正式木柄/金属挂架：`assets/terrain/obstacle_torch.png`，144×278透明PNG。BootScene及`ISO_WALL_GEO.torch`已有登记，无需生图或新建重复纹理。
- 历史实现：Git `5701cfd` 的`src/world/obstacle-spawn-system.js:_placeTorch`使用这张图、`impact_dot`三色上飘粒子和`registerEnvironmentGlow`。当前ObstacleSpawnSystem已于此前收敛为零生成，本次不恢复它。
- 当前效果：沿用GameScene现有粒子纹理、常驻柔边暖光与亮度开关。按旧图杯口`(26,14)`定位火焰、背板`(120,128)`定位挂点，避免沿用旧中心/脚点混用的位置算法。

## 接入与摆放

- `src/world/dungeon-wall-torch-system.js`只读最终`_gridBlockWall`、`_baseSegments`、正式墙脚锚和房间/通道多边形（含回环孔洞）；在单房或多房墙门装配完成后执行一次。
- 兼容规则房的一整段和随机墙环的两半段。不挂门端半段、折角/交会块、木撑C款；与完整门线至少130px、转角90px、其他火把340px距离。只取朝镜头且面向真实室内/通道的墙面，不向房外黑区挂灯。
- 候选顺序用独立坐标散列；不调用布局生成器、不更改种子、模板概率、墙款散列或房图。粒子和暖光沿用引擎自身视觉随机变化，不承诺跨帧火焰形状逐像素一致。
- `ISO_WALL_STYLES.abandonedMine.wallTorches`为唯一开关/参数：缩放0.30、挂点高度66、墙面偏移18；每物理房最多6、每通道最多2、全场最多32。数量是上限，短墙、木撑密集或门洞密集可能更少，不强行塞满。
- 两个墙轴对火把做方向镜像；挂点、火盆和粒子使用同一个带符号缩放。墙块本身仍禁止镜像，无独立门框或新补缝件。

## 表现与生命周期

- 原挂架加小幅向上火焰，墙面暖光半径88、alpha0.16；杯口半径32、alpha0.24，10%轻微闪烁。暖光复用现有ADD柔光，是视觉照明，不是新增法线/PBR点光源、投影或穿墙遮光求解器。
- 深度在宿主墙之后紧邻排序；新对象不进入墙件、占格或物理碰撞。只照明，不灼烧、不交互、不改变怪物行为。
- 本体/粒子进入现有世界特效组，地图模式隐藏；暖光继续服从`localGlowEnabled`与现有迷雾同步。退出战斗、场地失败恢复及Phaser shutdown均注销暖光、销毁粒子和挂架；普通波次推进不重新生成。
- 旧障碍接口、其他地牢、矿洞位面和建筑用火把保持原状。本次仅覆盖通过CombatRoomSystem构建的矿洞单格墙战斗场地；没有推广为位面散布装饰。

## 交付限制

仅查看本轮真实差异与必要局部调用合同。未运行测试或运行时验证，按约定由用户测试。

重新进入矿洞战斗后重点看：两轴挂架与杯口火焰是否贴合、左上/右下门端和转角是否保持净空、不同随机房/短通道密度、暖光是否过亮，以及离场后有无残留。背向镜头的墙面有意不挂；灯光不含物理遮光，复杂近邻墙的光晕观感尚待实机确认。设定里关闭局部辉光时，暖光隐藏但燃烧火焰保留。
