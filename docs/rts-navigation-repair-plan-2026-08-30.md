# RTS 寻路与墙塔通行修复计划

> 发布状态：本文记录共享开发区的完整导航方案/实现；2026-08-30仅独立近战遮挡与紧凑方阵已纳入发布提交。完整导航因未入库的驻守/墙体移动接口依赖暂缓，详见[rts-publication-2026-08-30.md](rts-publication-2026-08-30.md)。

## 范围与契约

修复指挥模式移动、追击、上/下楼梯、墙顶和塔楼通行。玩家仍由 PlayerRtsController 输出意图，士兵仍由既有 AI 与 MovementSystem 执行；不改武器、伤害、索敌评分、建筑占格、存档和固定 EXE。保留其他会话改动。用户授权制定计划后直接实施；本轮不运行测试、构建、lint、浏览器或游戏。

## 实施顺序

1. 预览与命令隔离：鼠标只做结构/能力可达性判断，不创建、推进或取消正式路线；正式下令保留 pending/complete/unreachable/search_limited。
2. 在途搜索保护：完成缓存与活跃查询分别管理；活跃任务不可因 LRU/TTL 被清除。容量满时新任务等待，取消、死亡、换令后释放；预算不增加。
3. 执行与终态统一：玩家接入同一分帧完整路径查询；士兵显式攻击的移动段也不允许无路直冲。失败绑定原始命令/战术任务，Shift 可续行。拥堵重试只累计连续失败，有效路程进展恢复重试额度。
4. 地面与高架接通：在现有地面搜索图上接入楼梯端点、墙顶节点和真实连接边，支持地面→楼梯→墙/塔→楼梯→地面及多段连接。地面段继续验证完整 footprint，楼梯段继续使用原 FIFO 和物理切面；返回路线分段执行，不把高架线段交给地面碰撞寻路。
5. 墙塔目标统一：拾取只说明目标承载面，是否需要楼梯由单位当前面判断；投影后的 XY、Z、wallId 同源。驻守终点排除墙塔高差接缝，保留经过接缝的通行，不修改墙塔高度和 footprint。
6. 局部调用链与真实差异核对，记录实际实现边界与人工验收清单。任何资源不足只报告搜索受限，不声称目标绝对无路或连续空间绝对最短。

## 性能与玩法边界

- 复用现有 Finder 帧预算、分片、调度队列和有界缓存；不按士兵×楼梯组合启动无界同步 A*。
- 高架连接图按拓扑、单位半径与圆心偏移缓存，增量构建；格网搜索仍校验起终点连接和地面格边。
- 跨高度通行边采用真实折线路程作为非负成本，不能把同坐标的地面和墙顶合并成同一节点。
- 无路和等待停止主动行进；击退、技能动作、楼梯安全退出保持优先。终点方阵保持独立槽位，途中不加刚性队形。
- 显式攻击失败终止当前任务，不自动修改索敌规则去选另一个敌人。

## 人工验收（本轮不运行）

- 长墙镜像目标、U 形墙、多门常锁/自动切换；无路停止且 Shift 下一项执行。
- 上墙规划中持续移动鼠标到另一面墙；原命令不得被预览重置。
- 单兵/混编/主角上墙、上下梯对向队列、梯中改令、楼梯拆除后的安全退出。
- 已在墙上时拆掉唯一楼梯，仍可沿同一墙链走向塔楼；地面单位应被拒绝上墙。
- 塔楼四边接入、接缝点击、多个驻守槽、塔楼占满、墙塔拆除后的原受控落地。
- 两侧楼梯连接的封闭墙：地面目标可经墙顶跨越；多个墙链的组合仍不能跳跃/穿墙。
- 移动攻击遭遇隔墙敌人、指定攻击、追击移动目标、主角失败后 Shift 续行；攻击建筑/锁门时接近外侧，主角长路线追击不周期性倒退到入口。
- 24/100 人复杂冷查询：已开始的搜索持续推进，等待者不抢占清掉在途结果；观察真实耗时，不能以本轮代码核对代替性能验收。

## 实施记录

- 游标改为只读结构判断，不再调用按单位保存状态的成本查询。无楼梯的墙面仍能拾取，由单位当前位置决定能否前往；投影后同步目标高度。墙塔高差连接面不再分配永久驻守位。
- `CommandRoutePlanner` 保留活跃请求，容量满时新请求等待；完成/换查询/取消后释放，普通结果仍有界缓存。楼梯与地面网格的连接检查共享缓存，拓扑变化清除。
- 新增 `command-transit-graph.js`。高架图按墙邻边和楼梯线性组装，不枚举楼梯对；地面与高架节点不同键。反向成本搜索可以通过多段楼梯/墙顶/塔楼连接，再把输出拆成入口地面路径、高架节点、独立出口和下一地面路径。
- `PathManager` 同时支持玩家控制器命令归属，追击目标小幅移动保留正在计算的路径；实际移动进展恢复拥堵重试额度。清晰的短距离路线先尝试验证直达，避免等待整张高架图构建。
- 玩家保留原意图/武器执行器，改用调度队列中的完整指挥路径，取消760px直线中继；失败发布完成记录，队列继续。玩家地面拐点减速，失效/等待路径不输出前进意图。
- 士兵显式攻击的移动段接入严格路径，停止攻击/施法不计拥堵；共享高架清理入口保留同一攻击命令的地面搜索，结束/换令仍清理，无需修改各兵种决策。失败绑定原战术任务，UI同时观察玩家、士兵移动和攻击失败。
- 主角已有高架追击路线交给共享控制器按拓扑和进展重算，不再每400ms归零。攻击目标中心属于硬障碍时，分帧采样最多12个外侧接近点，交完整成本查询选择可达侧，不修改战斗目标或伤害范围。

### 实际限制

- 新的地面借道高架图覆盖正式方块墙、城墙塔及其楼梯，沿用现有承托几何与30px单位准入；旧式非方块墙仍使用已有表面规划接口。
- 地面借道高架按格网/实际折线长度计费；目标上墙/下墙仍保留原入口队列惩罚。不是对未来FIFO等待时间的精确预测，也不承诺连续空间绝对最短。
- 建筑攻击的外侧候选沿用360px投影范围，每方向保留首个开放点；超大或封闭目标可能仍需调整命令。接近点仅解决移动合法性，能否出手仍由原战斗判定负责。
- 搜索数量、驻留节点和缓存仍有上限；40px地面网格不能保证表达所有极窄入口，资源/精度不足报告搜索受限。帧预算为软截止，单个几何查询和最终路线拆分可能跨过截止点，但耗时继续记账，未提高原配置预算。
- 仅查看本轮实际差异和必要调用链。未运行测试或运行时验证，按约定由用户测试；未构建、发布或启动固定EXE。

## 三项复审修复（2026-08-30）

- **近战隔墙停步**：新增 `src/combat/melee-reach.js`，将同层判定与现有墙体遮挡检查组合；盾卫、民兵、战士的普攻接近/起手/命中复查统一调用。高架攻击保留当前承载墙忽略规则，攻击结构只额外忽略目标本身；不改距离、伤害数值、挥击时钟和战士横扫筛选。三个兵种AI仅改这些调用点，保留其他会话已有改动。
- **超时重新选梯**：`elevated-navigation-controller.js` 区分 `restart` 与 pending 续算；超时和失败后的重试递增规划代次，使已有 `costedSurfaceRoute` 重新冻结入口成本，正常跨帧轮询不重启。FIFO超时记录实际入口组，在原队列成本上临时增加4倍入口成本（默认720，至少6000ms后失效），不硬封禁唯一入口。`defense-system.js` 与 `command-transit-graph.js` 同步将该非负成本纳入地面借道图及缓存键；移除承载面/转场、拓扑变化和过期会清理或忽略记录。保持原预算、FIFO许可和缓存数量上限。
- **追击目标换层**：跨墙借道路线保存真实语义目标身份和高度快照，复用时同时检查目标身份、承载面/墙或楼梯组、高度差（12px）及平面距离。目标换层时取消旧路线；追兵已在梯中时仍先执行原方向安全出口。

### 本次人工验收重点（未执行）

1. 盾卫/民兵/战士与目标同层、平面距离在攻击范围内但隔着墙或锁门：有路则绕行，无路则按既有失败终态停止；开门后重新下令恢复正常接敌。无遮挡普攻、同墙顶近战、战士横扫和防暴队继承行为不变。
2. 两个可达楼梯入口之一完全堵塞直至排队超时：重新比较替代入口；只有一个入口时仍允许重试。长队持续前进不能误判超时，梯中单位不能失去方向许可。
3. 地面跨墙追击途中，目标在48px内上梯/登塔/下楼或切换承载面：旧借道路线失效，重新追击；追兵在梯中先安全离梯，不瞬移。

本次只查看真实差异和必要局部调用链，未运行测试或运行时验证，按约定由用户测试；未构建、同步或启动EXE。临时拥堵成本是玩法启发式，实际等待时间与绕行距离的权衡仍需实机验收。
