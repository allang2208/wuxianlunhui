# 恐怖地牢地标路线界面升级（2026-08-29）

## 范围

- `zombieDungeonBeginner`、`zombieDungeonMid`与`zombieDungeon`三档（界面名称“恐怖地牢”）统一启用`mapPresentation:"landmark"`。
- 路线直接覆盖在全屏哥特场景上，不再把画面切成上方背景、下方作战板。
- 左侧原尺寸组队栏与右侧原尺寸栏位图标是硬安全区；地图布局只能避让，禁止反向调整旧面板。
- 冰原、沼泽继续使用既有背景和显示合同；矿洞三级另按`docs/dungeon-mine-landmark-ui-2026-08-30.md`接入独立平台/楼梯模板。

## 美术资产

- 正式资产：`assets/scenes/dungeon-map-horror-landmarks/`下五张静态背景，依次为城塞、淹水教堂、墓园城塞、检疫铸造堡和疫城墙垣；旧`assets/scenes/dungeon-map-bg-horror-landmark-v3.png`继续作为配置回退。
- 生成记录：`tools/ai-gen/dungeon-horror-landmark-background-set-20260830.json`
- 生成方式：内置 ImageGen，五张均为1672×941固定镜头，生成无文字、无图标、无节点、无路线、无面板的16:9环境图。
- 构图合同：每张提供六段从左到右的可行走结构和清楚分开的上下地形带；左侧274px、右侧104px、顶部信息区和底部索引区继续作为运行时安全区。
- 显示合同：背景等比居中cover，只允许按视口裁切装饰边缘，禁止非等比拉伸。节点、线路和情报卡全部由运行时叠加，不能回烘焙进背景。
- 旧`dungeon-map-bg-horror-cold-steel-v2.png`是正式地标母图生成清单登记的直接编辑参考，保留来源链及旧40/60回退用途；当前三级路线不加载它，不视为未选废案。

## 长路线方案

- 房间生成、节点坐标、迷雾、边与可达规则保持权威；地标背景只是承载层。
- 每4个生成列归为一个区段；聚焦态只显示本区段及前后各一列接头，避免几十个房间同时缩成不可读的小点。
- 五张背景分别登记原始像素锚点、HUD安全边界与拓扑偏好。单局地图生成后，以分支密度、最大单列节点负载、同列连接占比和行跨度计算加权距离，选择最近模板；路线指纹只作稳定破同分，因此同一局往返路线页不会跳图。
- 总览最多每行显示8个区段，超出后蛇形折返；总览只暴露区段进度、玩家区段和入侵者区段，不泄露迷雾房型。
- 底部使用细线区段索引；上一段、下一段和区段编号只改变查看窗口，不移动角色。
- “战略总览/返回当前位置”保留为区段索引右侧的小型原生按钮，不建立额外行动指令栏。

## 顶部信息布局

- 左上：地牢名称、地标路线标题和探索进度；生命/魔法/等级状态栏继续使用既有页面根层顶部居中位置与原尺寸，不纳入地标指挥层缩放。
- 左侧情报栈：预期奖励在上、特工入侵提示在下；组队栏只在恐怖地牢路线模式下移动到情报栈之后，三者不重叠。组队栏尺寸、内容和地牢外位置不变。
- 右上：安全撤离和放弃并返回纵向排列，继续复用原按钮语义、确认流程与显隐时机。
- 右侧栏位不改尺寸、位置、间距或图标规格；经济、时钟和常规战斗HUD在路线页继续隐藏。

## 节点与交互合同

- 节点继续使用切角冷钢外壳；已走路线为青灰实线，可前往路线为银青流动虚线，当前不可到达路线改为黑铁槽底、锈红断续线与中点阻断叉，便于提前规划且不改变可达判定。
- 地标模式为正式1920×1080背景登记六段结构锚点带，覆盖左下桥廊、中央门厅与阶梯、上层城堡和右侧塔门；当前区段的列与分支行只投影到这些展示锚点，路线与背景共用同一cover矩阵，因此1080p、2K和裁切视口下不会漂离地标。生成器节点坐标和边不修改。
- 起点、普通战斗、精英战斗、随机事件、首领、奖励和未侦察分别使用`assets/ui/dungeon-map/cold-steel-v2/`下的透明冷钢徽记；节点外壳、状态环、选中光和迷雾透明度仍由运行时绘制。
- 地标徽记由原18～34px范围放大为24～44px，接近填满节点内圈，但不扩大节点外壳、点击半径或状态环。
- 同一生成列因宝箱岔路出现密集节点时，展示层按结构带长度计算2～4条平行小轨和每轨纵向槽位，优先使用完整结构带展开；随后对当前聚焦区段全部节点做最多12轮、受母图安全区限制的确定性消碰撞，目标母图中心距至少72px。节点较少的列继续保持单轨，不缩小徽记或选择圈。
- 可前往节点悬停时，在节点附近显示冷钢档案卡：节点编号、类型、危险等级、现场线索、预估收益和“进入节点”。
- 直接点击节点与档案卡按钮都必须经过`isNodeClickable()`，然后复用既有`_enterNode()`；不改变奖励、入侵、迷雾、岔路或完成状态。
- 档案卡只显示现有配置和运行态推导信息，不新增玩法判定；非地标地牢继续使用旧轻量悬停提示。
- `#dungeonRouteControls`与`#dungeonRouteTopHud`均带结构版本，热更新或同页重入发现旧结构时先销毁再创建。
- 区段聚焦失败只能降级路线表现，不能阻断`DungeonMapSystem.init()`或删除导航入口。

## 验收重点

- 三档恐怖地牢均从五张静态全屏地标背景中按路线拓扑稳定选择一张，没有旧黑色网格或40/60金属板；同一局返回路线页不换背景。
- 路线沿左下桥廊、中央阶梯、上层城堡和右侧塔门结构展开；切换区段后仍使用同一组背景锚点，左侧奖励、入侵提示和组队栏纵向排列，组队栏只改变路线页位置、不改变尺寸；右侧栏位图标保持地牢外的位置和规格。
- 标题/进度、奖励/入侵、生命魔法状态栏、撤离按钮互不遮挡；状态栏保持原位置和尺寸，离开起始点后安全撤离按原规则消失。
- 悬停可前往节点时档案卡不出屏，移动到卡片和点击“进入节点”可用；直接点击节点仍可进入。
- 主路线与上下宝箱岔路的徽记、外框和呼吸环互不覆盖，密集列拆轨后仍保持row顺序与原连接关系。
- 不可到达线路的锈红断续线和阻断叉应明显区别于银青可前往线路；状态只随既有`getAvailableNodes()`变化。
- 区段切换、战略总览、返回当前位置、跨区自动跟随、几十房间蛇形总览、迷雾和入侵者区段标记正常。
- 重点检查1920×1080与2560×1440；窄屏只允许新路线UI降级，不得改动旧组队栏或右侧栏位。
