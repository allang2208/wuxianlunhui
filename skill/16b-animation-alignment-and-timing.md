# 动画尺寸、位移与攻击接触统一合同

适用于新增、替换或优化的所有角色动画：怪物、军事友军、工人/平民、侍从，以及共用精灵图管线的玩家/NPC。按本次实际涉及的动作执行，不因改工作流而批量重做现有角色或改变平衡。独立模型、武器分层和非战斗动画同样遵守尺寸/锚点规则，但不虚构攻击判定。

## 1. 先登记基准，再生成

每个角色维护一份最终 manifest，至少登记下列内容。双份配置、Boot、实体、AI和面板是其消费者；没有自动导入器时逐项同步，不能声称已自动生成。

| 分类 | 必填内容 |
|---|---|
| 来源 | 用户接受的母图/原动画、直接编辑祖先、参考角色、视频/提示词/provenance、准确截取区间和关键帧索引 |
| 体量 | 基准角色、有效躯干高度、源到世界的固定比例、正常/最大镜头下的可见像素、用途档位 |
| 布局 | 每动作帧宽高、列行数、有效帧数、endFrame、固定裁框、原点/脚点/referenceCell、镜像轴 |
| 运动 | 循环/单次、代码位移或表内位移、地面脚点/悬浮轨迹、死亡末帧与尸体策略 |
| 时钟 | 总时长、逐帧停留或阶段时长、0-based接触/发射/声音/装填帧、有效窗口、攻击间隔语义 |
| 判定 | 身体Collider、投射物受击体、接敌距离、接触伤害区域、碰撞中心与视觉根点的关系 |
| 接入与证据 | 纹理/动画键、配置与兜底入口、驻留/召唤依赖、正式GIF、已执行检查、未验证项 |

制作前看当前配置、近期相关提交和实际素材。视角按已认可的同类角色：四足优先参考四足，骑兵/器械分别标定。朝右不等于纯水平侧视，不用文字中的任意俯视角覆盖已批准参考。

时代装备互换时，正式动作表和图标仍写回各兵种自己的资源路径；先核对动作布局、帧数、脚点和显示比例，再替换资源。美术换装与战斗数值分开提交，除非用户另行明确授权，不能因为装备时代更先进就顺手改生命、伤害、范围或速度。

## 2. 尺寸一致：统一主体比例，不统一占满画布

- 按躯干/有效身体高度标定，排除细长武器、尾尖、翅尖、背刺。不同动作的身体比例相同，抬手、蹲伏、飞扑产生的轮廓变化必须保留。
- 所有动作共用源像素比例；一个动作全部帧共用一个裁框。宽动作扩大帧格或按动作紧裁，不逐帧按Alpha框fit，不独立把攻击动作放大到“看起来满格”。半透明翅膀、武器与自然运动不能被裁掉。
- 显示变换必须还原到同一世界尺度：`世界长度 = 源长度 × 源缩放 × 运行时缩放`。有`referenceCell/footRatio/frameLayouts/scale`时按真实渲染分支换算，不能只核对`spriteSize`一个字段。明确先后顺序，防止配置与实体各乘一次。
- 无明确美术设计时保持X/Y等比，不用非等比拉伸补视角或裁框错误。用同一姿态的躯干标志点核对比例，不能用运动中变化的Alpha宽高比当人体伸缩证据。
- 逐项核对首次创建、贴图切换、待机↔移动、攻击↔待机、变身、死亡和重载；任何一个入口重设`displayWidth/displayHeight/origin`都可能使切换时放大。只修本角色相关入口，不扩展全局行为。
- 用户要求“体型和碰撞放大20%”时，长度、半径及相对根点的偏移统一×1.2；面积/体积会按平方/立方变化。分别核对Collider实际读取的半径/高度、投射物受击框及专属接触区，不能只改调试框。仅优化贴图分辨率时，世界体型和判定保持不变。

## 3. 根点与运动：分清画布、屏幕、地面和高度

- 同角色各动作保持同一逻辑根点及镜像轴；按固定裁框换算`footX/footY/origin/footOffsetY`，脚点不能误用画布中心。裁掉顶部/侧边后要换算锚点，不能只换PNG尺寸。
- 分别登记素材内部位移、Sprite显示偏移、实体/Collider世界位移、Z高度和透视投影。地面效果跟随Collider，空中效果跟随实际视觉挂点；不把屏幕Y当世界高度或用阴影偏移掩盖根点错误。
- 默认不得逐帧缩放、Alpha居中、脚底拉齐或几何拉直已接受动作。地面角色观察支撑脚与躯干根点，飞行/悬浮/坠落保留自然升降；RIFE此类动作使用`--preserve-vertical-motion`，禁止用最低翅尖当脚底。
- 飞扑/冲锋先确定唯一位移源。代码移动Collider时，素材应有原地推进姿态；确需表内位移则显式描述其与逻辑轨迹的配合。发现双重前冲、回待机跳位，先追两套位移，不靠反向Tween补偿。已批准自然轨迹有冲突时单独修正或重新出候选，不静默拉直。
- 左右翻转围绕同一个根点；攻击中按已提交方向播放。只有左右源图时，不声称已支持任意方向像素级接触；上下/斜向通过游戏透视下的判定与可读性验收，必要时补方向素材。

### 石化冻结与独立长武器层

- 石化保留的是实际Sprite已显示的纹理、帧和翻转。逻辑取消攻击可能先把状态改成idle，冻结渲染却仍留在attack；此时按逻辑态重算footOffset会使身体跳位。保存冻结姿态，并用实际纹理对应的frameLayout及实际scale恢复脚点；死亡覆盖冻结，解除控制不补发旧命中。
- 长鞭等超出人体画格时可独立成层：保留固定比例的人体，武器挂点、锁定方向、接触时间与判定共用数据。独立层的视口裁剪范围、深度/遮挡、迷雾、控制冻结、死亡和切场清理须接齐，不能通过放大人体或伤害盒容纳武器。
- 原AI鞭被独立曲线替代时明确标注来源；它不再是原视频轨迹。仅有侧向身体源时说明上下方向共用人体，离线方向投影图不能替代实机验收。

## 4. 插帧与循环

- 从未插帧关键帧做一次2×RIFE，保留源帧索引映射。循环N→2N并处理末→首；单次N→2N−1、不回绕、不用倒放死亡或硬冻尾替代完整收势。
- 插帧不等于加速。沿用获准总时长、阶段节拍与尾帧停留；单次动作少一个间隔时必须明确末帧停留，不能只把FPS翻倍后默认时长完全相同。
- 检查全部有效帧、透明RGB、边缘/翅膀Alpha、奇数帧黑块/异常重影、原关键帧位置和循环接缝。运动连贯度不能只靠帧数、Alpha框或平均差值证明。
- `frameCount/endFrame`仅包括有效帧，正式PNG宽高必须整除帧宽高。待机和移动复用一张表时保持单个纹理键，不加载重复副本。
- GIF必须使用最终运行时时钟；GIF的10ms量化按累计时间取整，避免64帧×30ms误写为2秒。预览标注时长、倍率和是否为制作示意；离线对照不是游戏截图。
- 浏览器安全的精确预览可按20ms时间片从同一逐帧时钟采样；分别记录源帧数、预览采样帧数和运行时动作时长，不能把预览帧数误写为精灵表帧数，也不能让GIF编码器自行重定时。

## 5. 攻击距离与接触时机必须一起标定

1. **分类**：普通单体近战、连击、范围/位移、远程/施法、持续接触各用原有合同。一种攻击只有一个伤害源；无攻击动画的虫群不能为了1.5秒标准强加普通挥击。
2. **选姿态**：按实际显示比例、脚点、镜像和攻击态变换，找手/爪/口器/武器的真实接触帧或枪口/施法释放帧。排除尾随残影、收刀最远帧和透明边，不用动作50%猜命中。
3. **量距离**：从实际Collider中心经源→世界→地面投影量取。身体受击体、AI接敌距离、攻击伤害区和武器长度分别维护。目标footprint仅计一次；不能放大身体或伤害区来掩盖空挥。
4. **锁定与复查**：起手快照原目标和方向；命中时复查目标有效性、同层、形状和墙体。普通近战走`melee-attack-resolver.js`，友军接其现有统一近战入口；自管技能不得额外触发通用普攻。远程按释放帧产生弹体，以真实弹道命中结算，不能在出膛时直接扣远处目标血。
5. **同一时钟**：动作播放、AI前后摇/锁定、命中窗口、出膛/音效、控制打断和死亡取消共用一个推进源。事件用跨阈值触发并按动作序号/段号去重，不能依赖恰好看到某一帧，也不能用两个独立计时器各结算一次。
6. **技能边界**：多段连击逐段登记窗口；位移攻击按实际扫掠；范围逐目标复查；持续接触保留自身间隔。眩晕/死亡/切状态后未发生的事件必须取消，尸体不得继续攻击。
7. **确认配置被消费**：写入 `basicMelee.timeline` 只是声明，不代表派生怪物会走通用有向近战。使用 `Enemy` 派生类时必须显式设置 `basicMeleeResolver: true`，或由该类明确把 `_usesDirectedBasicMelee` 设为真；交付前沿 `MovementSystem → CombatSystem → Attack` 核对实际消费者，不能只看 JSON 字段存在。
8. **目标体积只计一次**：`impactReach` 从攻击者实际根点量到武器/爪/口器的可见接触前沿，目标 collider/footprint 由形状相交阶段另行计入，不能再把目标半径加进 reach。`attackRange`、`attackDistance` 与 `approachReach` 同步，`impactReach/width` 则按接触帧独立收口。

非均匀攻击节奏只有一个逐帧时长源：配置中的`frameDurations`既要被Phaser动画帧消费，也要由AI按命中帧之前的前缀和计算伤害延迟，并按总和计算动作锁；攻击间隔继续独立表示起手到下次起手。任一消费者仍按平均FPS时，预览、画面、命中和待机衔接就会再次分叉。

## 6. 偏慢普通攻击以约1.5秒为调整目标

- 适用于本轮制作/升级中偏慢、没有专门蓄力设计的普通攻击；先看同类已认可单位。目标为约1500ms完整出手动作，保留清楚的前摇、接触和收势，记录具体时长。已更快且合理的动作不减速；重蓄力、Boss预警、装填、多段技能、持续接触与死亡不机械套用。
- 用总时长控制速度。等时帧按`FPS = 有效帧数 / 动作秒数`；有阶段/逐帧停留时显式重分配。RIFE后原事件帧k映射2k，最终裁帧后再次登记，不保留旧帧号。
- 加速时同步重算接触/声音/释放事件时间、有效窗口及AI动作锁；均匀加速的事件时间按`新总时长/旧总时长`缩放。逐帧时间以进入事件帧前的累计停留为准，不能混用`N/FPS`与`(N−1)/FPS`而遗漏尾帧。
- 攻击间隔另行记录是“起手到下次起手”还是“结束后再等待”。不能把1500ms动作再叠加1500ms等待造成3秒周期，也不能只提FPS却提前下一次结算、漏掉装填或提高DPS。视觉提速不自动授权改伤害、攻速属性、全局AI或平衡。
- 若用户同时授权改变攻击间隔，明确给出新周期、每段伤害和DPS变化，同步前台面板与后台估算；攻速Buff仅推进一次。`aiInterval`是调度/决策间隔，不代替动作总时长或攻击冷却。

## 7. 接入核对与交付

| 层次 | 必查项 | 证据/边界 |
|---|---|---|
| 源与成品 | 原图可追溯；关键帧映射；有效帧/Alpha/接缝；比例及锚点 | 全动作GIF、关键姿态图、实际像素报告；不代表实机通过 |
| 配置与代码 | 双份JSON；Boot切帧/FPS；渲染比例；实际Collider；事件时钟/冷却；兜底/父类；驻留依赖 | 只核对本次修改和必要调用链，区分声明与实际消费字段 |
| 状态切换 | 待机↔移动、移动→攻击、连续攻击、打断、死亡/尸体、变身/召唤 | 无尺寸跳变、双重位移、错纹理、旧事件或动画重启 |
| 战斗实机 | 贴脸、极限接敌距离、横向擦边、目标后撤、墙/门/高台隔断、长帧跨窗口、左右/斜向 | 无吸附命中、身后伤害、重复/漏判；距离和时机与姿态相符 |

按AGENTS执行授权：明确要求检查素材时可做对应离线素材检查；“检查一下”不自动授权启动游戏、测试、构建或浏览器。未经授权的实机项目列为待用户验收，不把静态或预算通过说成“所有动画状态已测试”。

预算按PNG解码尺寸×4及实际纹理键依赖闭包计算，不能按磁盘文件大小。普通量产角色目标32MiB、超过64MiB需明确例外；少量特殊角色64/128MiB，Boss128/256MiB；不得改变全局预算掩盖超限。同动作共享键只计一次，保留原生清晰度导致超目标时说明成本。本文没有新增运行时缩放或全局1.5秒设置。

## 8. 废案与提交收口

- 只清理可确认由本任务产生且不再被正式输入链使用的内容；先列具体路径/字节/原因。获准母图、直接编辑祖先、当前未插帧源、正式PNG、最终GIF、报告和精确制作参数保留。
- 未选母图/视频、大批逐帧缓存、重复成品和过时时钟预览移出活动目录；默认可恢复移到Git忽略的`tools/.trash-<task>/`。历史元数据标记已停用/移除，不留下活动假链接；清理不顺手停止其他生成任务。
- 蓝边修复只处理Alpha轮廓附近的窄带溢色，并对正式四动作逐帧复查；板甲、钢剑本身含蓝灰色，不能用整幅“蓝色像素数”阈值大范围改色。保留修复报告与关键姿态证据，确认窄带残留为零。
- 清理时保留获准母图→关键帧→最终源片→未插帧源表→正式表/GIF的可重建链；被拒视频二进制可删除，但其提示词、供应商任务JSON和拒绝原因应保留。`__pycache__`、可重建逐帧缓存和重复时钟预览不进入Git。
- 正式输出仅一个活动位置；重建脚本改读保留输入。当前共享工具版本尚未入库且会改变像素时，保留本资产实际使用版本的快照/版本号，不能把别人尚未完成的整套工具修改混进提交。
- 遵守第15卷：独立分支/worktree、精确文件或代码块、两份配置一起提交、真实diff/暂存区核对。清理缓存不等于删除未追踪文件；不得`git clean`、全仓`git add -A`或强推共享主线。
