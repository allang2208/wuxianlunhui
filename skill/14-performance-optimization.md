# 14. 性能优化与采样

> 本分卷是 Phaser 运行时性能工作的统一入口。具体业务契约仍以对应分卷为准：
> 结构阴影见 `06-dungeon-scene.md`，位面后台化与世界系统见
> `07-world122-defense.md`，寻路预算见 `08-pathfinding-movement.md`，Phaser 4
> 渲染陷阱见 `12-pitfalls-debug.md`。

## 14.1 优化铁律

1. **先采样，再改动。** 同一场景、相机、单位数和画质下做 A/B；至少观察平均值、
   P95/P99、峰值和慢帧样本，不能只看一次 FPS。
2. **先拆清 CPU 与帧间隔。** `requestAnimationFrame` 帧间隔包含浏览器调度、GPU
   提交等待、合成和垂直同步；已测 JS 分项之和只是主线程已埋点部分，不能冒充整机 CPU
   或 GPU 占用。
3. **先处理最大且可解释的分项。** 优先级通常是持续高耗时提交 > 周期性尖峰 >
   高频小分配/小查询；没有报告证据时不做大范围“预防性优化”。
4. **视觉裁切不得改变模拟。** 相机外可停止同步 Sprite、HUD、粒子和阴影，但不得据此
   停止 AI、战斗、碰撞、寻路、经济、迷雾、小地图或存档推进。
5. **优化必须保持降级路径和正确性契约。** 预算耗尽不是失败，后台位面不是删除，
   近似计算必须能在事件、切回或存档时确定性结算。
6. **配置真源保持双份同步。** `data/performance-config.json` 与
   `public/data/performance-config.json` 必须一致。

## 14.2 性能面板与报告判读

### 采样入口

- `src/systems/performance-monitor.js`：帧窗口、CPU 分项、计数器和慢帧样本。
- `src/ui/panels/dev-tools.js`：交互开发面板“性能”页与 Markdown 导出。
- `data/performance-config.json` / `public/data/performance-config.json`：采样、裁切和预算配置。
- `src/game.js`：逻辑主循环、旧 Canvas 与 DOM UI 埋点。
- `src/phaser/scenes/GameScene.js`：Phaser 同步、阴影、实体/HUD 可见量等埋点。

### 报告必须包含

- 采样帧数、实际持续时间、平均 FPS。
- 帧耗时与原始帧间隔的平均、P50、P95、P99、峰值。
- 已测 CPU 分项的平均、P95、峰值和周期累计。
- 当前快照计数器：实体总量/可见量、寻路队列、阴影投射体、顶点、三角形、命令数、
  重建次数与重建耗时。
- 最慢若干帧及其主要分项，便于判断“持续慢”还是“周期尖峰”。

### 判读约束

- CPU 排行中的百分比只表示**已测分项内部占比**，不代表系统任务管理器占用。
- `counters` 默认是导出时快照，不是采样窗口平均值；比较前要保证场景状态相近。
- `frameCost` 是已埋点工作耗时；`rawFrameGap` 才能反映用户感知帧间隔。若前者低而后者高，
  优先检查 GPU/合成、浏览器调度、显示同步或未埋点区域。
- Phaser 各阶段必须互斥计时，避免父级 `phaserSync` 与子阶段重复计入总 CPU。
- A/B 开关实验只改变一个变量，例如“太阳移动+结构阴影开/关”；单位、相机、UI 和采样窗口
  同时变化时，结论只能视为线索。

## 14.3 视口裁切

### 正确做法

1. 基于 Phaser Camera `worldView` 计算可见矩形，并按系统需要加入 padding。
2. 只跳过纯视觉同步：Sprite、名字/血条、粒子、结构影命令等。
3. 迷雾仍是最终显示门禁；视口内但处于战争黑雾的对象不能因性能裁切而泄露。
4. 镜头快速移动、缩放、场景切换和实体重新进入视口时必须完整恢复视觉状态。
5. 输出 `visibleEntities` / `culledEntities` 等计数器，验证裁切是否真正命中。
6. 同一 Phaser 帧内 HUD、Sprite、阴影和附着层可复用实体可见性结果，但缓存键必须至少包含
   帧代次、实体坐标和当前 Sprite；无 Sprite 的首帧实体不得缓存，防止创建贴图后半径变化造成边缘误裁。
   缓存只省略重复的视口几何计算，不能省略迷雾终态门禁或改变实体模拟。

### 禁止做法

- 不得把 `active=false`、AI 休眠或移出空间分区绑定到“当前镜头看不到”。
- 不得用 HUD 是否可见决定实体是否参与碰撞、索敌、战斗或小地图。
- 不得把裁切矩形做得过紧；阴影、长武器、弹道和大体型对象应按可达范围扩张。

当前结构阴影视口外扩契约为 `shadowPaddingPx: 64`。普通实体沿用 World-122 已有的
视觉裁切外扩；不同系统不可未经采样直接共用同一个 padding。
`renderCulling.reuseVisibilityWithinFrame` 控制帧内复用；性能计数器必须暴露检查数、命中数、
未命中数和命中率，便于确认优化是否覆盖了真实重复调用。
持续可见且从未被视口隐藏的实体可通过 `renderCulling.skipStableVisibleWrites` 跳过整套 Sprite/HUD/阴影
恢复遍历；屏外实体仍须刷新隐藏状态，以保证屏外新建的附着层不会泄露。记录对象应使用无临时数组的
自有属性遍历，避免 `Object.values(...).forEach(...)` 在单位量增大时制造逐帧短命分配；迷雾仍保留最终裁决权。
每帧用于“本轮仍活动”的暂存 `Set` 应由对应渲染子系统持有并在入口 `clear()` 后复用；HUD、单位阴影、
状态附着层、无人机锁定、结构阴影、中立实体和防御塔不得反复 `new Set()`。合并队伍成员与世界友军时
分别遍历两个真源并用复用的去重集合仲裁，禁止用数组展开先复制出一份全量友军列表。同步暂停的地图模式
必须主动清空这些集合，不能让性能缓存反向延长旧实体生命周期。
队伍成员与世界友军若在同一 Phaser 帧内连续被精灵同步、投射物同步和动态深度读取，应以
`renderViewportEpoch` 为帧代次复用“可渲染成员列表、完整成员列表、ID→实体索引”；队伍成员仍按原规则
过滤失活项，世界友军的既有包含语义不得顺手改写。活动 ID 集合和成员对象表的清理遍历也必须复用集合、
使用自有属性 `for...in`，禁止每帧数组展开、`filter()`、`Object.keys()`、`Object.entries()` 和重建 `Map`。
成员源刷新/复用次数及当前列表规模必须进入性能计数器；地图模式等暂停渲染分支要清空缓存引用和帧代次。
动态深度仍须每帧执行脚线、高架、墙体与建筑遮挡仲裁，但最终 Phaser `setDepth()` 只在计算值与对象当前
`depth` 不同时提交；禁止以缓存旧深度代替本帧几何计算。玩家、敌人、友军、武器附着层、魔法、无人机和
中立单位附属层应共用同一提交守卫，并输出每帧/累计真实写入与冗余跳过次数。直接遍历 Phaser Group 的
`getChildren()` 返回值，禁止为只读遍历额外使用数组展开复制。
迷雾隐藏实体/特效的每帧强制执行不能删除，因为其他渲染子系统可能在两次 10Hz 可见性判定之间重新显示对象；
`FogVisualAdapter.setHidden()` 应保留 `_fogRestoreVisible` 语义，但仅在当前 `visible` 与目标值不同时调用
`setVisible()`。累计真实写入和冗余跳过次数必须进入性能计数器，不能用“减少判定频率”冒充这项优化。
迷雾调试覆盖层关闭时，必须在构造 `getFogDebugModel()` 之前返回；禁止默认游戏每帧枚举全部跟踪特效和
视野源，只为了让关闭状态的调试 UI 在其内部再次返回。

## 14.4 实时太阳与结构阴影

### 已验证的爆卡形态

连续太阳移动会不断令静态建筑阴影变脏。若每次更新都对所有投射体重新求轮廓、生成大量
扫描线顶点、逐多边形调用通用填充，并且每个投射体还持有独立渲染对象，会同时放大：

- CPU 几何重建尖峰；
- WebGL 三角形和绘制命令；
- 对象遍历、显存与提交成本；
- 相机外完全不可见阴影的无效工作。

用户同场景 A/B 曾定位到开启太阳移动和阴影时 Phaser 同步为绝对主因；第一轮结构优化后，
用户报告从约 49 FPS 提升到约 144 FPS。这个结果证明优化方向有效，但它是当次场景证据，
不是所有设备和场景的固定基准。

### 当前结构契约

1. 每个静态投射体只保留**非渲染句柄**；统一由结构阴影层绘制，禁止为每栋建筑常驻一个
   空 `Graphics` / `Sprite`。
2. 先用投射体包围盒、太阳方向和最大影长做保守相交判断；确定阴影不可能到达扩张视口时，
   在求轮廓前剔除。
3. 轮廓以精确扫描线结果为输入，再对左右单调边界做 Ramer-Douglas-Peucker 简化：
   高画质约 `0.35px`，中画质约 `0.7px`；保留端点和窄尖，禁止简化到跨越轮廓。
4. capsule 圆弧按画质使用 8/12/16 段；不要所有质量档固定最高段数。
5. Earcut 三角化只在阴影变脏时执行，结果缓存为 `fillTriangle` 命令；正常帧只重放命令。
6. 多结构影先做同层并集，再绘制内收羽化；禁止为每个投射体单独上滤镜或外扩描边。
7. 保持太阳方向连续变化。禁止用角度档位、预烘焙阴影或固定超大离屏画布偷换视觉契约。

### 必须导出的阴影计数器

- 总投射体、视口前剔除、几何后剔除、实际绘制投射体；
- 原始轮廓顶点、简化后顶点、三角形、渲染命令；
- 脏重建次数、最近/累计/峰值重建耗时；
- 阴影层可见状态和画质档。

### 进一步升级条件

- 若稳定帧仍被提交耗时主导，且命令/三角形数量依旧很高，再评估单个自定义 WebGL
  批次、typed buffer 复用；不要先于采样重写渲染器。
- 若平均帧达标但 P99 被重建尖峰拉高，可评估双缓冲或跨帧分批重建；切换期间必须继续显示
  上一份完整阴影，不得出现半成品闪烁。

## 14.5 AI、碰撞与寻路预算

- 大范围碰撞、分离、侧翼和索敌先走空间分区近邻查询；保留无分区时的正确性回退。
- 静态格子成本按 `(格子坐标, 半径)` 缓存；半径不得从 key 中省略。
- `PathWorkScheduler` 当前合同：每帧最多启动 2 次重算、5 次有效性检查，启动门禁 3ms；
  玩家 RTS 保持同步直算。
- `PATH_DEFERRED` 表示预算延后：保留旧路径与任务，下帧重试，绝不能当作不可达。
- 首次寻路错峰、不可达短 TTL、区域失效和 LRU 告警节流必须保留。
- 静态且无行为需求的实体可进入业务定义的 dormant 状态；“镜头外”本身不是休眠条件。

### 大规模 RTS 寻路合同（2026-08-25）

- 超距移动先由 `HierarchicalRoutePlanner` 在 640px 扇区图上搜索门户序列，再把不超过
  700px 的中继点交给细层寻路；扇区路线和门户按拓扑版本、半径桶共享，失败结果短时缓存。
  粗层搜索本身也必须按 `hierarchy.frameBudgetMs` 保存 open/cameFrom/current-dir 状态跨帧续算。
- AI 的细层 A* 必须把建网格和节点扩展保存为 typed-array 作业，`finderBudgetMs` 到期返回
  `PATH_DEFERRED`，下帧以稳定 `requestId` 续算；只在任务开始前检查预算不算硬预算。
- 位面入侵单位使用同目标共享流场：公共路径走廊先提供热路径后缀；走廊外但仍在共享窗口内的单位，
  消费从目标反向扩展的积分 Dijkstra 场并沿 `next` 梯度取路。流场建格与积分扩展同样消费
  `finderBudgetMs`、可跨帧暂停；接入前校验公共终点到本次终点的静态可达性。路径数组继续由
  `PathManager` 防御性复制，局部转向继续由单位自身执行，不是刚性编队。
- 全局路线不得把短时单位拥挤当作拓扑。防御波次的 A*/流场忽略 `DynamicObstacleMap` 成本，
  单位间分离、侧翼、墙体 resolve 和卡住修复继续承担局部转向；静态建筑、墙、树和门成本仍参与规划。
- 不可达缓存分两层：精确格起终点负缓存，以及包含起点扇区的共享负缓存；不得仅按目标扇区
  把一个入口的失败扩散为整个地图不可达。
- 建筑中心投影、`RegionIndex` 阻挡栅格/Flood Fill/原子提交、区域边界出口扫描都属于寻路预算，
  必须在 deadline 到期时返回 `PATH_DEFERRED`；不得在进入 A* 前后留下同步全图扫描。
- 墙/树/掩体 `SpatialHash` 冷重建同样必须按 deadline 跨帧；构建时保留上一份完整索引，
  新索引完成后原子交换。玩家 RTS 同步指令保留直接完成的例外。
- 普通建筑 iso footprint 必须先进入空间索引再参与格子查询；静态 memo 命中/未命中都只能
  叠加一次实体障碍，禁止 `_getCellData` 与 `_buildGrid` 双重扫描。
- 双份 `performance-config.json#pathQueue` 必须同步；报告至少导出 pendingSearches、
  incrementalSlices、hashBuildSlices、projectionSlices、sharedFlowFields/hits/buildSlices、negativeCacheHits、
  hierarchyRoutes/cacheHits/searches/pending/usedMs 与 regionRebuild/exitSearch 进度。细分归因还必须包含
  validation/recalc 当帧、最近与峰值耗时，footprint/dynamicObstacle 同步耗时，以及
  SpatialHash/反向流场的 pending、processedCells、totalCells 和 progress；这些指标只观测，不得改变调度行为。

## 14.6 多位面后台化

非当前位面应从实体模拟切换为**可结算数据包**，但必须覆盖突发入侵、限时事件和玩家切回：

1. 打包人口、兵力批次、建筑产能、库存、岗位、研究/出兵进度、守军战力、位面世代和
   `lastSettledAt`，卸载大部分实体与视觉对象。
2. 常态后台只推进经济账本和少量全局截止时间；收益按离散批次/解析公式结算，不逐单位 tick。
3. 入侵等事件使用固定时间窗的聚合战斗：兵种数量×单兵统计得到阵营 DPS/有效生命，
   每个窗口结算伤亡、建筑损害、资源消耗与下一事件时间。
4. 只有事件边界、存档、玩家查看摘要或切回位面时补结算；不得因玩家正在地牢而把后台入侵
   实例化成完整单位战场。
5. 切回前先结算到当前时间，再按剩余批次数量物化实体；同一位面世代和结算游标保证幂等，
   防止重复收益、重复出兵或重复伤亡。
6. 需要精确交互的英雄、Boss、门和脚本事件可保留少量“特殊参与者”，其余军团聚合。

当前约定：非当前位面常态仅低频检查全局科研/截止时间；入侵按约 10 秒窗口聚合，出兵以批次
推进。调整频率前必须用报告证明后台 CPU 已成为瓶颈。

## 14.7 UI、粒子与 Phaser 4 特效

- DOM UI 按值变化刷新；高频进度显示可节流到约 100ms，并用 CSS/视觉插值保持连续感。
- 小地图按业务允许的频率重绘，场景切换和缩放后做一次原子刷新。
- 粒子系统必须设硬上限、对象池、离场销毁和视口相交门禁；天气强度优先改变发射率，
  不无限累积存活粒子。
- 高频连续伤害数字按目标和暴击通道聚合，合并间隔、单桶时长、同屏上限和视口边距集中在
  双份 `performance-config.json#floatingText`；聚合只改变显示，不得改变伤害、暴击或命中次数。
- 高频装饰特效统一经过 `EffectManager.spawnCosmetic()`，在创建 Phaser Sprite/Graphics 前执行视口门禁、
  单帧发射上限与存活上限；枪口焰、弹壳、扬尘、命中血花、撞墙烟雾和死亡血雾的预算集中在
  双份 `performance-config.json#effectBudget.cosmetic`。`profiles` 按当前实际渲染场景选择：`scene7` 地牢档放宽，
  `scene8~scene11` 位面档收紧，主神空间等走默认档；观察其他位面时以当前 `SceneManager.currentScene` 为准，
  不能因为后台仍保留地牢进度而误用地牢档。投射物、攻击预警、范围判定与信息文字不得接入该可丢弃预算。
- 装饰特效视口门禁必须兼容瞄准偏移、无人机操控和观察/RTS/建造自由镜头：分别检查 Phaser 当前
  `worldView`、逻辑 `Camera.x/y` 视口与按镜头速度前探的预测视口。预测距离由
  `effectBudget.cameraSweep.lookAheadMs` 和各档 `maxCameraLeadPx` 共同约束；三个矩形必须分别判断，禁止把
  瞬移前后的视口合成巨大包围盒。该扩展仅决定可丢弃装饰特效是否创建，不得驱动镜头、战斗或实体模拟。
- 特效预算必须向 `PerformanceMonitor` 暴露当前档位、有效阈值、存活量、上帧生成量，以及按
  `offscreen/frameCap/activeCap` 分类的累计丢弃量；镜头移动场景还要记录 `cameraMode`、镜头速度、预测距离，
  以及按 `follow/aim/drone/observer/rts/building` 分类的生成与丢弃量。只有拿到同场景报告后才继续调整倍率。
- 已登记池类型的创建入口必须实际走 `_acquire + reset`，不能一边保留池工厂一边继续 `new`；回池对象可隐藏并
  复用 Graphics，但池满淘汰和 `clearPools()` 必须显式销毁池内视觉对象，不能只清空引用数组。
- Phaser 4 `enableFilters().filters` 是每 GameObject 独立 render-to-texture + shader pass。
  大量实体禁止逐对象滤镜；稳定效果优先离屏烘焙为共享纹理，动态效果优先合并到少量共享层。
- UI 预览图使用缩略图、异步解码和惰性加载；关闭面板应释放不再需要的临时画布和预览对象。

### 14.7.1 运行时贴图驻留与切场加载（2026-08-27）

- `BootScene` 只预载玩家、队友、UI、通用小型特效和地图核心资源。World-122 量产友军不再全量
  预载；大于 `resourceResidency.deferredEnemyTextureMinMiB` 的敌人精灵表必须在 Boot Loader 排队前
  拦截并登记，禁止先上传显存再卸载。
- 友军贴图按“当前场上存量 + 当前建筑真正会继续生产的已研发兵种 + 存档恢复队列”驻留。
  未研发兵种不得预取；科技换代或切换编制后的旧兵种只有场上仍有存量时保留，最后一个存量离场且
  不再生产后才进入热缓存并卸载，不能为了节省显存删除旧兵实体或打断死亡动画。
- 建筑主体、复合前后景、接地层和建筑动画也走同一驻留器；仅供 DOM 面板使用的完整预览图不得再
  上传 Phaser/WebGL，由浏览器在面板打开时按需读取。科技尚未解锁、当前位面无实例且未被
  建造预览选中的建筑不得在 Boot 预载；选中建造卡时允许异步加载并临时 pin，取消预览后再进入
  热缓存。传送门、位面祭坛及被地牢障碍复用的通用贴图属于核心资源，不参与动态卸载。
- 建筑升级必须区分两类生命周期：全局编制科技属于不可逆视觉换代，全部实例切换后旧主体可回收；
  房屋、仓库、研究所属于逐实例升级，多个等级可长期共存，驻留集合必须取当前所有实例等级的并集。
  升级读条存在时还要提前保留 `targetLevel` 贴图，完成换图后才允许旧等级按“无任何实例引用”回收。
- 敌人按资源族加载；防御波次应在休整期预取下一波。并行下载上限由
  `resourceResidency.maxParallelDownloads` 控制，默认 3，避免同时解码和上传大量 4K 精灵表。
- 当前场景资源强驻留；上一场景资源进入默认 30 秒热缓存。超过
  `resourceResidency.softGpuBudgetMiB` 或热缓存到期后，按最近使用时间释放非当前资源；WebGL 上下文
  丢失回调内只标记独立的 `contextLost` 与安全模式，所有直接提交、预算释放和定时回收入口都必须在
  `contextLost` 期间硬阻断；等恢复回调完成旧滤镜断引用后，才允许安全模式释放旧对象。
- 加载进度按预计 RGBA 解码字节加权，真实 `filecomplete` 推进；纯缓存命中可把最短遮罩缩至约
  350ms，冷加载仍保留完整过渡。必需资源失败必须触发现有切场回滚；可选预取失败写入默认 5 秒
  负缓存，避免逐帧重试。
- 负缓存必须区分“单文件 404”和“传输层整体不可用”。XHR `status=0`、浏览器离线或同批传输失败
  应打开全局指数退避熔断，熔断期间所有按帧补载入口直接返回，不得反复创建 Promise；同时暂停普通
  热缓存卸载，避免旧纹理刚释放就因资源服务器不可用而无法恢复。WebGL 安全模式仍可越过该保护，
  优先释放非当前资源以控制显存风险；网络恢复或退避到期后再恢复加载与定时回收。
- 可运行所必需的装备、技能、玩家/武器动画配置必须保留 `data/` 打包内副本作为离线真源，运行时
  `public/data/` 只做递归覆盖。请求失败、字段缺失或局部空值不得把打包内 `sword.hitBox` 等必需子树
  覆盖为空；消费端也不得依赖“catch 后继续运行但配置对象为空”的隐式状态。
- `PerformanceMonitor` 至少暴露驻留友军数、当前友军数、驻留/延迟敌人贴图数、当前敌人资源族、
  驻留/当前/预览/延迟建筑贴图数、预计 GPU MiB、安全模式、网络退避剩余时间和并行下载数。
  资源驻留只管理视觉对象，不得改变模拟、人口、生产、科技、存档或后台结算。

### 14.7.2 DOM 项目图标轻量驻留（2026-08-28）

- 建筑升级卡、升级悬浮窗和武器改造配件属于 DOM UI，不得注册成 Phaser/WebGL 纹理。正式配置继续
  保存原始美术路径，运行时统一由 `src/ui/dom-project-image.js` 映射到
  `assets/ui/runtime-icons/<原 assets 相对路径>` 的 128×128 透明等比副本；副本缺失时只允许单次回退
  原图，不能形成逐帧或重复 404 请求。
- 项目图片统一使用惰性加载、异步解码和低请求优先级。武器改造只保留当前武器已安装项目与当前打开
  槽位的候选图；槽位弹窗、悬浮窗或整个面板关闭时移除对应 `<img>` 节点，使解码表面具备回收条件。
  浏览器 HTTP 缓存仍由浏览器管理，移除节点不能被表述为已强制清空全部浏览器图片缓存。
- 运行时副本由 `tools/build-runtime-project-icons.ps1` 从 `craft-config.json`、`building-upgrades.json` 和
  `src/`中直连的`assets/ui/building-upgrades/`逐实例扩建卡自动发现，使用透明画布 `contain` 缩放，
  不覆盖原始美术。新增、改名或删除项目图标后必须以`-Prune`重跑生成器，并核对每个配置引用都有对应
  副本；清理仅限`assets/ui/runtime-icons/`派生目录，不能删除原始美术。
- 静态容量只能按 `width × height × 4` 报告 RGBA 理论上限；实际浏览器解码驻留、回收时机和峰值必须
  通过运行时采样确认，未经实测不得把理论降幅表述为真实常驻内存降幅。

## 14.8 优化顺序

1. 固定复现场景并导出基线报告。
2. 用单变量 A/B 锁定系统，例如阴影、天气、UI 或单位模拟。
3. 补齐该系统的阶段耗时和工作量计数器。
4. 先删除无效工作：视口外、重复同步、重复几何、重复查询、重复 DOM 写入。
5. 再减少单次工作量：简化几何、批处理、缓存、空间索引和预算队列。
6. 最后才考虑渲染器重写、多线程或架构迁移。
7. 用同条件报告复测平均、P95/P99、峰值和视觉/玩法正确性。
