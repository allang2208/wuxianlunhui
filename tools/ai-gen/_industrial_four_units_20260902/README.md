# 近代四单位 MiniMax H3 正式开发包

本包只负责以下四个单位：

- `service_rifleman`：制式步枪兵（SVT-40风格）
- `emplaced_machine_gun_crew`：单人BAR自动步枪兵；旧键只作存档/配置兼容
- `industrial_carbine_cavalry`：近代骑枪兵
- `gunpowder_explosive_lancer`：传统长矛重骑兵；旧键不代表爆炸或动力功能

近代炮兵本轮延期。反坦克枪兵、近代侦察射手、钢盾突击兵和战壕突击兵已有正式动作素材，不在本批重制。

## 固定流程

1. `prepare-video-references.py`：把获准母图/动作关键帧等比放入1024×576纯白画布。
2. `run-h3-batch.py`：通过统一`ai-asset.py`入口生成17个正式动作的MiniMax H3视频；idle/run只用loop，attack/charge用recover，death用one-way。重骑冲锋v01被完整动作审查淘汰后，v02用同一获准待机图作为精确首尾帧重抽，因此历史生成记录为18段、当前重建链保留17段获准源视频。被判退二进制已按`cleanup-20260902.json`清理，提示词、供应方JSON/任务ID、逐帧统计和判退原因仍保留。
3. `build-source-reviews.py`：每段视频输出32帧联系表；逐段确认身体、步态、根点、武器、方向和动作事件。
4. 在`formal-selection.json`登记人工确认后的源帧，把状态改为`reviewed_after_h3_contacts`。
5. `build-formal-assets.py`：BiRefNet抠图、每动作固定尺度/锚点、一次2×RIFE、自动最小空格布局、运行时钟GIF、联系表和解码预算报告。
6. 按`formal-build-report.json`把逐动作格子、帧数、帧率、脚线和事件帧同步进`data/`与`public/data/`配置。

## 生成合同

- MiniMax H3：5.17秒、1024×576、20步、每动作1候选、visual-only、character-asset。
- 方向：原生朝屏幕右；枪口/长矛、头胸胯、膝与脚尖、移动轴必须一致。
- 循环：只有idle与running可做末帧回首帧RIFE；attack、charge和death均为一次性。
- 正式表：每动作只允许一次2×RIFE；death保留垂直运动；每动作固定单一缩放和锚点，不逐帧拟合/重居中。列数按真实解码像素自动选择，最长边不超过4096px，尾格空置不超过12.5%。
- 预算：crowd目标每单位32MiB，准入上限64MiB；超过上限脚本直接失败。
- 重骑兵五动作因长矛横向画幅较宽，正式采样主体高采用168px并由运行时显示尺寸补偿到179.765px世界主体高；不改变碰撞、脚线或游戏内体型。
- 交付：保留母图、动作关键帧、源MP4、源/最终联系表、正式PNG图集及与运行时帧率一致的可直接查看GIF。

本包的离线图像核对不等于游戏实机验收；测试、构建、浏览器探针和EXE发布不在本任务授权范围。
