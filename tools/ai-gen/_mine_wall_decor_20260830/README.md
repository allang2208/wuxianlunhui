# 矿洞墙面挂饰：挂绳、矿镐、旧工区木牌

2026-08-30按用户“墙上再添加小物，让场景不单调、有点随机”实施。三类、两个墙向共六张透明PNG已接入，正式路径见`manifest.json.assets`，安装记录见`installation.json`。不覆盖原墙门、火把或地板小物，不修改场地生成规则。

## 美术来源

- 矿镐复用`build-mine-props-model-review.py:pickaxe`完整模型，刚性转为竖挂姿态并增加双铁钩。
- 挂绳重新构造成连续垂直绳圈，加背板/挂钩；不复用平放绳圈PNG的错误视角。
- 新建有破边、背条、钉头的旧工区木牌，仅三道浅刻痕，没有指向箭头、可读任务提示或发光标记。
- 三者均用`environment-prop-materials.py`的`environment-prop-pbr-v1`木/铁/锈/绳材质，Blender原生渲染，没有额外AI生图。
- 固定正交30°相机、6.4视宽、底部0.875；模型根分别旋转−44.8°/+44.8°，两面独立渲染、光源不动，禁止在游戏中镜像图片。512²画布不裁切；挂点取模型局部`(0,0,0.95)`的相机投影，实际世界比例48px/模型单位。
- `mine_wall_decor.blend`为可编辑源；原PNG、模型参数与来源保留。无地面平面、方向投影、碰撞或交互。

## 运行时规则

`data/abandoned-mine-wall-decor.json`及public镜像提供资源、权重与疏密参数；`abandonedMine.wallDecorations`仅启用矿洞。

1. 共用当前火把系统的最终墙段候选、房间/通道内外判定及门端、转角、木撑排除。原火把先完成，位置/数量不变，新挂饰再找剩余空位。
2. 独立散列分别决定候选顺序、58%候选留用与加权品类（绳1、镐0.75、牌0.55）；同一场地坐标稳定，不每帧重抽、不改地牢种子或场地随机规则。实际数量还受净空限制，不把58%理解为墙面最终覆盖率。
3. 挂饰间至少240px、离火把150px，同类500px内不重复；每物理房最多3件、每通道1件、全场最多16件，允许空墙。位置只沿墙微移±8px、挂高64±6px；禁止对墙块本身扰动。
4. 宽挂饰不能沿用火把的屏幕法线偏移：矿墙核心的可见侧面位于格心外约37×19px。新挂饰采用另一条等距格网轴方向的±40,+20px浅浮出，避免被相邻墙块遮去一半；宿主墙depth+0.12排序，原墙和火把位置不改。
5. 新挂饰沿用本体可见性及退出/失败恢复/shutdown清理，无额外粒子/光源、碰撞、采集或伤害。

## 文件与重建

- `tools/ai-gen/build-mine-wall-decor.py`：Blender `--background --factory-startup --python`生产本目录模型及六张PNG；默认不覆盖正式资产。
- `tools/ai-gen/present-mine-wall-decor.py`：生成`wall-decor-presentation.png`，上部主体放大，下部按正式尺寸和墙面参数人工摆放；不是随机布局结果或游戏截图。
- `src/world/dungeon-wall-torch-system.js`：共享候选、挂饰选位、独立权重及生命周期。
- `src/world/wall-system.js`：仅增加矿洞`wallDecorations`开关。
- `src/phaser/scenes/BootScene.js`：读取新配置，预载六个方向资源。
- `assets/terrain/abandoned-mine-wall-decor/`：六张正式512²透明PNG，未加到地板散布池。
- 重建会重写制作manifest；`installation.json`记录上次明确安装，重建不自动重新安装。

初次挂墙样张复用火把偏移，宽挂饰被邻墙部分遮住；当前正式参数与样张已改为等距侧面挂点。只完成本轮素材制作与必要局部代码差异核对，未运行测试或运行时验证，按约定由用户测试。

需用户重点看：随机房中实际密度和重复感、双墙向挂点与遮挡、木牌/绳圈在游戏缩放下是否足够清楚，以及退出后的清理。短墙或火把密集处可能不放挂饰，这是净空约束的正常结果。固定EXE不会自动同步本轮改动，未发布或启动新包。
