# 世界地图山脉正式图集与可拼接河流候选

2026-09-01。当前状态：**15个山脉/山口模型已形成独立正式图集，并在共享工作区本地接入；17个河流连接件仍为候选素材**。本Git增量归档正式山脉资源与最小可重建来源，远端玩法接线因战略底座尚未发布而不在本提交内。按用户后续要求取消桥梁；本地运行规则改为直接渡河并增加移动耗时。本任务没有调用外部AI或上传素材，也没有替换既有地貌基础图集；没有运行游戏或测试。

## 内容与参照

- 15个山地模型：沙漠、雪原、森林、遗迹、矿洞各一款连峰山脊、一款雄峰山体、一款开阔山口。为拉开山地与普通地貌装饰的战略层级，连峰山脊垂直高度提高35%、雄峰提高42%、山口两侧提高28%；XY占地不变。山口在几何上分开前后山体，继续保留东西向通道。
- 17个河道连接件：3个共有边河段、A/B两类格点共6个双臂转弯、2个三向汇流、6个封口端头。不设桥梁；首批3个桥梁候选已退出模型集合、manifest有效清单、图集和预览。
- 固定55°正交相机，从南侧-Y看向北侧+Y，+Z向上、滚转0°；`orthoScale=2.6`、target=(0,0,0.22)，与原地貌一致。左上柔光(-3,-4,7)、冷色填光(4,1,5)，Cycles 48 samples、CPU 8线程。
- 参照已安装的`assets/ui/world-map/terrain-atlas.png`及其V2模型/材质对照；复用现有地貌基础几何作者脚本、`world-map-camera.py`、`environment-prop-materials.py`和原有五类地面贴图。没有套用战斗场景30°/44.8°相机。
- 原生渲染512px；候选以320px原始画幅等比缩放、按Alpha紧裁打包，保留每帧接地点及透明边距。不旋转、镜像、拉伸成品图；低饱和PBR与地貌保持同一组色材。

## 本地正式山脉接入合同

以下接入已存在于共享工作区，但其世界战略底座尚未进入远端主线；本Git增量只发布资源、来源与合同。

- `assets/ui/world-map/mountain-relief.png`是运行时图集；`data/world-map-relief.json`及`public/data/world-map-relief.json`保存15帧的紧裁区域、脚点、相机、像素密度与来源。
- 五类位面各有`ridge`、`massif`、`pass`三款。普通山地按地格q/r坐标稳定选择山脊或雄峰，同一存档反复打开地图不会换款；带山口规则的地格固定使用开阔山口。
- 高度来自原生模型顶点：`ridge=1.35`、`massif=1.42`、`pass=1.28`，不是运行时纵向拉伸。正式元数据与manifest均记录该倍率，重建时不会回退旧高度。
- 近景逐格绘制正式贴图，远景烘入大地图地貌缓存；山地通行仍完全由`strategic-terrain.js`决定，贴图不参与碰撞、寻路和存档。
- 山脉图集与基础地貌图集分别异步加载。山脉资源失败时回退原矢量山形，基础地貌、选格和指令仍可继续使用。

## 河流接口

战略地图逻辑已把河流保存为相邻六边格之间的边，而非地格中心之间的水道。此套匹配现有语义，后续接入无需重洗地图或改存档。

- 半径1的尖顶六边形，单边长1；世界平面上的边方向为30°、90°、150°。
- 边段以共有边中点为锚，向两端各延伸0.28；端点格结以六边形顶点为锚，向每条相连边延伸0.22。`0.22 + 0.56 + 0.22 = 1`，接口在同一平面相接。
- A类格点方向依次为30°、150°、270°；B类为90°、210°、330°。文件名末尾mask以这些方向的位权1/2/4编码：03、05、06为两条边，07为三条边。
- 所有端口水宽0.132、岸宽0.280；水面Z=0.018；由内到外的岸线截面见manifest.connections.crossSection。河岸内部有几何起伏，接口位置不做随机偏移，也不加封闭端面。
- 一个边只画一次；在每个顶点收集相连河边，选择对应端头/转弯/汇流件。模型的port.position为相对于该件锚点的XY；屏幕坐标使用`screenX=X*s, screenY=-Y*sin55*s`。
- 不绘制桥梁。单位跨越已有河边时使用运行时统一行军代价，不由贴图决定能否通行。

## 本地渡河移动合同

- `data/world-strategy.json`与`public/data/world-strategy.json`统一配置`terrainRules.riverCrossingMultiplier=2`：同一地形，跨河这一步耗时乘2；沿岸移动不加罚。既有地貌/山口、军团补给和单位类别倍率照常叠加。
- `src/world/strategic-terrain.js`取消必须有桥的邻格阻断，并将渡河代价交给既有`strategicStepDays/strategicStepMs`。寻路选线、行程预估、实际行军共用这条计算链，不修改全局时钟或战斗场景单位速度。
- 山脉仍不可直接通行，山口规则不变。新地图不生成桥；旧存档的`bridges`数组保留读写兼容，但不再决定通行、耗时或绘制。无需重置种子、河流、基地或存档版本。
- 已经开始的行军路段保持原定时长，从下一段起应用新倍率，避免改变当前进度。位面入侵保留原有一天预行军总时长归一化契约，跨河仍占更大的路段时间份额。
- 地格提示及地形耗时图例明确区分不跨河基准与包含渡河的路线预估。用户重点体验直接横渡、沿岸不减速、预估与实际耗时，以及含旧桥记录的存档。

## 可重建来源

- `build-terrain-features.py`：山体、山口、河岸/水面/接口几何，材质、相机、渲染及manifest；已移除桥梁建模函数。
- `world-map-relief.blend`：32个独立命名集合，默认显示forest_ridge；项目材质贴图随模型打包。选择其他集合时需手动切换其视图/渲染可见性。
- `renders/`、`sprites/`与`whitebox/`是可由脚本重建的本地工作输出，本次不进入Git。首批`bridge_*`历史候选同样不发布；`manifest.retiredCandidates`记录取消原因。
- `export-candidates.py`：等比采样、紧裁、候选图集与15帧运行时山脉图集打包，以及离线排版。脚本只写当前制作目录；正式文件由任务明确复制到`assets/`与双份`data/`，不会自动覆盖运行时。
- `manifest.json`：相机/来源/材质库版本/接口/类别，以及候选与正式山脉图集容量；候选帧图集与逐帧元数据由导出脚本按需重建，不作为本次正式资源发布。
