# 深脉之母行走循环修复

用户反馈移动没有形成循环，随后授权处理。旧版将认可视频f0…138按步长6压成48帧/4秒，虽然设置repeat=-1，开场与末段仍处于不同落脚相位。本轮重新选取该视频后半段的完整步态，不重新生成角色或视频。

- 正式源：[walking-doubao-v01.mp4](../videos/walking-doubao-v01.mp4)，原视频720×720、24fps。
- 选定窗口：**[88,134)**，即3.6667～5.5833秒，46个源帧跨度。f88和f134同一落脚阶段且运动方向一致；f134作为周期边界，不额外重复入表。
- 原生关键帧：f88…132、步长2，共23张；2×RIFE输出46个有效帧。源帧按同一比例重采样，保留自然抬脚/重心变化。没有倒放、保持前帧或逐帧拉伸。
- 播放：36fps，**1277.777778ms/轮**。旧版144源帧压入4秒等于36源帧/秒，新版保持这个既有步频，仅把循环单位从混合长片段改成一个完整周期；实际移动速度105未改。
- 布局：472×448，6列8行，endFrame=45，余下两格透明且不参与播放；footY425、主体采样320、世界显示300不变。Boot读取frameCount，实体按duration取模，无需修改共享渲染或状态机。
- 预算：本图38.71875MiB（含两个空格），整族238.29MiB未增；七套动画总有效帧299→297，其余六套正式PNG、攻击参数和碰撞均未改变。

## 重建和文件范围

`../repair-walking-loop.py prepare`从保留的认可高清抠图生成本窗口源表；`interpolate`调用共享RIFE；`previews`生成跨缝GIF/联系图；`publish`只更新walking正式图、v2源表/记录、预算帧数和双份walking配置。发布之后用`../build-runtime-sprites.py finish walking`更新单轮GIF与七动作总览，不写其他六套独立预览或正式PNG。

全族制作器也已登记相同起止窗口和步长；原f17→源f51补丁不适用于新窗口，覆盖逻辑现在消费manifest的nativeFrameOverrides（新行走为空），避免下一次重导插回旧姿态。

本轮查看源周期、完整步态和接缝联系图，导出连续三轮GIF，并核对本次局部真实差异。**未运行测试或运行时验证，按约定由用户测试；未构建、启动游戏或同步EXE。** 源视频已有的轻微材质/重心变化仍保留；请重点确认长距离连续移动、起停和左右转向时的观感。
