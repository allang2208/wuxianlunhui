## 源文件与复现

- `../build-mine-wall-pbr-kit-v2.py`：显式调用原建模辅助函数，在独立Blender进程中配置v2局部岩面和输出目录；不写回v1脚本或v1成果。
- `../compose-mine-wall-pbr-kit-v2.py`：导出Alpha、4×4门精灵表、素材参数、静态拼装与GIF；不启动游戏、不安装到正式目录。
- `../install-mine-wall-pbr-kit-v2.py`：把已选中的三张墙与门精灵表逐字节复制到`assets/terrain/`，不重渲、不重新采样；写入正式来源记录并将旧清单标记为已替代。
- `mine_wall_and_gate_pbr_v2.blend`：可编辑墙A/B/C和独立门叶集合，包含打包岩石底色、共享材质、墙/门两台原规格相机。默认显示墙A，门动画位于Blender帧1～16；开门后隐藏是运行时状态规则，没有写成删掉门模型。
- `geometry.json`：墙几何、门几何、16帧世界升起量与像素升起量。
- `manifest.json`：输出清单、来源及制作状态。`slate-albedo-prompt.txt`与底色原图沿用v1，来源路径保留在清单；不是本轮重新调用ImageGen。

仓库根目录运行Blender后台脚本，再运行带Pillow/numpy的Python拼装脚本即可重建本目录。重建仅产出新候选，不自动覆盖游戏；拼装器在`lastInstallation`保留上次正式接入记录。需再次明确接入时运行安装脚本。旧建模/拼装辅助脚本仍是显式依赖，不应在清理候选时连同删除；两个旧安装入口已禁止覆盖当前版本。

## 门与拼接合同

- 门画布640×640，4×4精灵表2560×2560，共16帧。
- `base=face=[[32.0003,299.9994],[608.0002,588.0004]]`，`gateX=[32,608]`，六格跨度和六层排序不变。
- 墙按固定`(+64,+32)` / `(-64,+32)`铺设，同格转角去重；矿洞门启用`tuckEndSlices:true`，首尾片取外端点Y+3.9，其余片取本段maxY+3.9，端墙保持+4。
- 帧0关闭，帧15升起；原世界升起量`3.55*t*t*(3-2*t)`。GIF按现有`WallGate`的900ms线性帧计数呈现开/关，每端帧30ms，中间帧60ms，另加静止观看时间。
- 反方向门的逻辑几何仍沿用`piece.flipX`映射；实际切片精灵由`bindGateSourceCrop`换成负`scaleX`、`flipX=false`，保持原图裁片列与底线/depth一一对应，避免Phaser将取图列镜像到另一端。墙本身不镜像，也没有新生成另一套相机视角。
- 原640画布在门升起过程中会裁掉上方出画部分，本轮保留此规格；`hideWhenOpen:true`在完全打开后隐藏门叶。GIF体现该最终隐藏规则，联系表则故意显示原始15帧内容，便于区分素材与状态。

## 素材亮度摘要

`material-summary.json`使用Alpha>200的主体像素，计算sRGB亮度。A/B/C中位亮度最大差0.00701，平均亮度最大差0.00565，低于知识库的0.01/0.015制作参考值。三款Alpha包围盒均为`[199,100,825,918]`。

这些数据只描述源PNG，不等于游戏照明、遮挡或显示效果已验收。
