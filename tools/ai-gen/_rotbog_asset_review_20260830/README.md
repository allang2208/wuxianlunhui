- 正式待机第0帧的腿、触须和轮廓有青紫色边线；走路也有相似残色。`original-frames-dark-light.png` 是原始帧在深浅底上的直接合成，不含锐化或清理。

- **插帧前第8个关键帧与正式冲刺第16帧逐像素相同**，因此这些杂边在RIFE之前已经存在，不能归咎于插帧工具凭空生成。奇数中间帧继续携带污染。
- 原视频 `../_rotbog_rhinoceros_beetle_king_20260828/videos/charge-doubao-v03.mp4` 实际是1280×720。其第64帧的主体外没有这些灰色块，快速腿部本身则已有视频软化/运动模糊。
- 冲刺处理记录使用近主体支持域、蓝青去色、最近不透明像素回填；`build-runtime-charge.py::decontaminate_opaque_edges` 会给Alpha在12～239之间的全部边缘回填最近不透明像素的RGB，保留原Alpha。**多余遮罩区域改成灰褐色仍然可见**，蓝色统计归零不能证明抠图干净。

## 素材统计的边界

`inspection.json` 只记录当前开发目录8个动作的布局、Alpha内容与颜色阈值计数。所有配置有效帧均有像素。

蓝色指标为 `B - max(R,G) > 18`，青色为 `min(G,B) - R > 18`，仅统计 `Alpha >= 12`。冲刺两项均为0，但目视仍有大片灰紫杂边；待机青色指标单帧最多5348像素。颜色计数只用于找候选问题，不等于这些像素全部应该删除，也不证明用户固定EXE的蓝色现场与当前目录完全一致。
