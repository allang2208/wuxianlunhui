## 时间与状态边界

| 阶段 | 普通冲刺 | 冲刺突击 |
|---|---|---|
| 进入 | 在原攻击最前120ms内，从当前实际跑姿接上原起手 | 利用已有奔跑蓄势计时的最后120ms准备；没有等待未来点击的倒计时 |
| 就绪 | 继续低持跑 | 躯干压低、主臂准备前刺、盾臂屈肘，膝脚沿当前跑步相位继续变化 |
| 点击后 | 原800ms攻击不延长，中后段沿原源帧/武器轨迹 | 原600ms零前摇突击立即开始；前80ms仅处理腿部姿态交接，主手已进入原攻击轨迹 |
| 定格 | 保留原500ms，显示原 `dash_recover` 第0帧 | 不新增定格 |
| 收势 | 原500ms时长 | 原500ms时长 |
| 退出 | 收势前80ms连续承接装备与姿态，末160ms接向选定跑步相位，锁定期不缩短 | 同左 |

演示蓄势阈值使用当前1级333ms，等级缩短公式同源记录在配置中。800ms为预览中选择点击的演示时刻，不是新增技能门槛。就绪后继续奔跑，不是到333ms就自动攻击。

两条序列各提供8种点击时的原跑步帧；回跑相位按两侧膝、踝与收势末帧的距离选择，本次两种候选均匹配到第3帧，不一律重置第0帧。这里是作者标定结果，正式接入仍需以最后实际显示姿态及当前移动输入交接，不能把预览的时间轴当输入系统。

## 像素与绑定方法

1. 普通奔跑依旧使用原8帧身体层、10FPS，沿用既有头部起伏、腿脚和帧内位置。
2. 短过渡中的躯干/腿部使用源像素网格变形，把头、颈、胸、腰、髋、双膝、双踝及脚端映射到中间姿态。准备姿态会压低髋部，这些过渡帧并非原跑腿像素完全不变。
3. 手臂不进入躯干网格，避免前伸手把头和胸拉坏。过渡双臂由独立上臂、前臂绕关节旋转，保留切片骨长；不可达目标钳制到实际可达掌点，装备使用同一个结果，不靠拉长手臂追剑盾。
4. 两张来源不同的身体底图在中间匹配姿态处切换像素来源，不做全身透明叠化。匹配的是2D关节点与轮廓，不能消除所有纹理/透视差异。
5. 普通攻击中后段仍读取原 `dash_attack` 和 `sword.dash`/`dashHand`；突击主手仍读取 `dash_attack_thrust` 和 `dashThrust`。原PNG和轨迹JSON均未写入。
6. 突击原图的双臂靠拢区域经身体/主臂遮罩分离，副臂改为独立屈肘持盾；仍有遮挡推定，不能称作完整真实骨骼提取。
7. 收势掌点按原图人工标定，候选在同样500ms内转向低持目标；这是新的收势表现，不声称逐像素复现当前运行时回idle的贝塞尔剑轨。正式接入应在同一套掌点协议中处理“回跑/回待机”。
8. 装备与身体始终使用同一采样记录、同一翻转；不让剑盾另开时间轴。剑的攻击原点沿当前运行时代码口径，低持原点读取每张纹理的独立握点，短过渡同时交接原点与尺寸。

另修正上一版离线奔跑剑尺寸：源码 `MELEE_SCALE` 为0.75，旧预览误读注释使用0.625。本轮改为直接读取源码常量，重新输出奔跑候选。只修正候选合成尺寸，没有修改正式装备数值。
